Git：从小白到资深

Git 是分布式版本控制系统——记录每次改动快照、随时回退、多人并行协作。本教程讲透数据模型（快照/三区）、分支与 rebase、远程协作、历史改写安全边界、工作流与 hooks——程序员与 AI 协作都绕不开的基石。

1. 它解决什么问题

网盘只存最新版、改错难回退、多人改同一文件必冲突。Git 存全部历史，支持并行分支与可控合并，是“代码时光机 + 协作总线”。

分布式：每人本地有完整仓库，离线可提交；远端（GitHub）只是其中一个副本，便于备份与协作。

2. 数据模型

  • 快照而非差异：每次 commit 记录项目完整状态（未变文件只存指向上版的指针）。
  • 对象：blob（文件内容）、tree（目录）、commit（指向 tree + 父提交 + 信息）、tag。
  • HEAD：指向当前所在分支的最新提交。

3. 三区与基础

工作区(你编辑) → git add → 暂存区(index) → git commit → 版本库
git config --global user.name "你的名字"
git config --global user.email "you@example.com"
git init
git add -A                # 或精准 add 指定文件
git commit -m "feat: 新增登录接口"   # 用 Conventional Commits 规范
提交信息：<type>: <简述>（feat/fix/style/refactor/perf/docs/chore），正文写清“改了什么、为什么、如何验证”。一次提交只做一件事，便于回档。

4. 分支模型

git branch feature && git switch feature     # 建并切
git merge feature                            # 合并回主线（产生合并提交）
git rebase main                              # 把当前分支挪到 main 顶端（线性历史）
  • merge：保留分叉历史，安全但图复杂。
  • rebase：历史线性整洁，但改写了提交（勿对公共分支 rebase）。
  • 冲突：两边改同处需手动解决，再 add+commit。

5. 远程协作

git remote add origin https://github.com/你/仓库.git
git push -u origin main      # -u 绑上游，之后 git push/pull 即可
git fetch                    # 取远端但不合并
git pull                     # fetch + merge（或 rebase）
推送被拒：远端有别人新提交 → 先 pull（建议 pull --rebase）再推。

6. 历史改写（安全边界）

  • git reset --soft/--mixed/--hard：回退提交（hard 会丢工作区改动，慎用）。
  • git revert <commit>：生成“反向提交”撤销，**不改历史**，生产首选。
  • git checkout <commit> -- 路径：只回档某文件到某版本。
  • 红线：已推送到远端的公共历史，禁止 push --force 覆盖；除非用户明确要求且确认影响。

7. 暂存/标签/hooks

  • git stash：临时收起未完成改动去处理别的事，stash pop 恢复。
  • git tag v1.0：里程碑标记；部署上线可打 deploy-20260911 之类 tag 作回档锚点。
  • hooks：.git/hooks/pre-commit 等可在提交前跑 lint/测试，CI 的前置防线。

8. 工作流

  • GitHub Flow：main 常可部署，开 feature 分支 PR 合并，简单。
  • Git Flow：dev/release/hotfix 多分支，适合有版本发布节奏。
  • Trunk-based：短命分支、频繁合主干，配 CI/CD，现代主流。

9. 常见坑

坑 1：没 git add 就 commit，改动没进版本。
坑 2：把密钥/.env 提交进仓库泄露 → .gitignore 排除，泄露即轮换。
坑 3：强推覆盖他人历史 → 非必要禁用。
坑 4：对公共分支 rebase 导致他人历史错乱。
坑 5：大文件进仓库导致克隆膨胀 → 用 Git LFS 或忽略。

10. 成长路线

阶段能力标志
小白会 init/add/commit/推远程
初级分支、merge/rebase、解决冲突
中级stash/tag/hooks、工作流选型
资深revert 安全回滚、CI 集成、仓库治理
练习：① 用 Conventional Commits 提交 ② 开分支开发再 rebase 合回 ③ 解决一次冲突 ④ 用 revert 撤销某提交 ⑤ 打 deploy tag ⑥ 写 pre-commit 跑 lint。
你已进阶：理解 Git 的快照模型与分支哲学，能安全协作、可控回滚、用工作流与 hooks 提升团队质量——这是资深后端工程素养的底座。
