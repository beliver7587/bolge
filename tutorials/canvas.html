Canvas 2D：从小白到资深前端

Canvas 2D 是浏览器原生的像素级绘图 API，用来画图表、做小游戏、处理图像。本教程讲透坐标系与变换栈、清屏重绘的动画循环、坐标命中、高清屏适配与性能——这是资深做轻量图形/可视化的基本功。

1. 它解决什么问题

DOM 适合“结构化 UI”，但画几千个点/做逐帧动画就吃力；SVG 是矢量但节点多也慢。Canvas 给你一块位图画布，用 JS 直接画像素，轻量、可控、无 DOM 开销。

一句话：Canvas 是“命令式逐帧绘制”的画布，适合图表、小游戏、图像滤镜；复杂 UI 仍交给 DOM。
对比：少量动态图形 → Canvas 2D；海量精灵/游戏 → PixiJS（WebGL 批渲染）。

2. 工程化起步

const canvas = document.querySelector('canvas');
const ctx = canvas.getContext('2d');
// 高清屏适配：用 DPR 放大画布、CSS 缩回
const dpr = window.devicePixelRatio || 1;
canvas.width = 800 * dpr;  canvas.height = 600 * dpr;
canvas.style.width = '800px'; canvas.style.height = '600px';
ctx.scale(dpr, dpr);
坑：不处理 DPR，高分屏上画布发虚。上面是标准解法。

3. 绘图基础

ctx.fillStyle = '#6366f1';
ctx.fillRect(10, 10, 100, 50);          // 填充矩形
ctx.strokeStyle = '#fff'; ctx.strokeRect(10, 10, 100, 50);
ctx.beginPath(); ctx.arc(200, 100, 30, 0, Math.PI * 2); ctx.fill();  // 圆
  • fillStyle/strokeStyle 是“状态”，会影响后续绘制，用 save/restore 隔离。
  • 状态栈：ctx.save() 压入当前状态，ctx.restore() 弹出——避免样式串台。

4. 变换与坐标系

ctx.save();
ctx.translate(400, 300);   // 把原点移到中心
ctx.rotate(Math.PI / 4);   // 旋转坐标系
ctx.fillRect(-25, -25, 50, 50);
ctx.restore();             // 还原，不影响后续
心智：变换作用于“之后的绘制”，且可叠加。配平 save/restore 是基本功——不还原会越套越乱。

5. 文本与图像

ctx.font = '20px sans-serif'; ctx.fillText('你好', 50, 50);
const img = new Image();
img.onload = () => ctx.drawImage(img, 0, 0);
img.src = '/pic.png';   // 注意跨域：跨域图需 crossOrigin 否则污染画布

6. 动画循环

function frame() {
  ctx.clearRect(0, 0, 800, 600);   // 清屏（关键！否则拖影）
  // ...重绘当前帧
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
坑：不清屏 → 上一帧残留成“拖影”；用 clearRect 或重绘背景每帧覆盖。

7. 交互与命中

  • 监听 canvas 的 mousemove/click，用 getBoundingClientRect 把屏幕坐标换算成画布坐标。
  • 命中检测：简单图形用几何判断（点到圆/矩形）；复杂用 ctx.isPointInPath(path, x, y)。

8. 性能优化

  • 离屏 Canvas：把静态背景画一次存到离屏 canvas，每帧直接 drawImage 贴上去。
  • 分层 Canvas：静态层（背景）与动态层（动画）分开，静态层不重绘。
  • 减少 save/restore 与状态切换；批量同色绘制。

9. 与 Pixi 边界

选型：图表、签名板、小游戏、图像裁剪 → Canvas 2D 足够轻；上千动态对象/粒子 → 上 PixiJS 走 WebGL。

10. 图像处理

const data = ctx.getImageData(0, 0, w, h);  // 拿到像素数组
// data.data 是 RGBA，可逐像素做灰度/滤镜
ctx.putImageData(data, 0, 0);
坑：跨域图片未设 crossOrigin，画布会被“污染”，getImageData 抛安全错误。

11. 常见坑

坑 1：高分屏不处理 DPR → 模糊。
坑 2：save/restore 不配平，变换/样式串到后续绘制。
坑 3：动画不清屏，出现拖影。
坑 4：动画循环在组件卸载后没停 → 内存/CPU 泄漏（React 里要在 cleanup 取消 rAF）。
坑 5：跨域图污染画布，取像素报错。

12. 调试

  • 在循环里 console.log 帧率；DevTools Performance 看每帧耗时。
  • 临时 ctx.strokeRect 画命中框验证坐标。

阶段能力标志

你已进阶：理解命令式绘制的“清屏-重绘”循环、坐标系与性能分层——这是资深图形前端的底色。
