Nginx 反向代理

网站的“前台” —— 统一收口、HTTPS 终止、WebSocket 透传，三个项目都用它。

1. 这是什么

Nginx 是高性能的 Web 服务器，最常用来做反向代理：所有用户只访问 443 端口，Nginx 这个“前台”按 URL 路径把请求分给内部不同服务。三个项目都靠它统一对外。

2. 正向 vs 反向

正向代理反向代理（本项目用）
立场帮“客户端”上网（梯子）帮“服务器”收口（前台）
谁配置客户端服务端

3. 子路径反代

# 把 /td/ 转发给内部 8095 端口的游戏服务
location /td/ {
  proxy_pass http://127.0.0.1:8095/;   # 末尾斜杠：去掉 /td 前缀再转发
  proxy_set_header Host $host;
}
关键：proxy_pass 末尾的斜杠表示“剥掉前缀”，漏写会让后端收到带前缀的路径而 404。

4. WebSocket 透传

location /socket.io/ {
  proxy_pass http://127.0.0.1:3000;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;     # ★ 必须
  proxy_set_header Connection $connection_upgrade;
  proxy_read_timeout 86400s;                  # 长连接别被掐
  proxy_buffering off;                        # 实时消息不缓冲
}
两个真实坑：漏掉 Upgrade 头 → 握手失败；proxy_read_timeout 用默认 60s → 玩家挂机就掉线。

5. 常见坑

坑 1：改完配置不校验：先 nginx -t 再 systemctl reload nginx，否则配错全站瘫。
坑 2：SSE 流式要 proxy_buffering off（见 SSE）。
坑 3：后端端口直接暴露公网——只绑 127.0.0.1，外网只走 Nginx。
