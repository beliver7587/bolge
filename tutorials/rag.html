RAG：从小白到检索增强生成

RAG（检索增强生成）先检索资料再让 大模型 基于资料作答，解决“模型不懂私有知识、会胡编”的问题。Memora 客服就是 RAG 落地。本教程讲清流程、混合检索与分块策略。

1. 它是什么

RAG = 检索（Retrieval）+ 增强（把资料塞进上下文）+ 生成（Generation）。模型不再只靠训练记忆，而是“现查现答”。

一句话：RAG = 让 LLM 先查资料再回答。专治“知识过时”和“ hallucination（幻觉）”。

2. 为什么需要

  • LLM 训练数据有截止日期，不懂你公司的私域文档。
  • 直接问易“幻觉”编答案；给它真实资料它能基于资料答。
  • 资料可溯源、可更新，不必重训模型。

3. 完整流程

入库：文档 → 切片 → Embedding → 向量库
提问：问题 → Embedding → 检索 TopK → 拼进 Prompt → LLM 作答

检索到的片段作为上下文，约束模型“基于这些回答”，并可在答案里附引用。

4. 检索方式

  • 向量检索（语义）：用 Embedding 找语义相近，能匹配同义。
  • BM25（关键词）：精确词面匹配，适合专有名词。
  • 混合：两者互补，再用 RRF 融合，效果好于单路。

5. 融合 RRF

不同检索返回不同排序，用倒数排名融合（见 RRF）合成一个 TopK，避免单路漏召。

6. 分块策略

  • 按语义断句，块大小适中（如 300–800 字），带重叠窗口保上下文。
  • 元数据（来源、标题）一并存，便于过滤与引用。
坑：块太大噪声多、超出上下文；块太小丢语境。需要调。

7. 与 LLM

RAG 是“外挂知识”，LLM 是“大脑”。检索质量决定上限，生成质量决定下限——检索烂，模型再强也答不对。

8. 常见坑

坑 1 检索质量差：RAG 上限由检索决定，先调 embedding/分块/融合。
坑 2 上下文溢出：塞太多块超出模型窗口；按相关度截断 + 摘要。
坑 3 不加护栏：用户可能诱导模型忽略资料；需 防注入 与约束。

9. 资源与路线

  1. 学 Embedding、BM25、LLM 后再做 RAG。
  2. 框架：LangChain、LlamaIndex、Dify。
  3. 练：用向量库 + LLM 搭一个“基于你笔记的问答”。
资深标志：把 RAG 当成“检索系统 + 生成系统”两块独立优化，清楚“检索上限论”，并用混合检索 + 融合压高召回。
