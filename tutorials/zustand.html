Zustand：从小白到轻量状态管理

Zustand 是极简的 React 状态管理库：一个 create 就建好全局 Store，组件用 hook 订阅。没有 Redux 的样板代码，也没有 Context 的“一改全渲染”。本教程讲清它为什么轻、怎么精准订阅、以及常见陷阱。

1. 它解决什么问题

Redux 要写 action/reducer/store 一大套样板；Context 虽简单，但任一值变化会让所有消费者重渲染。Zustand 取两者之长：像 Context 一样随手用，又像 Redux 一样可精准订阅。

一句话：Zustand = 一个全局可变 store + 选择器订阅。改哪取哪，互不牵扯。

2. 工程化起步

npm i zustand

无额外配置，直接 create。支持 React 18 + 并发特性。

3. 基本用法

import { create } from 'zustand';
const useStore = create((set) => ({
  count: 0,
  inc: () => set((s) => ({ count: s.count + 1 })),
}));
// 组件里
const count = useStore((s) => s.count);
const inc = useStore((s) => s.inc);
<button onClick={inc}>{count}</button>
关键点：store 是“外部可变对象”，组件通过 hook 取切片；更新用 set，且应产生新对象（不可变）。

4. 选择器订阅

只订阅需要的字段，其他字段变也不渲染该组件：

const name = useStore((s) => s.user.name);  // 只关心 name
坑：选择器返回新对象/数组（如 (s)=> ({a:s.a,b:s.b})）每次都是新引用，会无限重渲染。用 useShallow 或分别取字段。

5. 异步 Action

const useStore = create((set) => ({
  data: null, loading: false,
  load: async () => {
    set({ loading: true });
    const d = await fetch('/api').then(r => r.json());
    set({ data: d, loading: false });
  },
}));

action 里直接 set，无需额外 thunk 概念——比 Redux 清爽。

6. 持久化

import { persist } from 'zustand/middleware';
const useStore = create(persist((set) => ({ token: '', setToken: (t)=>set({token:t}) }),
  { name: 'auth' }));  // 自动存 localStorage
适合：登录态、主题、购物车等“刷新也不丢”的状态。

7. 中间件

  • devtools：接入 Redux DevTools 时间旅行调试。
  • immer：用“可变写法”改嵌套状态（底层仍是不可变）。
  • subscribeWithSelector：脱离组件监听变化。

8. 与 Redux

ZustandRedux Toolkit
样板极少中等（createSlice）
重渲染按选择器精准需 reselect
适用中小全局状态强规范、可回溯团队

9. 与 Context

Context 适合“低频、整块”的配置（主题、locale）；Zustand 适合“高频、按需”的状态。关键区别：Context 一变全渲染，Zustand 只渲染订阅者。

10. 常见坑

坑 1 选择器返回新引用：见第 4 节，用 useShallow。
坑 2 直接改 state：s.count++ 不触发更新，必须 set 新对象（或用 immer）。
坑 3 在组件外读值：用 useStore.getState() 而非 hook，否则拿不到响应式。

11. 最佳实践

  • 按域拆多个小 store，别塞一个巨型 store。
  • 服务端数据交给 React Query/fetch，别存进 Zustand。
  • 用选择器只取必要字段，提升性能。

12. 项目实战

  • 简历工坊：用 Zustand 管“当前编辑的简历草稿、主题切换”。
  • 网页游戏：管“房间连接状态、本地玩家信息”。
  • Memora：管“对话会话列表、当前选中的会话”。
