Bun + Elysia：从小白到极速运行时

Bun 是用 Zig 写的 JS/TS 运行时，比 Node 启动更快、API 更全（自带打包/测试/转译）。Elysia 是其上的轻量后端框架。本教程讲清它为什么快、能替代 Node 哪些部分、以及局限。

1. 它是什么

Bun 不只是运行时，还内置了包管理、打包器、测试运行器、转译器——一个工具顶 Node + npm + esbuild + jest 的组合。

一句话：Bun = 更快的 JS/TS 运行时 + 全家桶工具链。开箱即跑 TS，不用额外编译。

2. 工程化起步

curl -fsSL https://bun.sh/install | bash
bun create elysia myapp
bun run dev          // 直接跑 TS，无需编译

3. 为什么快

  • 用 Zig + 自研 JS 引擎（JavaScriptCore 衍生），启动与冷运行快。
  • 内置基于字节的 HTTP 服务器，吞吐高于 Node 的 http。
  • 热重载、转译在原生层完成，省去 JS 侧开销。
资深视角：快在“少一层抽象”——Node 用 V8 + C++ http + JS 生态；Bun 把更多收进原生层。

4. 内置 API

Bun.serve({
  port: 3000,
  fetch(req) { return new Response('hi'); },  // 兼容 Web 标准 fetch/Response
});
  • Bun.serve：高性能 HTTP。
  • Bun.file、Bun.write：文件操作。
  • bun test、bun build：测试与打包开箱即用。

5. 与 Node 兼容

大部分 Node API（fs、process、Buffer）与 npm 包可用。但生态仍在追赶，少数原生插件/老包可能不兼容。

坑：生产前先验证关键依赖在 Bun 下是否正常，别盲目替换。

6. Elysia 框架

import { Elysia } from 'elysia';
new Elysia()
  .get('/user/:id', ({ params }) => ({ id: params.id }))
  .listen(3000);
  • 端到端类型安全：从路由到响应类型自动推导。
  • 插件式（cors、swagger、trpc），轻量无负担。

7. 打包与测试

bun build ./src/index.ts --outdir dist   # 自带打包
bun test                                 # 自带测试

不必再装 esbuild/jest，工具链更短。

8. 部署

  • 单二进制友好，适合 Docker 多阶段构建。
  • 前接 Nginx 反代，用 PM2 类工具守护（或系统进程管理）。

9. 常见坑

坑 1 生态成熟度：某些 Node 原生模块不支持，先验证。
坑 2 版本差异：Bun 迭代快，生产锁版本，避免破坏性更新。
坑 3 调试工具：部分 Node 调试生态未完全对等。

10. 资源与路线

  1. 官方 bun.sh、elysiajs.com。
  2. 已有 Node/Express 基础再迁移更稳。
  3. 练：用 Elysia 写一个带类型推导的 REST 服务。
资深标志：能为团队评估“Bun 带来的提速”是否值得“生态风险”，并在合适项目（新服务、内部工具）果断采用。
