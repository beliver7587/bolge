Next.js

基于 React 的“全栈”框架 —— 简历工坊前端用它做服务端渲染与文件路由。

1. 这是什么

Next.js 是 Vercel 出品、构建在 React 之上的全栈框架。普通 React 只是“前端库”，而 Next.js 额外给了你：文件路由、服务端渲染(SSR)、API 路由（能写后端）、打包优化。一句话：React 负责“画”，Next.js 负责“怎么组织、怎么上线”。

2. 为什么用它

能力好处
SSR / SSG页面先在服务器渲染好 HTML，首屏快、对 SEO 友好（简历被搜索引擎收录）
文件路由app/about/page.tsx 自动变成 /about，不用手写路由表
API 路由在 app/api/... 写接口，前后端一个项目搞定
内置优化图片、字体、代码分割开箱即用

3. App Router 路由

Next.js 14 推荐用 app/ 目录组织页面，路径即路由：

app/
├── layout.tsx        # 所有页面的公共外壳（导航/页脚）
├── page.tsx          # 对应网站根路径 /
├── resume/
│   └── page.tsx      # 对应 /resume
└── api/
    └── user/route.ts # 对应接口 /api/user

4. 服务端组件 vs 客户端组件

关键：默认组件是“服务端组件”，能直接读数据库、不发到浏览器；需要点击事件/状态时要加 'use client' 变成“客户端组件”。
// 服务端组件：直接在服务器取数据
export default async function Page() {
  const data = await db.query('SELECT * FROM resume');
  return <List items={data} />;
}

// 客户端组件：有交互
'use client';
function Btn(){ const [n,setN]=useState(0); return <button onClick={()=>setN(n+1)}>{n}</button>; }

5. 第一个页面

npm create next-app@latest my-site   # 选 TypeScript + App Router
cd my-site && npm run dev            # 打开 http://localhost:3000

改 app/page.tsx 里的内容，刷新浏览器即可看到变化。

6. 常见坑

坑 1：在“服务端组件”里用了 onClick 等浏览器事件会报错——记得加 'use client'。
坑 2：环境变量：NEXT_PUBLIC_ 前缀的才暴露给浏览器，其余只服务器可见。
坑 3：改了 next.config 要重启 dev 服务才生效。
