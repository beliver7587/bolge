RRF：从小白到结果融合

RRF（倒数排名融合）把多路召回（如 BM25 + 向量）的结果按排名合成一个列表。它是 RAG 混合检索的最后一步。本教程讲清它为什么比加权平均更稳。

1. 它是什么

多路检索各返回一排好结果（带排名），RRF 只看“排名”不看“分数”，把各路排名倒数相加再排序。

一句话：RRF = 把多路召回按排名融合成一个 TopK。不看分，只看名次。

2. 公式

RRF(d) = Σ 1 / (k + rank_i(d))      // rank 是该路中 d 的排名，k 通常 60
// 分数高的排前面

k 是平滑常数，避免第一名权重过高。

3. 为什么用

  • 不同检索的分数量纲不同（BM25 几分 vs 余弦 0–1），直接加权难调权重。
  • RRF 只用排名，天然消除量纲差异，无需调权重。
  • 某路漏召的文档，被另一路补上，召回更稳。
实战：BM25 + 向量两路各取 Top50，RRF 合成 Top10 喂给 LLM。

4. 与加权对比

RRF加权求和
依赖只看排名，无权重要调各路权重
鲁棒高（量纲无关）低（量纲敏感）

5. 常见坑

坑 1 同分未打散：并列排名要稳定处理，避免 TopK 抖动。
坑 2 只召一路：RRF 收益来自多路互补，单路无意义。
坑 3 k 设太小：第一名权重过大，融合退化。

6. 资源与路线

  1. 论文 Reciprocal Rank Fusion；RAG 框架（LangChain）内置。
  2. 配合 RAG、BM25、Embedding。
  3. 练：写一个小函数，把两路排名用 RRF 融合。
资深标志：能用 RRF 把异构召回稳健融合，理解“排名比分数更可靠”，并据此提升 RAG 召回质量。
