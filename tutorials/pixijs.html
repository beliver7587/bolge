PixiJS：从小白到资深前端

PixiJS 是基于 WebGL 的高性能 2D 渲染库，用来做游戏、粒子、数据可视化、互动动画。本教程讲透它的场景图、批渲染原理、资源/精灵管理、Ticker 循环与性能优化——这是资深做“高性能 2D 画面”的硬核能力。

1. 它解决什么问题

原生 Canvas 2D 是软件渲染，几千个图形就掉帧；DOM 更扛不住。PixiJS 用 WebGL 把大量图形批处理成少数 GPU 绘制调用，轻松渲染上万个精灵。

一句话：PixiJS 把“画 2D 图形”交给 GPU，用场景图（树）组织对象，批渲染压低开销，适合高性能互动画面。
适合：2D 游戏、粒子特效、可视化大屏、互动广告。
不适合：简单静态图（用 CSS/Canvas 即可）、3D（用 Three.js）。

2. 工程化起步

'use client';
import { Application, Sprite, Assets } from 'pixi.js';

const app = new Application();
await app.init({ width: 800, height: 600, background: '#0f1424' });
document.body.appendChild(app.canvas);

v8 用 app.init() 异步初始化；app.canvas 是真实 <canvas>。可嵌入 React 的 ref 容器。

3. 场景图与核心

  • Stage：根容器，所有对象挂在它下面。
  • Container：分组容器（可嵌套），统一管理位置/缩放/可见。
  • Sprite：基于纹理的显示对象（图）。Graphics：用代码画的矢量图形。Text：文本。
import { Container, Graphics } from 'pixi.js';
const layer = new Container();
const g = new Graphics().circle(0, 0, 50).fill('#6366f1');
layer.addChild(g);
app.stage.addChild(layer);

4. 渲染原理

关键在批渲染（batching）：WebGL 一次 draw call 能画很多个“用同一纹理/同材质的精灵”。Pixi 自动把可合并的对象合并成批量，draw call 从“每对象一次”降到“每批一次”。

资深视角：性能瓶颈常不在“对象多”，而在“批被打断”（不同纹理穿插）。把同纹理精灵连续绘制、用图集，批才不会断。

5. 资源与精灵

const texture = await Assets.load('/hero.png');
const hero = new Sprite(texture);
hero.anchor.set(0.5);          // 锚点居中，旋转/缩放绕中心
hero.position.set(400, 300);
app.stage.addChild(hero);
  • anchor：锚点（0~1），决定旋转/缩放中心。
  • 纹理图集（atlas）：把多张小图拼一张大图，减少纹理切换、提升批渲染。

6. 交互

hero.eventMode = 'static';     // 开启交互
hero.cursor = 'pointer';
hero.on('pointerdown', () => console.log('点到了'));

用 hitArea 自定义点击区域；支持拖拽（监听 pointermove + 全局坐标）。

7. Ticker 与动画

app.ticker.add((ticker) => {
  hero.rotation += 0.02 * ticker.deltaTime;   // 帧率无关推进
});
  • Ticker 是游戏主循环，每帧回调。用 deltaTime 让动画与帧率无关（高刷/低刷速度一致）。
  • 粒子、缓动可用社区库或自写。

8. 性能优化

  • 纹理图集：合并小图，连续绘制保批。
  • 对象池：子弹/粒子复用，别每帧 new + 销毁（GC 抖动）。
  • 避免每帧创建对象：在循环外建好、循环内改属性。
  • 视口裁剪：屏幕外的精灵设 cullable 让其不被送 GPU。

9. 与 Canvas2D 边界

选型：少量静态图形/图表 → 原生 Canvas2D 更轻；大量动态对象、粒子、游戏 → PixiJS。两者都不是 DOM，复杂 UI 仍用 DOM/React 叠加。

10. 常见坑

坑 1：对象不销毁 → 内存泄漏。移除时 destroy({ children: true }) 并释放纹理。
坑 2：Ticker 回调不移除 → 页面切走仍在跑，耗电；组件卸载时 ticker.remove。
坑 3：高分屏模糊 → 设 resolution: window.devicePixelRatio 并 autoDensity。
坑 4：纹理穿插打乱批渲染，draw call 暴涨。

11. 调试

  • Pixi 官方 Pixi Inspector（浏览器扩展）看场景图。
  • DevTools Performance 看帧时间；关注 draw call 数量。

12. 成长路线

阶段能力标志
小白能加载图、画个会动精灵
初级会交互、Ticker 动画、文本
中级懂批渲染、图集、对象池优化
资深设计渲染架构、压 draw call、控内存与帧率
练习：① 用 Pixi 做一个弹球/粒子效果 ② 用图集批量渲染 1000 个精灵并看 draw call ③ 实现一个对象池的子弹系统 ④ 在 React 里挂载并在卸载时清理 Ticker。
你已进阶：理解 GPU 批渲染与场景图，能做出稳定高帧率的 2D 画面——这是资深互动/游戏前端的分水岭。
