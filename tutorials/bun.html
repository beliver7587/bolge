Bun

一体化的 JavaScript 运行时 + 工具链 —— 比 Node 更快，自带包管理器、测试、打包。学完你能用更现代的“全家桶”跑 JS 项目。

1. 这是什么

Bun 是新一代 JS 运行时（用 Zig 写，内嵌 JS 引擎），目标是一站式替代 Node + npm + 若干工具：

  • 运行时：直接跑 JS/TS，无需先编译 TS。
  • 包管理器：bun install 比 npm install 快很多。
  • 内置：HTTP 服务、测试 bun test、打包 bun build、脚本运行。
一句话：Node 能做的 Bun 都能做，且更省心更快；但不是 100% 兼容所有 Node API。

2. 环境准备

# macOS / Linux
curl -fsSL https://bun.sh/install | bash
# Windows 用 npm：npm install -g bun
bun -v

3. 跑脚本/装包

bun run server.ts        # 直接跑 TS，无需 tsc
bun install              # 装依赖，秒级
bun add express          # 加依赖

4. 内置 API

const txt = await Bun.file('a.txt').text();   // 读文件
await Bun.write('b.txt', txt);                // 写文件
console.log(Bun.env.API_KEY);                 // 读环境变量

5. 起 HTTP 服务

Bun.serve({
  port: 3000,
  fetch(req) {
    return new Response(JSON.stringify({ msg: 'hi from Bun' }), {
      headers: { 'Content-Type': 'application/json' }
    });
  }
});
console.log('http://localhost:3000');

6. 与 Node 差异

能力NodeBun
跑 TS需 tsc/ts-node原生支持
装包npmbun install（快）
测试jest/vitest内置 bun test
HTTP需框架内置 Bun.serve

7. 常见坑

坑 1：某些 Node 专属原生模块/老库不兼容，跑起来报找不到功能；先用 Bun 试，不行回退 Node。
坑 2：Windows 上用 npm 全局装 bun 有时 PATH 没生效，重开终端或手动加。
坑 3：环境变量读取用 Bun.env 而非 process.env（两者都可用，但习惯统一）。
坑 4：部署到服务器要注意运行时是 Bun，CI/启动命令用 bun run 而非 node。
