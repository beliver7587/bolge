Function Calling：从小白到资深

Function Calling 让大模型“开单据”——返回它想调用的函数名与参数，由你的代码真正执行再回传。它是 Agent 的手脚、把 AI 接到真实世界（查库/发消息/算账）的桥梁。本教程讲透工具 Schema、协议往返、并行调用与 tool_choice、参数校验容错、流式工具调用、工具设计与安全。

1. 它解决什么问题

模型本身“只会说话、不能动手”。Function Calling 把“意图”翻译成结构化调用（函数名 + JSON 参数），由你执行副作用，再把结果喂回模型生成答案。

一句话：模型不开支票（不真执行），只是“开出要调哪个函数、传什么参数”的单据；你按单办事、回报结果。

2. 工程化封装

OpenAI / 智谱 / Claude 协议高度相似（tools + tool_calls + tool 角色消息）。生产应封装一层适配器，屏蔽各供应商差异，业务只面向统一接口。

// 统一抽象：调用 → 可能返回 tool_calls → 执行 → 回传
async function callWithTools(messages, tools, exec) {
  let r = await llm.chat({ messages, tools, tool_choice: 'auto' });
  while (r.tool_calls) {
    messages.push(r);                         // 关键：原样存回模型的 tool_calls 消息
    for (const tc of r.tool_calls) {
      const args = await safeParse(tc.function.arguments);
      const out = await exec(tc.function.name, args);   // 你执行真实动作
      messages.push({ role:'tool', tool_call_id: tc.id, content: out });
    }
    r = await llm.chat({ messages, tools });   // 回传后再问一次
  }
  return r.content;
}

3. 工具定义

工具 = JSON Schema 描述的能力清单。模型靠 description 决定“何时用、怎么传参”。

const tools = [{
  type:'function',
  function:{
    name:'getWeather',
    description:'查询指定城市的当前天气（返回温度与天气状况）',
    parameters:{ type:'object', properties:{ city:{type:'string', description:'中文城市名'} }, required:['city'] }
  }
}];
资深：description 要像“写给同事的说明书”——写清用途、参数含义、返回什么，模型才能选对、传对。

4. 协议与往返

  • 模型返回 message.tool_calls（含 id、函数名、参数 JSON 字符串）。
  • 必须原样把这条 tool_calls 消息存回 messages，再追加 role:'tool' 的结果——缺任一步，下一轮 API 会报错或丢失上下文。
  • 一个请求可返回多个 tool_calls（见 §5），每个都要回传对应 tool 消息。

5. 并行与选择

  • 并行调用：模型可在一次回复里并发请求多个无依赖工具（如同时查天气和汇率）；执行方可并行，省一轮往返。
  • tool_choice：auto（模型自决）/required（必须用工具）/none（禁用）/{name}（强制某工具，做“结构化抽取”很稳）。

6. 校验与容错

  • 参数解析：arguments 是 JSON 字符串，可能不完整——JSON.parse 失败要 try/catch，并让模型“重新生成”。
  • Schema 校验：用 zod/ajv 校验类型与必填；不符就回传错误，让模型自纠。
  • 执行兜底：工具异常要捕获，把错误信息（而非崩溃）作为结果回传。

7. 流式工具调用

用 SSE 流式时，tool_calls 的 arguments 是分片增量到达的，需累积拼接完再 JSON.parse：

let acc = { name:'', args:'' };
for await (const chunk of stream) {
  const d = chunk.delta.tool_calls?.[0];
  if (d?.function?.name) acc.name += d.function.name;
  if (d?.function?.arguments) acc.args += d.function.arguments;   // 累积
}
const args = JSON.parse(acc.args);

8. 工具设计

  • 粒度适中：太小导致多步往返，太大模型难选；一个工具做一件事。
  • 幂等：可安全重试（网络抖动时关键）。
  • 返回裁剪：只回必要字段，避免大结果撑爆上下文。

9. 安全

注入 + 越权是头号风险：攻击者可在用户/检索内容里诱导模型调用危险工具（发邮件、删库）。对策：最小权限、危险动作人工审批、对工具输入做净化与校验，详见 提示注入防护。

10. 生产要点

  • 超时/降级：工具慢或挂了要超时并兜底，别拖垮整个对话。
  • 重试：网络/限流（429）按退避重试；参数错误则让模型纠正。
  • 缓存：相同参数的幂等查询可缓存结果，降成本降延迟。

11. 常见坑

坑 1：忘了把模型的 tool_calls 消息原样存回 → 后续 API 报错/丢上下文。
坑 2：参数 JSON 解析失败没兜底 → 崩溃。
坑 3：Schema 过松（啥都 string、不写 required）→ 模型乱传参。
坑 4：工具 description 含糊 → 选错/误用。
坑 5：忽略注入与权限 → 被诱导执行危险动作。
坑 6：工具返回过大 → 上下文爆炸。

12. 调试

  • 打印每次 tool_calls（函数名 + 原始 arguments）与回传结果，确认“选对、传对、执行对”。
  • 用 tool_choice:{name} 做结构化抽取时，验证输出是否符合预期格式。

阶段能力标志

资深安全治理、生产可靠性、与 Agent 编排
