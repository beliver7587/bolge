systemd：从小白到资深

systemd 是现代 Linux 的初始化与服务管理系统，接管启动流程、进程生命周期、日志与定时任务。本教程讲透unit 类型、service 文件结构、依赖顺序、timer 定时、journald 日志、资源限制与排查——比 PM2 更底层、语言无关的 productions 守护方案。

1. 它解决什么问题

系统启动后要拉起一堆服务，并崩溃重启、开机自启、统一日志。systemd 用声明式 unit 文件管理这一切，替代老旧 SysV init 脚本。

对比：PM2 是 Node 专属；systemd 系统级、任何进程都能管，且天然开机自启、纳管日志。

2. unit 类型

  • .service：守护进程（最常见）。
  • .socket：按需激活（端口有连接才拉服务，省资源）。
  • .timer：定时任务，替代 cron。
  • .path：文件/目录变化时触发。

3. unit 文件

放 /etc/systemd/system/my-api.service：

[Unit]
Description=My API
After=network.target            # 网络就绪后再起
Wants=postgresql.service        # 弱依赖

[Service]
Type=exec                       # 主进程即 ExecStart
User=ubuntu
WorkingDirectory=/home/ubuntu/app
ExecStart=/usr/bin/node /home/ubuntu/app/server.js
Environment=NODE_ENV=production
EnvironmentFile=/etc/my-api/env   # 密钥放这里，权限 600
Restart=on-failure             # 非零退出才重启
RestartSec=5
MemoryMax=512M                  # 防内存泄漏拖垮整机

[Install]
WantedBy=multi-user.target      # enable 后开机自启

4. 关键指令

sudo systemctl daemon-reload    # 改了 unit 必执行
sudo systemctl start my-api
sudo systemctl enable my-api     # 开机自启（建软链到 multi-user.target.wants）
sudo systemctl status my-api
sudo systemctl restart / stop my-api
Type 选择：simple/exec（前台主进程）/forking（传统 daemon 自己 fork）/notify（启动后发 READY 信号，配合健康检查）。

5. 依赖与顺序

  • After/Before：仅排序，不保证存在。
  • Requires：硬依赖，依赖挂了本服务也停。
  • Wants：软依赖，最好一起起，失败不影响。

6. 定时 timer

# my-backup.timer
[Timer]
OnCalendar=*-*-* 03:00:00      # 每天 3 点
Persistent=true                # 错过也补跑
[Install]
WantedBy=timers.target

配同名 my-backup.service 执行实际任务，systemctl enable --now my-backup.timer。

7. 日志 journald

journalctl -u my-api -f          # 实时跟踪该服务
journalctl -u my-api --since "1 hour ago" --no-pager
# 持久化：改 /etc/systemd/journald.conf 中 Storage=persistent

8. 资源限制

生产务必加护栏，避免一个服务拖垮整机：

  • MemoryMax / MemoryHigh：内存上限。
  • CPUQuota：CPU 占比上限（如 50%）。
  • TasksMax：最大线程/进程数。

9. 排查

  • systemctl status my-api 看激活状态与最近日志。
  • journalctl -xe 看失败详情（如权限、端口占用）。
  • 手动以同 User 跑 ExecStart 命令，确认路径/依赖无误。

10. 与 PM2 取舍

纯 Node 快速迭代用 PM2 方便（集群/日志面板）；要求系统级纳管、语言无关、与 OS 启动深度集成，用 systemd。两者也可结合：systemd 拉起 PM2（pm2 startup 底层就是写 systemd unit）。

11. 常见坑

坑 1：改 unit 没 daemon-reload → 不生效。
坑 2：User/路径/权限不对，起不来。
坑 3：环境变量没在 unit 设 → 用 Environment/EnvironmentFile。
坑 4：Restart=always 且启动即崩 → 疯狂重启；用 on-failure 或修启动错误。
坑 5：没资源限制，内存泄漏拖垮整机。

12. 成长路线

阶段能力标志
小白会写 service、start/enable/status
初级依赖顺序、EnvironmentFile、日志
中级timer 定时、资源限制、socket 激活
资深故障排查、与容器/PM2 协同治理
练习：① 写 service 管你的后端 ② enable 开机自启 ③ 加 MemoryMax/CPUQuota ④ 用 timer 替代 cron 跑备份 ⑤ journalctl -f 查一次崩溃 ⑥ 把密钥移进 EnvironmentFile。
你已进阶：理解声明式服务管理，能给任意进程做开机自启、崩溃重启、资源护栏与统一日志——这是资深后端在 Linux 上做生产守护的底层能力。
