BM25 关键词检索

经典相关性算法 —— 擅长订单号/型号等精确匹配，与向量检索互补。

1. 这是什么

BM25 是搜索引擎（如 Elasticsearch）背后的经典算法，按“关键词在文档里出现的频率、罕见程度”给文档打分排序。它不懂语义，但精确匹配极强：订单号 A10086、型号、错误码，必须字面对上才召回。

2. 与向量检索互补

方式强项弱项
向量检索懂语义，"无法充电"匹配"充不进电"对专名/编号迟钝
BM25精确匹配专名/订单号/错误码不懂同义改写
结论：两者融合（见 RRF）才是最稳的检索方案，Memora 正是这么做的。

3. 中文分词

中文没有空格，BM25 要先把句子切成词。轻量做法是用 1-gram + 2-gram（单字+双字），免引分词器也能得到可用召回：

// "手机充不进电" → 手、机、充、不、进、电、手机、机充、充不、不进、进电
for(let i=0;i<seg.length;i++){
  tokens.push(seg[i]);
  if(i+1<seg.length) tokens.push(seg.slice(i,i+2));
}

4. RAG 里的角色

在 Memora 的 RAG 链路里，BM25 作为一路召回，与向量路并行，最后用 RRF 融合排序，再交大模型精排。即使向量接口被限流，也能单独降级为只用 BM25，对话不崩。

5. 常见坑

坑 1：中文不分词直接按字，召回质量差——至少上 2-gram。
坑 2：停用词（的、了）要在索引时过滤，否则噪声大。
坑 3：别只用 BM25 而放弃向量，会丢失语义召回能力。
