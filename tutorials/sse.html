SSE：从小白到资深

SSE（Server-Sent Events） 是基于 HTTP 的单向流式推送：浏览器开一条长连接，服务端随时推文本片段，断线浏览器自动重连。它是大模型“打字机式”输出、实时进度条的首选（Memora 即用此流式回答）。本教程讲透协议格式、服务端 flush 与心跳、客户端自动重连、流式 LLM、Nginx 部署、鉴权与健壮。

1. 它解决什么问题

传统请求“一来一回”；SSE 让服务端能持续、逐片地把数据推给浏览器——适合“结果逐步产生”的场景（LLM 逐 token、日志流、行情）。

对比：WebSocket 双向全双工，适合游戏/实时交互；SSE 只下不上、走普通 HTTP，与 Web 框架/反代天然兼容、自动重连。轮询则又慢又浪费。

2. 协议格式

每条事件是一组以 \n\n（空行）结尾的字段行：

data: 第1片\n
data: 第2行也属同一事件\n
event: progress\n
id: 42\n
retry: 3000\n
\n
: 这是注释（心跳），以冒号开头
  • data: 多行会自动拼接成一个事件；event: 指定事件名（默认 message）。
  • id: 用于断线后续传（Last-Event-ID）；retry: 指定重连间隔。
  • 必须以空行 \n\n 结束，否则浏览器不触发。

3. 服务端

app.get('/stream', (req, res) => {
  res.writeHead(200, {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    'Connection': 'keep-alive'
  });
  let i = 0;
  const t = setInterval(() => {
    res.write(`data: 第${i++}条\n\n`);     // 每个事件独立、以空行结尾
    if (i > 5) { clearInterval(t); res.end(); }
  }, 1000);
  // 心跳：定时发注释行，防止代理因空闲断开
  const hb = setInterval(() => res.write(': ping\n\n'), 15000);
  req.on('close', () => { clearInterval(t); clearInterval(hb); });  // 断开务必清理
});

4. 客户端

const es = new EventSource('/stream');
es.onmessage = (e) => render(e.data);                 // 默认 message 事件
es.addEventListener('progress', (e) => updateBar(e.data));  // 命名事件
es.onerror = () => { /* 浏览器会自动重连，无需手动 */ };
  • 断线后浏览器自动重连，并带上 Last-Event-ID 头；服务端可据此续传。
  • 用完 es.close() 释放连接。

6. 流式 LLM

把模型按 token 的增量片段，逐片 data: 推出；前端把 e.data 累加即“逐字出现”的打字机效果（见 Agent 步骤也可如此流式展示）。

资深：每条 SSE 片只含“增量 token”，而非全量；前端负责拼接。注意编码与换行转义。

7. 部署要点

  • Nginx：默认会缓冲响应导致“攒一批才推”，必须 proxy_buffering off; 并设 proxy_read_timeout 足够长（Memora 的 Nginx 已配好）。
  • 若开 gzip，确认不缓冲流式；或对该路由关闭压缩。

8. 鉴权

EventSource 不能自定义 Header：无法用 Authorization: Bearer。改用：① 同源 cookie（推荐，天然带）；② URL 查询参数带 token（注意日志泄露）；③ 先拿一次性 ticket 再连。

9. 健壮与背压

  • 心跳：定时发注释行 : ping\n\n，防代理/网关因空闲断开长连接。
  • 清理：监听 req.on('close') 清掉 timer/流，避免泄漏。
  • 背压：高频写入时关注 res.write 返回 false（缓冲区满），必要时暂停生产。

10. 常见坑

坑 1：事件没以 \n\n 结尾 → 浏览器不触发 onmessage。
坑 2：Nginx 缓冲 → 推送延迟；设 proxy_buffering off。
坑 3：断线没清理 timer/流 → 内存泄漏。
坑 4：想用自定义 Header 鉴权 → EventSource 不支持，改用 cookie/参数。
坑 5：代理空闲超时断流 → 加心跳、调长超时。
坑 6：浏览器同域 EventSource 并发有限 → 及时 close。
