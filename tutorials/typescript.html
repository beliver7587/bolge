TypeScript

给 JavaScript 加“类型”的超级增强版 —— 三个项目都用它写得更稳。

1. 这是什么

TypeScript（简称 TS）是微软出的语言，是 JavaScript 的超集：所有 JS 都能跑，但额外允许你给变量、函数参数标上“类型”。写完后用 tsc 编译成普通 JS 再运行。浏览器只认 JS，所以 TS 是“开发期帮手”。

2. 为什么加类型

核心价值：在写代码时（而不是运行时）就发现错误。比如把字符串传给只接受数字的函数，编辑器立刻标红。项目越大、人越多，类型越能救命。
// JavaScript：错了也发现不了
function add(a, b){ return a + b; }
add("1", 2);   // "12"，静默出错

// TypeScript：编译就报错
function add(a: number, b: number): number { return a + b; }
add("1", 2);   // ❌ 类型不匹配，红波浪线

3. 基础类型

let age: number = 18;
let name: string = "王越";
let ok: boolean = true;
let list: number[] = [1, 2, 3];
let data: any = fetchSomething();  // any：放弃类型检查（尽量少用）

4. 接口与类型别名

用 interface 描述“一个对象长什么样”，团队协作时特别清晰：

interface User {
  id: number;
  name: string;
  vip?: boolean;     // ? 表示可选
}
function greet(u: User){ return "你好 " + u.name; }

5. 泛型入门

泛型 = “类型当参数”，写通用函数时不提前定死类型：

function first<T>(arr: T[]): T { return arr[0]; }
first<number>([1,2,3]);   // T 是 number
first<string>(["a","b"]); // T 是 string

6. 常见坑

坑 1：TS 报错不一定导致运行失败（除非开了严格模式 + 编译失败拦截），但别忽视红波浪线。
坑 2：第三方库若没带类型，需要装 @types/xxx，否则它是 any。
坑 3：过度使用 any 会失去 TS 的意义，能用具体类型就用具体类型。
