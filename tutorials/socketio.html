Socket.IO：从小白到资深实时后端

Socket.IO 是在 WebSocket 之上的实时双向通信库：自动重连、不支持 WS 时降级为长轮询、内置房间/命名空间/广播。本教程讲透连接生命周期、鉴权、Redis Adapter 横向扩展、Nginx 部署、安全与无状态架构——这是做生产级实时系统（聊天、协作、联机游戏）的关键。

1. 它解决什么问题

原生 WebSocket 只管“长连接”，重连、心跳、降级、房间广播都得自己写。Socket.IO 把它包好：

  • 自动重连 + 断线恢复；降级（WS 不通时走 HTTP 长轮询）。
  • 房间/命名空间：天然支持“按组发消息”。
  • ACK 回调：emit 可带确认，知道对方收到。
重要：Socket.IO 是自定义协议，不能用原生 WebSocket 客户端直连它的服务端（反之亦然）——两端必须都用 Socket.IO 或都原生 WS。

2. 工程化起步

npm install socket.io
# 若前端单独打包：npm i socket.io-client

服务端基于 Node.js + Express，把 Socket.IO 挂在同一 http.Server 上（共享端口）。

import express from 'express';
import { createServer } from 'node:http';
import { Server } from 'socket.io';
const app = express();
const httpServer = createServer(app);
const io = new Server(httpServer, { cors: { origin: 'https://你的域名' } }); // 别用 '*' 生产
httpServer.listen(3000);

3. 连接生命周期

  • Handshake：客户端先发 HTTP 请求协商，服务端可在此阶段鉴权（见第 6 节）。
  • connection：连上拿到 socket；disconnect：断线（含原因 reason）。
  • 重连：客户端自动指数退避重连；服务端用 socket.id 会变——用“业务用户标识”而非 socket.id 做状态键。

4. 收发消息

socket.on('chat', (msg, ack) => {          // ack 是客户端传来的回调
  console.log(msg);
  ack({ ok: true });                         // 确认收到
});
socket.emit('chat', '你好', (res) => console.log('对方确认', res));
  • 事件名即“通道”，避免用通用名（如 data），按业务语义命名。
  • 二进制（ArrayBuffer/TypedArray）直接传，无需 base64。

5. 房间与命名空间

socket.join('room-123');                     // 加入房间
io.to('room-123').emit('msg', '房间内广播');  // 仅房间
socket.broadcast.emit('msg', '除自己外全服'); // 广播（排除自己）
io.emit('msg', '全服');                        // 所有人
  • Namespace（io.of('/admin')）隔离不同应用/权限，省端口。
  • 理清作用域：socket 单连接、io 全局、broadcast 排除自己、to 限定房间。

6. 鉴权

在握手阶段就把 token 带上，拒绝非法的连接：

io.use((socket, next) => {
  const token = socket.handshake.auth.token;
  if (!verify(token)) return next(new Error('unauthorized'));
  socket.userId = decode(token).id;          // 挂到 socket 供后续用
  next();
});
别在业务消息里才鉴权：连接即资源，应在 handshake 拦截；且禁止客户端自报“我是谁”，要以服务端校验的身份为准。

7. 横向扩展

单进程有上限。多实例时，A 进程连的 socket 收不到 B 进程的广播——需 Adapter 把事件在节点间转发：

import { createAdapter } from '@socket.io/redis-adapter';
import { createClient } from 'redis';
const pub = createClient(), sub = createClient();
io.adapter(createAdapter(pub, sub));   // 经 Redis 发布订阅转发
关键点：用了多节点必须配 Adapter；且前置 Nginx 要“粘滞会话（ip_hash）”或用 Adapter 让任意节点都能服务。

8. 部署

  • Nginx 反代必须放行 Upgrade：proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";，否则长连接被切断。
  • 心跳 pingInterval/pingTimeout 控制存活检测；超时自动断。

9. 安全

  • origin 校验：只允许可信域名，防跨站 WebSocket。
  • 限流：连接频率/事件频率做节流，防刷连接。
  • 不信任客户端：房间号、目标用户要服务端校验，防越权广播。

10. 架构与性能

架构红线：把“谁在哪个房间”这类状态存进 Redis，而不是进程内存——否则多实例/重启就丢。socket 对象本身只代表一个连接，重启即失。
  • 不要在 socket 上挂大量监听器或闭包，避免内存泄漏。
  • 高频消息合并/节流；大房间广播考虑分片。

11. 常见坑

坑 1：跨域连不上 → 正确配置 cors.origin。
坑 2：原生 WS 客户端接 Socket.IO 服务端 → 协议不兼容，两端要配对。
坑 3：多进程没配 Adapter → 消息收不全。
坑 4：Nginx 没放行 Upgrade → 长连接秒断。
坑 5：用 socket.id 当业务主键 → 重连后 id 变，状态错乱。
坑 6：监听器反复注册（每次连接叠加 on）→ 内存泄漏、重复处理。

12. 调试

  • 服务端 DEBUG=socket.io* node app.js 看协议细节。
  • 客户端 localStorage.debug = 'socket.io-client:socket' 看连接日志。
