WebSocket

持久双向通信协议 —— 实时游戏与流式输出的底层基础。

1. 这是什么

普通 HTTP 是“一问一答、问完就断”；WebSocket 是建立一次连接后长期保持、双方随时互发的协议，像打通了一根电话线。适合聊天、实时游戏、行情推送、流式输出等“需要持续通信”的场景。

2. HTTP vs WebSocket

HTTP： 浏览器 → 请求 → 服务器 浏览器 ← 响应 ← （断开） WebSocket：浏览器 ⇄ 长连接 ⇄ 服务器（随时双向）

3. 浏览器里用

const ws = new WebSocket('wss://域名/ws');   // wss = 加密的 ws
ws.onopen = () => ws.send('你好');            // 连上就发
ws.onmessage = (e) => console.log(e.data);    // 收消息
ws.onclose = () => console.log('断开');

4. 服务端（Node）

import { WebSocketServer } from 'ws';
const wss = new WebSocketServer({ port: 8095 });
wss.on('connection', (ws) => {
  ws.on('message', (buf) => {
    ws.send('收到：' + buf.toString());       // 回显
  });
});
注意：游戏项目里服务器“只转发不解析”——收到的消息原样转给同房间其他人，运算在客户端（见 端侧权威）。

5. 常见坑

坑 1：Nginx 反代要显式转发 Upgrade/Connection 头并关闭缓冲，否则握手失败或长连接被掐（见 Nginx）。
坑 2：长时间没消息可能被中间设备断连，要做“心跳”（定期发个 ping）。
坑 3：断网重连要自己写，别假定连接永远在。
