Next.js：从小白到资深全栈

Next.js 是 React 的生产级框架：约定式路由、混合渲染、API 路由、构建优化一应俱全。本教程带你从“能跑起来”走到“能设计可扩展的全栈架构”，理解它每个默认行为背后的权衡。

1. 它解决什么问题

纯 React + Vite 是 CSR（客户端渲染）：浏览器先下载空 HTML 再拉 JS 画页面——首屏慢、SEO 差、要自己接路由/SSR/API。Next.js 把这些“生产必备但重复造轮子”的事收进框架。

一句话：Next.js = React + 路由 + 混合渲染 + API + 构建优化 + 部署约定。让你专注业务，不必在“怎么把 React 做成网站”上耗散。
适合：需要 SEO 的内容站、带后端的全栈应用、电商/营销页、SaaS 控制台。
不适合：纯内部后台（CSR + Vite 更轻）、超简单静态页。

2. 工程化起步

1

创建项目

pnpm create next-app@latest my-app --typescript --app --tailwind --eslint
cd my-app && pnpm dev

关键选项：--app 选 App Router（新版，推荐）；--src-dir 把代码收进 src/。

2

理解目录

app/
├─ layout.tsx     # 根布局（html/body、全局 Provider）
├─ page.tsx       # 路由 “/”
├─ dashboard/
│  ├─ page.tsx     # “/dashboard”
│  └─ loading.tsx  # 该路由的加载态
├─ api/            # Route Handlers（后端接口）
└─ globals.css
next.config.js

App Router 里文件夹即路由，page.tsx 是页面，layout.tsx 是包裹层。

3

质量门

同 React：ESLint + Prettier + tsconfig 严格模式。Next 自带 next lint。

3. 渲染策略全景

这是 Next 最该懂、也最容易被讲错的部分。四种渲染，各有成本与适用：

策略何时渲染适用
CSR浏览器已登录控制台（无需 SEO）
SSR每次请求个性化、实时、SEO 都要（首屏慢一点）
SSG构建时博客/文档（内容固定、极快）
ISR构建 + 定时重生成电商商品页（海量、偶尔变）
RSC（React Server Components）：组件默认在服务端运行、不进客户端 JS 包。可以直连数据库、读文件，零体积发给浏览器。这是 Next 当前的核心范式。
资深权衡：SSR 每次都算，贵；SSG 快但内容陈旧；ISR 折中。选错策略=要么烧钱要么数据旧。按“数据多久变一次 + 要不要 SEO”决策。

4. App Router 路由

  • 嵌套布局：layout.tsx 用 <Children /> 包子路由，父布局不重挂载——侧边栏/顶栏稳定，只换内容。
  • 动态路由：app/post/[id]/page.tsx，用 params.id 取。
  • 文件约定：loading.tsx（Suspense 兜底）、error.tsx（错误边界）、not-found.tsx（404）、route.ts（API）。
  • 路由组：(marketing)/ 括号不进 URL，用于分组布局。
// app/post/[id]/page.tsx
export default async function Post({ params }: { params: { id: string } }) {
  const post = await db.post.find(params.id);
  return <article>{post.title}</article>;
}

5. 数据获取

App Router 下，Server Component 直接 async/await 取数，无需 useEffect：

// 服务端组件：直接查库，结果随 HTML 一起到浏览器
async function Users() {
  const users = await db.user.list();
  return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}

需要写后端接口时，用 Route Handler：

// app/api/users/route.ts
export async function GET() {
  return Response.json(await db.user.list());
}
对比：传统 SPA 要在前端 useEffect 里 fetch；Next 把“取数”放回服务端，首屏就有数据、还能缓存。

6. Server / Client 边界

默认所有组件是 Server Component（能读 secrets、直连 DB、零客户端体积）。只有用到事件/状态/浏览器 API才加 'use client'。

边界规则：Server 组件可以渲染 Client 组件，但不能把 Server 专有函数作为参数传给 Client 组件（函数没法序列化）。状态/事件要上移到 Client 组件里。
'use client';          // 这一行以下的组件跑在浏览器
export function Like({ id }: { id: string }) {
  const [n, setN] = useState(0);
  return <button onClick={() => setN(n + 1)}>👍 {n}</button>;
}

7. Server Actions 与表单

Next 13+ 的 Server Actions 让你“不写 API 也能写数据”：表单直接调服务端函数，且渐进增强（JS 没加载也能提交）。

'use client';
import { useState } from 'react';
async function save(formData: FormData) {        // 标记为 action
  'use server';
  await db.post.create({ title: String(formData.get('title')) });
}
export function Form() {
  const [pending, start] = useTransition();       // 乐观 UI
  return <form action={save}><input name="title" /><button>保存</button></form>;
}
资深用法：Server Action + revalidatePath 刷新缓存，省掉一整套手写 API 与状态同步。

8. 缓存与重验证

Next 有多层缓存，资深必须理清，否则“改了数据页面不更新”：

  • 请求记忆（Request Memoization）：同一次请求内重复 fetch 去重。
  • Data Cache：fetch 默认缓存到文件系统/内存；用 { cache: 'no-store' } 或 revalidate: 60 控制。
  • Full Route Cache：静态路由缓存整页。
  • Router Cache：客户端过渡缓存。
revalidatePath('/post/123');     // 数据变了，让该路由缓存失效
revalidateTag('posts');          // 或用 tag 批量失效

9. 样式

用 Tailwind（创建时已选）或 CSS Modules（*.module.css）。全局样式放 app/globals.css，布局级样式放 layout.tsx 引入。

10. 性能优化

  • 流式渲染（Streaming）：用 <Suspense> 把慢的部分先“挂起”，其余先到达——首屏更快。
  • next/image：自动懒加载、响应式、WebP，替代原生 <img>。
  • 部分预渲染（PPR，实验）：静态壳 + 动态洞，兼顾快与实时。
  • 打包分析：next build && npx @next/bundle-analyzer 找体积大户。

11. 鉴权与中间件

// middleware.ts：在请求进入页面前统一拦截
export function middleware(req: NextRequest) {
  if (!req.cookies.get('token')) return NextResponse.redirect('/login');
}
export const config = { matcher: ['/dashboard/:path*'] };

会话用 JWT 或 Session；敏感逻辑放 Server Component/Action，token 不落客户端可见的 JS。

12. 部署

  • Vercel：git push 即部署，自动按策略渲染，零配置。适合大多数。
  • 自托管：next build && next start 跑 Node 服务，前面用 Nginx 反代，用 PM2 守护。
  • 环境变量：.env.local（本地）/ .env（提交，非机密），服务端变量别加 NEXT_PUBLIC_ 否则进前端包。

13. 安全

  • 别泄露 secrets：只在 Server 组件/路由读密钥，误加 NEXT_PUBLIC_ 会进浏览器。
  • Server Action 也要校验：客户端能直接构造请求调 action，别信前端传来的任何东西。
  • SSRF：若按用户 URL 服务端取资源，要白名单校验，防内网探测。
  • CSP：配置内容安全策略，配合框架默认转义防 XSS。

14. 常见坑

坑 1：水合不匹配（Hydration mismatch）：服务端和客户端首渲 HTML 不一致（如 new Date()、随机值、读取 localStorage），浏览器报 mismatch 并可能错乱。用 suppressHydrationWarning 或把客户端特有逻辑放 effect。
坑 2：在 Server 组件里 import 了含 'use client' 依赖、却还想传函数，序列化失败。
坑 3：过度用 'use client'，把本可在服务端的组件全搬前端，首屏体积暴涨、DB 逻辑暴露。
坑 4：缓存导致“改了不生效”，不理清四类缓存与 revalidate。

15. 调试与监控

  • next build 输出路由表，标明每个路由是静态(S)/动态(ƒ)/ISR。
  • React DevTools + Next 内置错误覆盖层。
  • 生产接 OpenTelemetry / Sentry 看慢路由与水合错误。
