向量检索 / Embedding

把文字变成数字向量、按语义距离找相似 —— RAG 召回的灵魂。

1. 这是什么

Embedding（向量化）是把一段文字变成一串固定长度数字（如 1024 维）的技术。关键性质：语义越接近的文字，向量在空间里距离越近。于是“手机充不进电”和“iPhone 无法充电”会离得很近——这就是“懂语义”的检索。

2. 向量怎么来

调用“嵌入模型”（如 bge-m3）把文本转成向量：

// 伪代码：用嵌入模型把问题向量化
const qVec = await embed("怎么重置密码");   // 得到 [0.12, -0.3, ...] 共 1024 个数
例子：Memora 用 bge-m3 生成 1024 维向量；知识库每段文字都预先向量化存好。

3. 相似度检索

把用户问题也向量化，算它和库里每段的“距离”（常用余弦相似度），距离越小越相关，取 Top-K：

function cosine(a, b){
  let dot=0,na=0,nb=0;
  for(let i=0;i<a.length;i++){ dot+=a[i]*b[i]; na+=a[i]*a[i]; nb+=b[i]*b[i]; }
  return dot/(Math.sqrt(na)*Math.sqrt(nb));   // 1 最相似，-1 最不相似
}

4. 存储与计算

规模方案
千级（Memora 现状）向量存 SQLite BLOB，内存算余弦，无需向量库
百万级专用向量库：Qdrant / pgvector / Milvus

5. 常见坑

坑 1：查询和入库必须用同一个嵌入模型，否则向量不可比。
坑 2：向量接口限流/故障要降级（Memora 自动降到只用 BM25）。
坑 3：纯向量对“订单号/型号”等精确词不敏感，要和 BM25 混合（见 RRF）。
