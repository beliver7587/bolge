Redis：从小白到资深后端

Redis 是内存中的键值数据库，读写微秒级，常做缓存、会话、限流、排行榜、轻量队列。本教程讲透数据结构选型、持久化、缓存三件套（雪崩/穿透/击穿）、分布式锁、高可用集群与性能陷阱——这是资深后端做高并发系统的必备。

1. 它解决什么问题

相比 MySQL 落盘、适合业务主数据，Redis 把数据放内存、访问极快，适合“要快”或“临时”的数据：缓存、计数、排行榜、Session、限流。

一句话：把慢的 DB 查询结果暂存到 Redis，下次命中缓存，系统快几十倍——但它是缓存/加速层，不是主存储。

2. 工程化起步

docker run -d --name redis -p 6379:6379 redis:7
redis-cli -h 127.0.0.1 -p 6379        # 连上操作

3. 数据结构

类型典型用途
String缓存值、计数器（INCR）、分布式锁
Hash对象（用户资料），部分更新友好
List队列、最新 N 条
Set / ZSet去重 / 排行榜（按分排序）
Stream消息队列（带消费组）
Bitmap / HyperLogLog签到位图 / UV 去重估算
选型：排行榜用 ZSet（ZADD/ZRANGE）；UV 估算用 HLL（省内存）；签到用 Bitmap。

4. 持久化

  • RDB：定时快照，恢复快、文件小，但可能丢最近数据（两次快照间）。
  • AOF：记每条写命令，丢数据少，但文件大、恢复慢。
  • 生产常用混合持久化：RDB 打底 + AOF 增量，兼顾速度与安全性。
别把 Redis 当主库：若只当缓存、关持久化也可；但若靠它存“不能丢”的数据，必须开持久化并确认。

5. 内存与淘汰

maxmemory 2gb
maxmemory-policy allkeys-lru     # 内存满时淘汰最近最少用
  • 策略：noeviction（写报错）/ allkeys-lru（全量 LRU）/ volatile-lru（仅过期键）/ lfu（最不常使用）。
  • 不设会吃光内存被 OOM 杀掉——务必配 maxmemory。

6. 缓存与一致性

Cache Aside（旁路缓存）是主流：

// 读：先缓存，未命中查 DB 再写回
// 写：先更新 DB，再删除缓存（不是更新缓存）
await db.update(...);     // 1. 改主数据
await r.del('user:'+id);  // 2. 删缓存，下次读自然回填
为什么删而非更新缓存：避免并发下“先更新缓存后更新 DB”导致脏数据；删缓存 + 回源更简单可靠（注意罕见的“删缓存失败”需重试/延迟双删）。

7. 三大经典问题

  • 缓存雪崩：大量 key 同时过期 → 请求全压 DB。对策：过期时间加随机抖动、熔断降级。
  • 缓存穿透：查不存在的数据，缓存永不命中，直打 DB。对策：缓存空值、布隆过滤器拦截。
  • 缓存击穿：热点 key 失效瞬间高并发打 DB。对策：互斥重建（只让一个请求回源）、逻辑过期。

8. 分布式锁

// 原子加锁：不存在才设，并带过期（防死锁）
const ok = await r.set('lock:order', token, 'NX', 'PX', 30000);
if (ok) { try { ... } finally { if (await r.get('lock:order')===token) r.del('lock:order'); } }
// 释放要校验 token，防误删别人的锁；长任务用看门狗续期
Redlock 争议：跨多实例的 Redlock 在分布式时钟/网络异常下并非绝对安全；强一致锁考虑 ZooKeeper/etcd，普通防重可用单机 SET NX。

9. 发布订阅 / Stream

  • PUBSUB 轻量广播，但消息不持久、离线丢失。
  • Stream + 消费组：可持久、可重放、能多个消费者分摊——更像正经消息队列（替代部分 Kafka 轻量场景）。

10. 高可用

  • 主从复制：主写从读，从可故障切换（哨兵 Sentinel 自动选主）。
  • Cluster：数据分片（16384 槽）到多节点，水平扩展；客户端按槽路由。

11. 性能

  • Redis 是单线程处理命令（6.0 后 IO 多线程），所以命令要快——避免 KEYS *、大事务。
  • Pipelining：批量发命令省网络往返；Lua 脚本把多命令打包原子执行（如限流 + 记录）。

12. 常见坑

坑 1：当主库又没持久化 → 重启丢数据。
坑 2：bigkey（大 Hash/List）删除阻塞 → 用渐进删除/UNLINK。
坑 3：热 key 集中单节点 → 本地缓存/多副本。
坑 4：KEYS * 阻塞服务 → 用 SCAN 游标迭代。
坑 5：缓存与 DB 不一致 → 用 Cache Aside + 删缓存。
坑 6：不设 maxmemory → 内存爆 OOM。

13. 调试

  • SLOWLOG 看慢命令；INFO memory 看内存；MONITOR 看实时命令（生产慎用）。
  • redis-cli --bigkeys 找 bigkey。

14. 成长路线

阶段能力标志
小白会用基本命令/类型、做缓存
初级懂缓存模式、过期策略
中级解决雪崩/穿透/击穿、分布式锁
资深高可用集群、性能调优、容量规划
练习：① 用 ZSet 做排行榜 ② 实现 Cache Aside 并演示删缓存 ③ 复现并解决缓存穿透（布隆过滤器）④ 用 SET NX 写分布式锁并防误删 ⑤ 用 SCAN 替代 KEYS 找 key。
你已进阶：能设计缓存一致性、扛住高并发三大问题、用 Redis 做锁与队列——这是资深后端做高性能系统的关键能力。
