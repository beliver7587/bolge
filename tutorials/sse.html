SSE：从小白到流式输出

SSE（Server-Sent Events）是服务器通过一条 HTTP 长连接把数据单向推给浏览器，基于标准 text/event-stream。它是 LLM 逐字输出（打字机效果）的常用技术。本教程讲清它与 WebSocket 的区别与实现。

1. 它是什么

SSE 是浏览器原生 API（EventSource），服务端持续发送文本事件，客户端逐个接收。简单、自动重连，专为“服务端→客户端”推送设计。

一句话：SSE = 服务端单向流式推送。最适合“服务器一直发、客户端只收”。
适合：LLM 流式回答、行情推送、通知。不适合：客户端要频繁发消息（那用 WebSocket）。

2. 与 WebSocket

SSEWebSocket
方向服务端→客户端单向双向全双工
协议HTTP（普通）独立 WS 协议
重连浏览器自动自己实现
穿透好（就是 HTTP）需 WS 支持

3. 客户端

const es = new EventSource('/stream');
es.onmessage = (e) => { append(e.data); };     // 逐段接收
es.onerror = () => { /* 浏览器会自动重连 */ };

4. 服务端

res.setHeader('Content-Type','text/event-stream');
res.setHeader('Cache-Control','no-cache');
// 每来一段：res.write('data: 片段\n\n');

注意每条以 \n\n 结尾；用 Nginx 反代要关缓冲（proxy_buffering off）。

5. 流式 LLM

for await (const chunk of llm.stream(messages)) {
  res.write(`data: ${chunk}\n\n`);   // LLM 每吐一个 token 就推一段
}

前端边收边渲染，得到“打字机”效果，首字延迟也更低。

6. 常见坑

坑 1 被缓冲：Nginx/网关缓冲导致不实时，要关缓冲。
坑 2 跨域：EventSource 不支持自定义头，跨域要走 CORS 或同源。
坑 3 断线丢数据：SSE 不持久，断开期间消息丢失，需业务层补。
