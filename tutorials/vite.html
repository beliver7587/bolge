Vite：从小白到资深构建工程师

Vite 是当下主流的前端构建工具与开发服务器。它让“冷启动”从几十秒降到毫秒级。本教程带你从“会用 dev/build”走到“懂 ESM 预构建、HMR、产物优化，能为大型项目定制构建链路”。

1. 它解决什么问题

老一代打包器（Webpack）启动时要先把整个应用打包成 bundle 再起服务——项目越大越慢，改一行也要等。开发体验与“项目规模”成反比。

一句话：Vite 在开发期利用浏览器原生 ESM，按需编译、秒级启动；在生产期用 Rollup 做优化打包。开发快、上线也快。
为什么快：① 开发时不打包，浏览器用原生 import 拉模块，Vite 只编译“被请求到的文件”；② 依赖（node_modules）用 esbuild 预构建成 ES 模块并缓存；③ 生产用 Rust 写的 esbuild/Rollup 做极致压缩。

2. 工程化起步

1

创建项目

pnpm create vite@latest app --template react-ts
cd app && pnpm i && pnpm dev

模板含 react/vue/vanilla 等，也可空模板自建。

2

关键文件

vite.config.ts   # 构建配置
index.html       # 入口（Vite 以 HTML 为入口，而非 JS）
tsconfig.json
package.json     # scripts: dev / build / preview

注意：Vite 的入口是 index.html，它用 <script type="module" src="/src/main.ts"> 拉入口模块。

3. 核心原理

  • 原生 ESM 开发服务器：浏览器直接请求 /src/main.ts，Vite 实时把 TS/JSX 编译成浏览器能跑的 JS 返回，不生成中间 bundle。
  • 依赖预构建（Pre-bundling）：node_modules 里的 CJS/ESM 混包、海量小文件，Vite 用 esbuild 一次性转成精简 ESM 并强缓存（node_modules/.vite）。避免浏览器发成百上千个请求。
  • 生产构建：用 Rollup 做 tree-shaking、代码分割、压缩，产出可上线的静态文件。
资深视角：开发快≠生产随便。生产构建的优化（分包、target、压缩）决定了真实用户的首屏。两者用的是不同引擎，不能只看 dev 体验。

4. 配置详解

import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import path from 'node:path';

export default defineConfig({
  plugins: [react()],
  resolve: { alias: { '@': path.resolve(__dirname, 'src') } }, // 路径别名
  server: {
    port: 5173,
    proxy: { '/api': 'http://localhost:3000' },  // 开发跨域代理
  },
  build: {
    target: 'es2020',
    outDir: 'dist',
    sourcemap: false,
  },
});
要点：代理解决开发期“前端 5173 调后端 3000”的跨域；别名 @ 让深目录引用变干净。

5. 插件生态

Vite 的插件接口兼容 Rollup 生态。常用：

  • @vitejs/plugin-react / plugin-vue：框架支持。
  • unplugin-auto-import：自动导入 API，少写 import。
  • vite-plugin-pwa：一键 PWA。
  • vite-plugin-svgr：把 SVG 当组件导入。
自定义插件：插件是个带 name 和钩子（transform/resolveId/load）的对象，可在构建流水线任意点介入——这是资深做“私有组件库按需注入/规范检查”的利器。

6. HMR 原理

热模块替换（HMR）：改一个文件，只替换那个模块，不刷新整页，状态保留。

  • Vite 通过 WebSocket 通知浏览器“某模块变了”。
  • 模块需自己实现 import.meta.hot.accept 处理更新；框架插件已内置（React Fast Refresh / Vue HMR）。
  • HMR 边界：更新会向上找“能接受热更新的最近边界”，边界外仍可能整组件树重挂载。
坑：全局副作用（如注册全局事件、改 document）在 HMR 时可能重复执行，需用 import.meta.hot.dispose 清理。

7. 环境变量与模式

// .env.local
VITE_API_URL=https://api.example.com
// 代码里
console.log(import.meta.env.VITE_API_URL);
  • 只有 VITE_ 前缀的变量才会进客户端包，其余仅服务端可见。
  • --mode staging 加载 .env.staging，区分环境。
坑：把密钥写成 VITE_SECRET 会打进前端包，任何人都能看到。真密钥只在后端用。

8. 代码分割与优化

build: {
  rollupOptions: {
    output: {
      manualChunks: {
        vendor: ['react', 'react-dom'],   // 把稳定库拆独立 chunk，长缓存
      },
    },
  },
}
  • 动态 import()：路由级自动分包，首屏不带全量代码。
  • manualChunks：把不常变的第三方拆出来，利用浏览器长缓存。
  • target：设低了兼容老浏览器但包变大；按用户群取舍。

9. 与框架集成

React 用 @vitejs/plugin-react（Fast Refresh），Vue 用 @vitejs/plugin-vue。Next.js 内部也是基于类似思路（但它自带更重的约定）。

10. 部署

pnpm build      # 产出 dist/
pnpm preview    # 本地预览产物
  • 产物是纯静态文件，丢到 Nginx/CDN/对象存储即可。
  • base 路径：若部署在子路径（如 /app/），要设 base: '/app/'，否则资源 404。

11. 常见坑

坑 1：路径别名只在 Vite 配，TS 不认——要在 tsconfig.json 的 paths 同步配，否则 IDE/类型报错。
坑 2：开发用 proxy 解决跨域，但生产没有 proxy——上线要由 Nginx 或后端处理跨域/CORS。
坑 3：把密钥放 VITE_ 前缀，泄露到前端。
坑 4：大依赖（如某个巨无霸库）没预构建/分包，首屏卡。检查并用 manualChunks 拆。
坑 5：部署子路径忘设 base，资源全 404。

12. 调试与剖析

  • vite build --debug 看插件执行。
  • rollup-plugin-visualizer 生成产物体积图，找“体积大户”。
  • 慢启动先看是不是依赖预构建没命中缓存（清 node_modules/.vite 重试）。

13. 成长路线

阶段能力标志
小白会 create、dev、build
初级会配 alias、proxy、env
中级懂 HMR/预构建原理、会分包优化
资深能写自定义插件、为大型项目定制构建链路、定位构建性能瓶颈
练习：① 给项目配 alias + proxy ② 用 manualChunks 拆 vendor ③ 装 visualizer 找出最重依赖并优化 ④ 写一个自动注入版本号的 Vite 插件。
你已进阶：理解“开发快”和“生产优”是两套引擎、懂得按需分包与跨域真相——这是资深前端构建能力的核心。
