Java：从小白到资深工程师

Java 是依靠 JVM 跨平台 的强类型面向对象语言，是银行、电商、安卓与企业后端的主力。本教程从“能写能跑”讲到JVM 内存模型、GC、并发编程、集合原理、Stream、JVM 调优与诊断——这是资深 Java 工程师的内功。

1. 它解决什么问题

WORA（一次编写，到处运行）靠 JVM：Java 编译成字节码，由各平台 JVM 解释/即时编译执行。相比 C 要为每个平台重编译、手动管内存，Java 自带内存管理（GC）与跨平台；相比 Python，它强类型、性能好、适合大型协作系统。

一句话：Java = 严谨的类型系统 + JVM 跨平台 + 自动内存管理 + 海量企业生态（尤其 Spring）。
适合：企业后端、分布式系统、安卓、大数据（Hadoop/Spark）。
不适合：系统底层、极致启动速度的 CLI（看 Bun）。

2. 工程化起步

  • 装 JDK 17+（LTS）；设 JAVA_HOME，验证 java -version。
  • 构建用 Maven（pom.xml）或 Gradle；IDE 用 IntelliJ IDEA。
  • 标准布局：src/main/java（源码）、src/test/java（测试）、resources。
public class Hello {
  public static void main(String[] args) {
    System.out.println("Hello Java");   // javac 编译 → java 运行
  }
}

3. JVM 与内存

JVM 运行时数据区：

  • 堆（Heap）：对象实例，GC 主战场；分新生代（Eden/Survivor）与老年代。
  • 虚拟机栈：每线程一个，存栈帧（局部变量、调用）；栈溢出 StackOverflowError。
  • 元空间（Metaspace）：类元数据（替代老 PermGen）。
  • 程序计数器 / 本地方法栈。
资深：懂“对象在堆、引用在栈、GC 只清堆”，才能定位内存泄漏与 OOM。

4. 面向对象深入

  • 封装/继承/多态是基础；组合优于继承（继承耦合紧、易碎）。
  • 接口 vs 抽象类：接口是“能力契约”（可多实现），抽象类是可复用基类（单继承）。
  • 多态靠“父类引用指向子类对象 + 方法重写”，配合 Spring 的依赖注入实现解耦。

5. 集合原理

List<String> list = new ArrayList<>();   // 数组实现，随机访问 O(1)，扩容 1.5 倍
Map<String, Integer> m = new HashMap<>(); // 数组+链表/红黑树，哈希冲突转树
  • HashMap 非线程安全——并发用 ConcurrentHashMap（分段/CAS + 红黑树）。
  • ArrayList 遍历中删除会 ConcurrentModificationException → 用迭代器或 removeIf。

6. 泛型

泛型是编译期类型安全，运行时被“擦除”（类型信息不在字节码保留）。

PECS 原则：Producer（生产者）用 extends、Consumer（消费者）用 super，让泛型方法既安全又灵活（如 Collections.copy）。

7. 并发编程

ExecutorService pool = Executors.newFixedThreadPool(8);
pool.submit(() -> doWork());          // 别手动 new Thread，用线程池
// 共享变量：synchronized / ReentrantLock 保证互斥；volatile 保证可见性
  • 可见性：线程改了变量别的线程未必立刻看到 → volatile 或锁。
  • 原子性：i++ 非原子 → 用 AtomicInteger。
  • 线程池：控制并发度、复用线程；避免无界队列堆积或 newCachedThreadPool 撑爆线程。
  • 高并发工具：CountDownLatch/CyclicBarrier/CompletableFuture（异步编排）。

8. 函数式与 Stream

list.stream().filter(s -> s.length() > 3).map(String::toUpperCase).collect(Collectors.toList());
  • Lambda + Stream 让集合处理声明式、可读；但并行流 parallelStream 有共享 ForkJoinPool 风险，IO 密集别用。
  • Stream 是“惰性求值 + 终止操作触发”，别在流里改外部状态。

9. I/O 与 NIO

  • 传统 BIO 阻塞；NIO 用 Channel/Buffer/Selector 做多路复用，是高并发网络（Netty）的底座。
  • 文件系统用 java.nio.file；大文件用缓冲流。

10. 异常处理

  • Checked（必须处理，如 IOException）vs Unchecked（RuntimeException，如 NPE）。
  • try-with-resources 自动关资源（流/连接），杜绝泄漏。
  • 异常别吞掉、别用异常做流程控制。

11. 性能与调优

  • GC 算法：G1（默认，平衡）、ZGC/Shenandoah（超低停顿，大堆友好）。
  • 常用参数：-Xms/-Xmx（堆上下限）、-XX:+UseG1GC。
  • 调优思路：先定位瓶颈（CPU/内存/IO/锁），再针对性调；用 GC 日志 + 火焰图。

12. 常见坑

坑 1：NullPointerException → 用 Optional、判空或 @NotNull。
坑 2：== 比对象比的是引用 → 字符串/对象用 equals。
坑 3：HashMap 并发改 → 用 ConcurrentHashMap。
坑 4：自动装箱 Integer 频繁拆装箱影响性能/缓存陷阱（-128~127 才缓存）。
坑 5：字符串大量拼接用 + 在循环里 → 用 StringBuilder。
坑 6：共享可变状态未同步 → 诡异并发 bug。

13. 调试诊断

  • jstack 看线程栈、jmap 看堆、jvisualvm 可视监控。
  • Arthas 在线诊断（方法耗时、热改、看类加载）；火焰图定位 CPU 热点。
