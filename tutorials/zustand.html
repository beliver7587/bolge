Zustand

极简的 React 状态管理库 —— 不用 Provider 包裹、不用写 reducers，一个函数搞定全局状态。学完你能优雅地跨组件共享数据。

1. 这是什么

当状态需要在多个不相邻组件之间共享（比如登录用户、主题、购物车），React 的 useState 就不够用了。传统 Redux 太啰嗦，Zustand 用极简 API 解决：

一句话：Zustand 就是一个“全局变量 + 订阅”，任何组件都能读、都能改，且改了相关组件自动刷新。
优点：无 Provider 嵌套、API 极小（create 一个函数）、TS 友好、可脱离 React 使用。

2. 环境准备

已有 React 项目（Vite/Next 均可）。安装：

npm install zustand

3. 创建 store

新建 store.js：

import { create } from 'zustand';

export const useUserStore = create((set) => ({
  name: '游客',
  isLogin: false,
  login: (name) => set({ name, isLogin: true }),
  logout: () => set({ name: '游客', isLogin: false })
}));
要点：create 里返回一个对象，包含“状态”和“修改状态的函数”；函数内部用 set 来更新。

4. 在组件里用

import { useUserStore } from './store';

function Header() {
  const name = useUserStore((s) => s.name);
  const isLogin = useUserStore((s) => s.isLogin);
  return <div>{isLogin ? name : '请登录'}</div>;
}
关键写法：useUserStore((s) => s.name) 只订阅 name 这一项——只有 name 变时这个组件才重渲染，性能好。

5. 改状态的几种写法

// 直接 set 新对象
useUserStore.getState().login('小王');   // 非组件里也能调用

// 组件内调用 action
const login = useUserStore((s) => s.login);
login('小王');

// 基于旧值更新
set((state) => ({ count: state.count + 1 }));

6. 跨组件共享（实战）

A 组件登录后，B、C 组件立刻读到新用户——无需把 state 一层层传 props：

function LoginBtn() {
  const login = useUserStore((s) => s.login);
  return <button onClick={() => login('小红')}>登录</button>;
}
// Header 里已 useUserStore 读 name，点登录后自动变成“小红”

7. 常见坑

坑 1：订阅了整个 store（const s = useUserStore()），任何字段变都重渲染。应只选需要的字段。
坑 2：在 set 里直接改原对象（state.name='x'）不生效，必须返回新对象 set({name:'x'})。
坑 3：Next.js 的 SSR 中 store 是模块级单例，多个请求会共享状态；需要按请求隔离时用 createStore + Context。
坑 4：非组件环境（如工具函数）用 useUserStore.getState() 取值，而不是当成普通对象。
