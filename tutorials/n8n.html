n8n：从小白到资深

n8n 是开源的可视化工作流自动化平台——拖拽节点把“触发→处理→动作”串成流水线，免写胶水代码，还能内嵌 大模型 节点。本教程讲透部署、JSON 数据流、触发器、常用节点、错误处理、凭据与成本控制，以及实战（每日热点推送企业微信）——把重复劳动交给自动化。

1. 它解决什么问题

很多业务是“定时/事件 → 调接口 → 处理 → 通知”的胶水逻辑，纯写代码成本高、改起来慢。n8n 用可视化节点表达，非程序员也能改，且自带调度、重试、凭据管理。

对比：Zapier/Make 是 SaaS（数据出公网、按次收费）；n8n 可自托管、数据不出内网、按执行节点计费免费。

2. 部署

docker run -d --name n8n -p 5678:5678 \
  -e N8N_SECURE_COOKIE=false \
  -e N8N_BASIC_AUTH_ACTIVE=true -e N8N_BASIC_AUTH_USER=admin -e N8N_BASIC_AUTH_PASSWORD=xxx \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n
  • 数据持久化：挂卷存 .n8n，否则容器删了工作流全没。
  • 对外暴露：经 Nginx 反代 + HTTPS + Basic Auth（Memora 即如此：n8n.ai应用.wylab.asia）。

3. 核心概念

  • 节点：一个动作（HTTP、函数、数据库、LLM）。
  • 连接：数据以 JSON items 在节点间流动；上节点输出即下节点输入。
  • 表达式：{{ $json.field }} 取上一步字段；$node["x"].json.y 取指定节点。
// Function 节点：规范输出为数组
return [{ json: { msg: '你好 ' + $json.name } }];

4. 触发器

  • Manual：手动点跑，调试用。
  • Schedule / Cron：定时（如每天 20:00）。
  • Webhook：暴露 URL，外部 POST 即触发。
  • 其他：邮件、表单、数据库轮询等。

5. 常用节点

  • HTTP Request：调任意 REST API（如 Express 后端、新闻接口）。
  • Function / Code：写 JS 处理/转换数据。
  • 数据库节点：MySQL/Postgres/Redis 直接读写。
  • AI 节点：OpenAI/国产模型，做“收文本→大模型→存库”。

6. 错误处理

  • Continue On Fail：单节点失败不中断整条流。
  • 错误分支：用 IF/Error Trigger 节点做降级或告警。
  • 重试：节点设 Retry On Fail（指数退避），应对 429/5xx。

7. 凭据与成本

  • 凭据：用 n8n Credentials 加密存储 API Key，绝不硬编码在节点表达式里。
  • 执行数据：可配置“存执行数据 N 天”便于调试，但占空间；生产可缩短或关闭。
  • 成本：循环/批量要设上限，避免产生海量执行把内存吃满。

8. 实战案例

Memora 每日热点推送：Timer(每天20:00) → HTTP Request 调 /api/hotnews/fetch 抓新闻 → LLM 节点摘要 → HTTP Request 推企业微信 webhook。注意 n8n v2.8 发布模型：导入工作流仅 active=1 不够，必须把 workflow_entity.activeVersionId 设为 versionId 才会真正注册定时触发器。

9. 何时不用 n8n

复杂分支逻辑、高性能流处理、需强类型/单测的场景，还是写代码更可控。n8n 适合“中等复杂度、常变更、非程序员也需改”的胶水自动化。

10. 常见坑

坑 1：节点数据格式不匹配（期望数组给对象）→ Function 节点用 return [{json:{...}}] 规范。
坑 2：Webhook 公网暴露无鉴权 → 经 Nginx + Basic Auth/HTTPS。
坑 3：循环产生海量执行吃满内存 → 设批量上限。
坑 4：凭据硬编码 → 用 Credentials 管理。
坑 5：定时没生效（v2.8 的 activeVersionId 坑）→ 检查触发器确实注册。

你已进阶：理解用可视化编排替代胶水代码，能设计可靠、安全、低成本的自动化流水线——这是资深后端做效率工程的利器。
