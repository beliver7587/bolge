JWT / bcrypt 认证

无状态登录的令牌标准 + 密码哈希 —— 两个项目的鉴权底座。

1. 这是什么

JWT（JSON Web Token）是一种“登录凭证”标准：用户登录成功后，服务器发一段签名过的字符串，之后每次请求带上它，服务器验签即可知道“你是谁”，无需查库。bcrypt 是把密码“加盐哈希”存储的算法，即使数据库泄露也还原不出原密码。

2. 登录流程

① 用户提交账号密码 → ② 服务端用 bcrypt 比对密码哈希 → ③ 比对成功，签发 JWT 返回 → ④ 前端存 Token，之后请求带上 → ⑤ 服务端验签，放行

3. bcrypt 存密码

import bcrypt from 'bcryptjs';
const hash = await bcrypt.hash('明文密码', 12);   // 12 轮加盐，永不存明文
const ok = await bcrypt.compare('输入密码', hash); // 比对

4. JWT 结构

JWT 由 头部.载荷.签名 三段 base64 组成，载荷里放 userId、过期时间等。Memora 还加了 令牌版本号 tv：改密码时 tv+1，所有旧令牌立即失效。

const token = jwt.sign({ userId:1, tv:3 }, SECRET, { expiresIn:'12h' });
// 验证：显式指定算法防 alg=none 攻击
jwt.verify(token, SECRET, { algorithms:['HS256'] });

5. 常见坑

坑 1：用默认弱密钥——Memora 若检测到弱密钥会自动生成随机密钥防伪造。
坑 2：Token 存 localStorage 易被 XSS 偷——放 httpOnly Cookie 更安全。
坑 3：登录失败响应不同导致账号枚举——用恒定时间比较、统一文案。
