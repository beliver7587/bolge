systemd：从小白到服务守护

systemd 是 Linux 的系统与服务管理器，用 unit 文件托管后台进程、保证开机自启、统一看日志。你的 Nginx、PM2 都靠它管。本教程讲清怎么写一份服务文件。

1. 它是什么

systemd 接管开机启动、服务生命周期与日志，是现代 Linux 发行版的标准 init 系统。

一句话：systemd = Linux 的“服务总调度”。写个 unit，进程就有人管（启停/自启/日志）。

2. unit 文件

# /etc/systemd/system/myapi.service
[Unit]
Description=My API
After=network.target
[Service]
ExecStart=/usr/bin/node /opt/api/dist/main.js
Restart=always
User=app
[Install]
WantedBy=multi-user.target

3. 常用命令

命令作用
systemctl start myapi启动
systemctl enable myapi开机自启
systemctl status myapi看状态
systemctl restart myapi重启

4. 写服务

  • Restart=always：进程退出自动拉起（守护）。
  • User=：降权运行，别用 root。
  • WorkingDirectory=：设工作目录。

5. 日志

journalctl -u myapi -f    # 跟随看某服务日志

日志由 journald 统一收集，不用自己管日志文件轮转。

6. 开机自启

systemctl daemon-reload     # 改了 unit 后重载
systemctl enable --now myapi

服务器重启后服务自动起来，配合 PM2 的 startup 同理。

7. 常见坑

坑 1 改完忘 reload：新 unit 不生效，先 daemon-reload。
坑 2 权限：ExecStart 路径/用户权限不对，启动失败，看 status 排查。
坑 3 循环重启：进程秒崩 + Restart=always 会狂重启，先修程序再托管。

8. 资源与路线

  1. man systemd.service、DigitalOcean 的 systemd 教程。
  2. 配合 Nginx、PM2、Docker。
  3. 练：把一个 Node/Java 服务写成 unit 并配开机自启。
资深标志：能用 unit 把任意进程做成“生产级守护”，设好 Restart/User/日志，让服务在机器重启后自愈。

完整流程：Systemd 托管服务

1. 写 unit 文件
/etc/systemd/system/myapp.service
[Unit]
Description=My App
After=network.target

[Service]
Type=simple
User=www
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/node /opt/myapp/index.js
Restart=always

[Install]
WantedBy=multi-user.target
2. 启动
sudo systemctl daemon-reload
sudo systemctl enable myapp
sudo systemctl start myapp
3. 查看日志
sudo systemctl status myapp
sudo journalctl -u myapp -f
要点：ExecStart 要写绝对路径；用非 root 用户运行更安全。
