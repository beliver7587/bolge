Docker：从小白到容器部署

Docker 把应用和依赖打包成镜像，到处一致运行，是部署事实标准。简历工坊、游戏后端都用它交付。本教程讲清镜像/容器、Dockerfile 与 Compose——让你“一次构建，到处运行”。

1. 它是什么

容器是轻量隔离的运行环境：共享内核，比虚拟机省资源；镜像则是容器的只读模板。

一句话：Docker = 镜像（模板）+ 容器（运行实例）。环境一致，告别“我本地能跑”。

2. 起步

docker --version
docker run -p 8080:80 nginx      # 跑一个 nginx 容器

镜像不存在会自动从仓库拉取。

3. 镜像与容器

  • 镜像：分层只读文件系统，docker images 查看。
  • 容器：镜像的运行态，docker ps 查看运行中的。

4. Dockerfile

FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build
CMD ["node","dist/main.js"]
坑：把 COPY . . 放在 npm ci 后，利用层缓存；别漏 .dockerignore 导致塞进 node_modules。

5. 常用命令

docker build -t app .
docker run -d -p 3000:3000 --name api app
docker logs -f api
docker exec -it api sh

6. 数据卷

容器删了数据就没，持久化用卷（volume）或挂载主机目录：

docker run -v mydata:/data app     # 命名卷
docker run -v $(pwd):/app app       # 挂载当前目录

7. 网络

容器间用自定义网络互通；对外用 -p 宿主机:容器 暴露端口。生产前接 Nginx 反代。

8. Compose

# docker-compose.yml
services:
  web: { build: ., ports: ["3000:3000"] }
  db:  { image: mysql:8, environment: { MYSQL_ROOT_PASSWORD: x } }

docker compose up 一键起多容器应用，开发/演示极方便。

9. 与虚拟机

容器虚拟机
隔离进程级（共享内核）系统级（各带内核）
启动秒级分钟级
密度高低

10. 常见坑

坑 1 镜像过大：用 alpine 基础镜像 + 多阶段构建，只留运行所需。
坑 2 数据丢失：没挂卷，容器删数据没；明确持久化策略。
坑 3 权限：容器内 root 写宿主机挂载目录可能权限错，注意 UID 映射。
