JWT

JSON Web Token —— 无状态的登录凭证，前后端分离必备。学完你能实现“登录后带令牌访问受保护接口”。

1. 这是什么

JWT 是一种令牌格式：服务端登录成功后签发一个字符串，客户端之后每次请求带上它，服务端验签即可知道“是谁、有没有权”，无需查库存会话。

对比：传统 Session 把登录状态存服务端；JWT 把状态编码进令牌本身，服务端无状态、易横向扩展。

2. 令牌结构

JWT 是 header.payload.signature 三段 base64：

  • header：算法（如 HS256）。
  • payload：存放数据（userId、过期时间 exp 等），任何人可解码看到，别放密码。
  • signature：用密钥对前两段签名，防篡改。

3. 签发令牌

Node 用 jsonwebtoken：

import jwt from 'jsonwebtoken';
const token = jwt.sign(
  { userId: 1, name: '小王' },
  process.env.JWT_SECRET,     // 服务端密钥，绝不外泄
  { expiresIn: '2h' }
);

4. 校验令牌

function auth(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];
  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET);   // 验签+过期
    next();
  } catch { res.status(401).json({ msg: '未登录' }); }
}

5. 前端携带

fetch('/api/me', { headers: { Authorization: 'Bearer ' + token } });

6. 刷新令牌

访问令牌短命（如 2h），另发一个长效 refresh token 存 HttpOnly Cookie；访问令牌过期时用 refresh 换新的，提升安全性。

7. 常见坑

坑 1：密钥写死在代码或泄露，任何人可伪造令牌；用环境变量且足够随机。
坑 2：payload 里放敏感信息（密码），base64 一解码就暴露。
坑 3：不设过期或过期太长，令牌被盗用风险高；短过期 + refresh。
坑 4：前端把 token 存 localStorage 易被 XSS 偷；敏感场景用 HttpOnly Cookie。
坑 5：JWT 无法主动吊销（除非维护黑名单）；重大风险时只能等过期或换密钥。
