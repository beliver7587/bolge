LLM：从小白到大语言模型

LLM（大语言模型）是基于海量文本训练出的神经网络，能理解并生成自然语言，是 RAG、Agent 的“大脑”。Memora 用它做客服回答。本教程讲清调用方式、参数与局限。

1. 它是什么

LLM 本质是“超强的文本续写器”：给定上下文，预测下一个最可能 token。通过提示（Prompt）引导它完成任务。

一句话：LLM = 读得多、会续写的 AI。Prompt 是给它的指令，输出是它“猜”的续写。

2. 核心能力

  • 理解：问答、摘要、分类、翻译。
  • 生成：写代码、写文案、写 SQL。
  • 推理（有限）：按步骤思考（思维链）解决简单问题。

3. 怎么调用

const res = await client.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role:'user', content:'用一句话解释 RAG' }],
});
console.log(res.choices[0].message.content);

消息分 system（设定角色/规则）、user、assistant（历史）。

4. 关键参数

参数作用
temperature越高越随机，越低越确定
top_p核采样，控制多样性
max_tokens最大输出长度
stop停止符

5. 与 Provider

模型由 Provider（如 OpenAI、通义、DeepSeek、本地模型）提供，通过统一网关（如 one-api）切换，避免绑定单一厂商。

6. 局限

  • 幻觉：会编看似合理但错误的内容（用 RAG 缓解）。
  • 知识截止：训练数据有时间点。
  • 上下文窗口：一次能处理的 token 有限，超了要截断/摘要。

7. 常见坑

坑 1 当百科用：不问出处直接信，会踩幻觉；关键事实要 RAG + 引用。
坑 2 参数乱调：temperature 太高回答飘，太低死板；按任务选。
坑 3 上下文溢出：塞太多历史/资料超窗口，要管理记忆（Memory）。

8. 资源与路线

  1. 各 Provider 官方文档、提示工程指南。
  2. 接着学 RAG、Agent、Provider。
  3. 练：用 API 做一个带 system prompt 的问答机器人。
资深标志：能把 LLM 当“不确定但强大”的组件，用 RAG/工具/护栏把它约束到可靠，而不是无脑当真理源。
