Docker：从小白到资深

Docker 用容器把应用连同依赖打包，一次构建到处运行，告别“我机器上能跑”。本教程讲透容器 vs 虚拟机、镜像分层与写时复制、Dockerfile 最佳实践、多阶段构建、网络与卷、compose 编排、安全与镜像治理、生产要点——部署一致性的核心能力。

1. 它解决什么问题

环境差异常导致“本地能跑线上挂”。Docker 把代码+运行时+系统库封进镜像，环境即代码，部署可复现。

对比虚拟机：VM 带整套 Guest OS（GB 级、启动慢）；容器共享宿主内核、只隔离进程（MB 级、秒起）。

2. 架构原理

  • 守护进程 + CLI：dockerd 管镜像/容器，CLI 发指令。
  • 镜像分层：每层是只读快照，FROM 继承；相同层只存一份。
  • 写时复制 CoW：容器在镜像层上盖一层可写层，改动只落在此层，删容器即丢（除非挂卷）。
  • Union FS：overlay2 把多层合并成统一视图。

3. 镜像与容器

docker pull nginx
docker run -d -p 8080:80 --name mynginx nginx   # -d 后台；-p 主机:容器端口
docker ps -a              # 看容器（含已停）
docker stop/rm mynginx
概念说明
Image 镜像只读模板，由 Dockerfile 构建
Container 容器镜像的运行实例，可启停删
Registry 仓库存镜像（Docker Hub / 私有）

4. Dockerfile 最佳实践

FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev          # 用 lockfile 确定性安装
COPY . .
RUN addgroup -S app && adduser -S app -G app   # 建非 root 用户
USER app
EXPOSE 3000
HEALTHCHECK --interval=30s CMD node healthcheck.js
CMD ["node", "server.js"]
  • 精简基础：alpine/distroless 减小体积与攻击面。
  • 层缓存：先 COPY 依赖清单并安装，再 COPY 代码，改代码不重建依赖层。
  • 非 root：容器内降权，防逃逸提权。
  • .dockerignore：排除 node_modules/.env，避免污染与泄密。

5. 多阶段构建

FROM node:20 AS build
WORKDIR /app
COPY . .
RUN npm ci && npm run build
FROM node:20-alpine AS run
COPY --from=build /app/dist /app/dist
CMD ["node", "/app/dist/server.js"]
价值：构建工具链留在 build 阶段，最终镜像只含产物，体积骤减、更安全。

6. 网络与存储

  • 网络：bridge（默认，容器间互通需同网络）、host（共用宿主网络）、none。
  • 存储：-v 命名卷（docker 管理，持久化）优于 bind mount；数据库必须挂卷，否则删容器数据没了。

7. 编排 compose

# docker-compose.yml
services:
  app:
    build: .
    ports: ["3010:3010"]
    environment:
      - NODE_ENV=production
    depends_on: [db]
    restart: unless-stopped
  db:
    image: postgres:16
    volumes: ["pgdata:/var/lib/postgresql/data"]
volumes: { pgdata: {} }

8. 安全与镜像

  • 最小镜像：distroless / alpine，少装包少漏洞。
  • 镜像扫描：docker scout cves 或 Trivy 查已知 CVE。
  • 密钥：绝不进镜像；用 env/secret/外部 Vault。
  • 基镜像固定版本：别用 latest 漂流，保证可复现。

9. 生产要点

  • restart: unless-stopped 崩溃自启（或交给 systemd/k8s）。
  • 资源限制：--memory/--cpus 防单容器吃满。
  • 日志驱动：接 json-file 限制大小或发到集中日志。

10. 常见坑

坑 1：容器数据不持久 → 挂卷。
坑 2：没 -p 映射，外部访问不了。
坑 3：镜像越积越大 → 多阶段 + 精简基础。
坑 4：用 latest 导致环境漂移、难回滚。
坑 5：root 跑容器 + 漏洞 = 提权风险；降权。
