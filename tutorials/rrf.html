RRF 融合排序

按“排名”而非“分数”融合多路召回 —— 规避分数量纲不一致。

1. 这是什么

RRF = Reciprocal Rank Fusion（倒数排名融合）。当你有两路（或多路）检索结果——比如 向量检索一路、BM25一路——怎么把它们的排序合到一起？RRF 用“排名”而非“分数”来融合，避免两路分数不可比的问题。

2. 为什么按排名

痛点：向量路的分数在 0~1，BM25 可能是 0~20，直接加权平均不公平。但“第 1 名”“第 3 名”这种排名是量纲无关的，所以按排名融合最稳。

3. 公式与代码

每个文档的得分 = Σ 1/(k + 排名)，k 一般取 60 防止第一名权重过大。

function rrfFusion(rankLists, k=60){
  const merged = new Map();
  for(const list of rankLists){
    list.forEach((item, rank) => {
      const key = item.id;
      const cur = merged.get(key) || { score:0 };
      cur.score += 1/(k + rank + 1);   // 排名越靠前，贡献越大
      merged.set(key, cur);
    });
  }
  return [...merged.values()].sort((a,b)=>b.score-a.score);
}

4. 在 RAG 的位置

向量召回 Top-K ┐ BM25 召回 Top-K ┼─→ RRF 融合 ─→ 取 Top-5 ─→ 大模型精排 ─→ 生成

5. 常见坑

坑 1：直接把两路分数加权平均，结果被分数大的那路主导——用 RRF 而非加权。
坑 2：k 太小会让头部过强、尾部噪声；60 是经验值，可按效果微调。
坑 3：融合后要再让大模型精排，RRF 只是粗排。
