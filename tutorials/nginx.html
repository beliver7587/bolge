Nginx：从小白到反向代理

Nginx 是高性能 Web 服务器，也常作反向代理与负载均衡。它是把多个后端（Spring Boot、Node）统一暴露、加 HTTPS 的入口。本教程讲清反向代理、负载均衡与上线部署。

1. 它是什么

Nginx 事件驱动、高并发低内存，既能托管静态文件，也能把请求转发给后端服务（反向代理）。

一句话：Nginx = 静态托管 + 反向代理 + 负载均衡。部署的“门面”。

2. 起步

nginx -t            # 测试配置
nginx               # 启动
nginx -s reload     # 热重载配置

3. 静态托管

server {
  listen 80; server_name x.com;
  root /var/www; location / { try_files $uri $uri/ /index.html; }
}

try_files 让前端路由（SPA）刷新不 404。

4. 反向代理

location /api/ {
  proxy_pass http://127.0.0.1:3000/;
  proxy_set_header Host $host;
}
用法：浏览器只访问 Nginx，Nginx 把 /api 转给后端，隐藏真实端口与拓扑。

5. 负载均衡

upstream api { server 127.0.0.1:3000; server 127.0.0.1:3001; }
location /api/ { proxy_pass http://api/; }   # 默认轮询

可换 ip_hash 或 least_conn 策略。

6. HTTPS

listen 443 ssl;
ssl_certificate /path/fullchain.pem;
ssl_certificate_key /path/privkey.pem;

证书用 certbot 免费签发并自动续期。

7. 性能优化

  • gzip on 压缩文本。
  • expires 给静态资源加缓存头。
  • 开启 keepalive 复用后端连接。

8. 与部署

典型链路：域名 → Nginx（HTTPS + 反代） → 后端服务（Docker 容器，用 PM2 或 systemd 守护）。

9. 常见坑

坑 1 长连接超时：WebSocket/流式要配 proxy_read_timeout 与 Upgrade 头，否则被断。
坑 2 403 权限：root 目录的读权限与 SELinux/用户要对。
坑 3 配置错未测：改完先 nginx -t 再 reload，避免全站挂。

完整流程：Nginx 反向代理与静态托管

1. 安装
sudo apt install nginx
# 或 docker run -p 80:80 nginx
2. 配置反向代理
server {
  listen 80;
  server_name api.example.com;
  location / {
    proxy_pass http://localhost:3000;
    proxy_set_header Host $host;
  }
}
3. 静态文件与负载均衡
location / { root /var/www/html; try_files $uri $uri/ /index.html; }
upstream backend { server 127.0.0.1:3000; server 127.0.0.1:3001; }
要点：改配置后 nginx -s reload；日志可配 access_log / error_log。
