BM25

经典的关键词相关性算法 —— 搜“怎么退款”能精准命中含“退款”的文档。它是 RAG 混合检索里的关键词主力。学完你能实现靠谱的关键词搜索。

1. 这是什么

BM25 是搜索引擎同款的相关性打分算法，根据“关键词在文档中出现频率、文档长度、词稀有度”给文档打分排序。

对比：向量检索 看语义（意思像）；BM25 看字面（词命中）。两者互补。

2. 核心思想

  • 词频：某词在文档出现越多，越相关（但会饱和，不是越多越好）。
  • 逆文档频率：越罕见的词（如“退款”）权重越高，常见词（如“的”）权重低。
  • 长度归一：长文档天然词多，做惩罚避免长文占便宜。

3. 快速使用

Node 用现成库：

npm install flexsearch   # 或 lunr / minisearch
import { Index } from 'flexsearch';
const idx = new Index({ tokenize: 'forward' });
docs.forEach((d, i) => idx.add(i, d.text));
const hits = idx.search('退款流程');   // 返回命中文档 id

4. 原理简述

score(D, q) = Σ IDF(qi) · (f · (k+1)) / (f + k·(1 - b + b·|D|/avgDL)) f: 词在文档 D 的频率 |D|: 文档长度 avgDL: 平均长度 k,b: 调参（常 k=1.5, b=0.75）

5. 与向量检索

在 RAG 里，BM25 负责“精确关键词命中”，向量负责“语义相近”。两者结果用 RRF 融合，效果比单用任一种更好。

经验：混合检索（BM25 + 向量 + RRF）是生产级 RAG 的标配。

6. 常见坑

坑 1：中文不分词直接搜，命中率极低；要用中文分词（jieba 等）或选支持中文的引擎。
坑 2：没做停用词/小写归一，无关词干扰排序。
坑 3：只靠 BM25 做语义搜索会漏“同义不同词”；必须配向量。
坑 4：大文档集每次全量建索引慢；增量更新索引。

7. 下一步

  1. 给知识库加一个关键词搜索。
  2. 学 向量检索 与 RRF 做混合。
  3. 学 RAG 整体闭环。
  4. 看 Memora，BM25 在检索链路中的角色。
毕业：能用一个 BM25 库实现关键词搜索——检索系统的关键词半边你已掌握。
