Express：从小白到资深后端

Express 是 Node.js 最经典的 Web 框架，用“中间件 + 路由”模型把原生 http 的啰嗦封装掉。本教程讲透洋葱模型、Router 模块化、集中错误处理、安全加固、测试与框架选型——这是资深 Node 后端写生产 API 的范式。

1. 它解决什么问题

原生 http 要手动解析 URL、路由、请求体，写接口很啰嗦。Express 提供声明式路由（app.get('/x')）和中间件管线，让横切逻辑（日志、鉴权、错误处理）可插拔复用。

一句话：Express = 路由 + 中间件。你写“对每个请求做什么”的函数链，框架负责按顺序跑。
适合：REST API、BFF、中小型后端；生态成熟、文档多。
不适合：追求极致吞吐或强约束架构（看第 10 节 Fastify/NestJS）。

2. 工程化起步

mkdir my-api && cd my-api
npm init -y && npm pkg set type=module
npm install express

真实项目按职责分层：routes/、controllers/、services/、middlewares/、validators/。配 TypeScript 加类型更安全（Express 类型用 @types/express）。

3. 路由深入

import express from 'express';
const router = express.Router();
router.get('/:id', (req, res) => res.json({ id: req.params.id }));
// 路由级中间件：只对该路由生效
router.use(authenticate);          // 该 router 下所有请求先鉴权
app.use('/users', router);         // 挂载到 /users 前缀
  • Router 模块化：每个业务一个 router，主应用 app.use('/x', router) 挂载，避免单文件膨胀。
  • 404 用“兜底路由”在最后注册：app.use((req,res)=>res.status(404).json({error:'not found'}))。

4. 中间件机制

中间件是 (req, res, next) => {}。核心是洋葱模型：请求从外到内穿过各中间件，响应再从内到外返回。

app.use((req, res, next) => {           // 进入
  console.log(req.method, req.url);
  next();                                // 放行；不调 next 则请求挂起
});
  • 应用级 app.use 全局；路由级 挂在 router；错误级 四参 (err,req,res,next) 必须在最后。
  • 顺序即一切：express.json() 要在读取 req.body 的路由之前；鉴权中间件要在受保护路由之前。

5. 请求处理

app.use(express.json({ limit: '1mb' }));          // 解析 JSON 体，限大小防滥用
import { body, validationResult } from 'express-validator';
app.post('/users', body('email').isEmail(), (req, res) => {
  const errs = validationResult(req);
  if (!errs.isEmpty()) return res.status(400).json({ errors: errs.array() });
  // 业务...
});
  • 文件上传用 multer；大文件走流而非缓冲进内存。
  • 校验放中间件层，别散在控制器里。

6. 错误处理

app.use((err, req, res, next) => {           // 四参错误中间件，必须最后
  console.error(err);
  res.status(err.status || 500).json({ error: err.message });
});
  • 异步路由里抛错不会自动进错误中间件——用 try/catch 包后 next(err)，或用 express-async-errors 让 async 错误自动冒泡。
  • 统一错误结构（{error, code}），前端才好处理。

7. 安全加固

  • helmet：设安全响应头（CSP、XSS 防护等）。
  • cors：精确配置允许的来源，别 * 全开。
  • 限流 express-rate-limit：防爆破/刷接口。
  • 校验 + 参数化查询防注入；密钥走环境变量。

8. 性能与部署

  • Express 中间件串行、同步为主，吞吐低于 Fastify；但多数 I/O 场景够用。
  • 用 PM2 或 cluster 起多进程吃满多核；前置 Nginx 做反向代理/TLS/静态。
  • 用 compression 开 gzip 减响应体积。

9. 测试

import request from 'supertest';
import app from '../app.js';
test('GET /users 返回 200', async () => {
  const r = await request(app).get('/users');
  expect(r.status).toBe(200);
});

10. 框架对比

ExpressKoaFastifyNestJS
风格中间件洋葱/async高性能装饰器/DI
约束自由自由自由强（架构）
吞吐中中高中
选型：快速灵活 → Express；极致性能 → Fastify；大企业级强架构 → NestJS。

11. 常见坑

坑 1：忘了 express.json() → req.body 为 undefined。
坑 2：中间件漏调 next() → 请求挂起超时。
坑 3：中间件顺序错（如鉴权在路由后）→ 保护失效。
坑 4：跨域被拦 → 配 cors 并限制来源。
坑 5：异步错误没冒泡 → 用 async-errors 或 try/catch+next(err)。
坑 6：对同一 res 多次 send/json → 抛 "headers already sent"。

12. 调试

  • DEBUG=express:* 看路由匹配；morgan 记录请求日志。
  • 用 node --inspect 断点；Postman/curl 联调。

练习：① 用 Router 把用户/订单拆模块 ② 写集中错误中间件并处理 async 错误 ③ 加 helmet+cors+限流 ④ 用 supertest 测一个接口 ⑤ 对比 Fastify 写同一接口测吞吐。
你已进阶：理解中间件洋葱模型与分层架构，能写出安全、可测、可维护的生产 API——这是资深 Node 后端的核心能力。
