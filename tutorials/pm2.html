PM2：从小白到资深

PM2 是 Node.js 的进程管理器——后台常驻、崩溃自启、多进程利用多核、看日志。本教程讲透进程/集群管理、日志轮转、零停机重启、env 管理、开机自启，以及与 systemd 的取舍——让 Node 服务在生产稳稳长跑。

1. 它解决什么问题

直接 node server.js 关终端就停、崩了没人拉、单进程吃不满多核。PM2 用守护进程包住你的应用，统一管生命周期。

对比：systemd 是系统级、语言无关；PM2 专为 Node 设计、命令更友好、自带集群与日志面板。

2. 进程管理

npm i -g pm2
pm2 start server.js --name my-api
pm2 start server.js -i 1 --watch        # 开发期文件变更自动重启
pm2 list            # 所有进程
pm2 logs my-api     # 看日志（带时间戳）
pm2 restart my-api / stop / delete
ecosystem 文件：用 ecosystem.config.js 声明多应用、env、args，版本化管理进程定义。

3. 集群模式

Node 单进程只用一核；集群模式 fork 多实例由 PM2 做负载均衡，吃满多核（无需改代码，共享端口）：

pm2 start server.js -i max      # 按 CPU 核数起进程
pm2 scale my-api 4              # 动态扩到 4 个实例
注意：有状态/单例资源（如内存缓存、文件锁）在集群下需外部化（Redis/数据库），否则多实例不一致。

4. 日志与轮转

  • 日志默认落 ~/.pm2/logs，会无限增长撑满磁盘——必须装轮转：
pm2 install pm2-logrotate       # 按大小/时间切割、保留 N 份

5. 零停机与部署

pm2 reload my-api     # 逐个重启实例，保持服务可用（零停机）
pm2 deploy ecosystem.config.js production   # 内置 SSH 拉代码+重启的部署流程
restart vs reload：restart 会瞬间全停再起（短暂不可用）；reload 滚动替换，生产用 reload。

6. 环境变量

// ecosystem.config.js
module.exports = { apps: [{ name:'my-api', script:'server.js',
  env: { NODE_ENV:'development' },
  env_production: { NODE_ENV:'production', PORT:3010 } }] };
pm2 start ecosystem.config.js --env production
密钥：JWT_SECRET 等走环境变量/Systemd EnvironmentFile，绝不硬编码（见 JWT）。

7. 开机自启

pm2 save          # 保存当前进程列表
pm2 startup       # 生成开机脚本（按提示执行；底层常写 systemd unit）
顺序：先 save 再 startup；否则重启后列表为空。

8. 与 systemd 取舍

PM2systemd
语言Node 专属语言无关
集群内置 -i需多 unit
日志自带面板journalctl
适用纯 Node 快速部署系统级/混合栈

9. 常见坑

坑 1：忘 pm2 save → 重启后进程没起来。
坑 2：日志无限增长占满磁盘 → 装 logrotate。
坑 3：端口被旧进程占 → 先 delete 再起。
坑 4：全局 pm2 在 sudo 下找不到 → 用 npm root -g 路径或软链。
坑 5：集群下内存态不一致 → 状态外置。

10. 成长路线

阶段能力标志
小白能 start/stop/list，后台跑服务
初级集群 -i、日志轮转、env 管理
中级零停机 reload、ecosystem 部署
资深与 systemd/容器取舍、可观测集成
练习：① 用 ecosystem 定义应用 ② 集群 -i max 起服务 ③ 装 logrotate ④ reload 零停机 ⑤ save+startup 开机自启 ⑥ 把密钥移进 env_production。
你已进阶：理解进程生命周期管理与零停机发布，能把 Node 服务在生产稳定长跑并多核扩容——这是资深后端部署 Node 的标配。
