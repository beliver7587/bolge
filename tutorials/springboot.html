Spring Boot：从小白到资深后端

Spring Boot 是 Java 企业级后端的事实标准：内嵌服务器、自动配置、起步依赖，几分钟内搭出生产级 API 服务。本教程从“能写接口”讲到“IoC 容器原理、事务边界、安全、性能调优、测试体系与可观测性”——这是资深 Java 工程师的护城河。

1. 它解决什么问题

传统 JavaEE/Spring 要写大量 XML、单独装 Tomcat、手动配 Bean，启动一个项目成本高。Spring Boot 用“约定优于配置”：引入依赖即自动装配、内嵌服务器一条命令跑起。

一句话：Spring Boot 让你用最少的配置，获得一个自带容器、可独立运行、生产就绪的 Spring 应用。
适合：企业后端、微服务、中台、简历工坊这类需要稳定与生态的项目。
不适合：极轻量脚本（用 Bun/Node 更省）、对启动内存敏感的边缘场景。

2. 工程化起步

  • JDK：Spring Boot 3 要求 Java 17+（推荐 21 LTS）。
  • 构建工具：Maven（普及）或 Gradle。装好 mvn -v 验证。
  • 创建：用 start.spring.io 勾选依赖（Spring Web、Data JPA、MySQL Driver、Validation、Actuator 等）生成骨架。
// 启动类：@SpringBootApplication = @Configuration + @EnableAutoConfiguration + @ComponentScan
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

3. 核心原理

  • IoC / DI：控制反转容器管理对象（Bean）的创建与依赖注入。你声明“我需要什么”，容器负责装配——解耦、可测、可替换。
  • 自动配置：@EnableAutoConfiguration 按 classpath 上的 jar 自动配好 DataSource、WebMvc 等；靠条件装配（@ConditionalOnClass 等）决定装不装。
  • Starter：spring-boot-starter-web 把 web 全家桶打包成一个依赖，无需逐个引。
  • Bean 生命周期：实例化 → 属性填充 → @PostConstruct → 就绪 → @PreDestroy。构造注入优于字段注入（不可变、易测、循环依赖早暴露）。
@Component
public class UserService {
    private final UserRepository repo;          // 构造注入（推荐）
    public UserService(UserRepository repo) { this.repo = repo; }
}

4. 分层架构

标准三层 + 防腐层：

  • Controller：接 HTTP、参数校验、调用 Service、组装响应。
  • Service：业务逻辑核心，事务边界所在。
  • Repository：数据访问，对上层屏蔽存储细节。
  • DTO / Entity 分离：对外用 DTO，持久化用 Entity，避免把数据库结构直接暴露给前端。
资深：依赖倒置——Service 依赖 Repository 的接口而非实现，便于测试时用内存实现替换。

5. Web 层

@RestController
@RequestMapping("/users")
public class UserController {
    private final UserService service;
    public UserController(UserService s) { this.service = s; }

    @PostMapping
    public ResponseEntity<UserDTO> create(@Valid @RequestBody CreateUserReq req) {
        return ResponseEntity.ok(service.create(req));
    }
}
  • @Valid：用注解（@NotBlank/@Email）声明参数约束，非法请求自动 400。
  • 统一响应 & 异常处理：用 @ControllerAdvice + @ExceptionHandler 把业务异常转成统一 JSON 结构，别在每个接口里 try-catch。
  • 拦截器/过滤器：鉴权、日志、跨域在 HandlerInterceptor 或 Filter 统一处理。

6. 数据访问与事务

@Service
public class TransferService {
    @Transactional                       // 事务边界：方法内全部成功或回滚
    public void transfer(Long from, Long to, BigDecimal amount) {
        accountRepo.debit(from, amount);
        accountRepo.credit(to, amount);
    }
}
  • ORM 选型：JPA/Hibernate 开发快、跨库；MyBatis-Plus SQL 可控、适合复杂查询。简历工坊用后者。
  • 连接池：默认 HikariCP，配置 maximum-pool-size 控制并发数据库连接。
  • 事务失效：自调用（同类内方法互调）、非 public、异常被吞都会导致 @Transactional 不生效（见第 13 节）。

7. 配置与多环境

# application.yml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/demo?useSSL=false&serverTimezone=UTC
    username: ${DB_USER}
    password: ${DB_PWD}
---
spring:
  config:
    activate:
      on-profile: prod   # 生产环境专用配置
  • 外部化配置：敏感信息用环境变量/配置中心（如 Nacos），别硬编码进仓库。
  • @ConfigurationProperties：把一组配置绑定成类型安全的对象，优于零散 @Value。

8. 安全

  • Spring Security：认证（你是谁）+ 授权（能做什么），默认表单登录可换成 JWT。
  • JWT：登录发 token，后续请求带 Authorization 头，过滤器校验（详见 JWT）。
  • 密码用 BCryptPasswordEncoder 加盐哈希，绝不存明文。
  • 防 CSRF / 越权：对资源做“是否属于当前用户”的归属校验，不能只靠前端隐藏按钮。

9. 性能优化

  • 连接池：按数据库承载与并发调 maximum-pool-size，过大反而拖垮 DB。
  • 缓存：@Cacheable + Redis 挡热点；注意缓存穿透/击穿/雪崩。
  • 异步：@Async 把非关键路径（发邮件、写日志）丢到线程池。
  • N+1：ORM 懒加载导致一查列表发 N 条 SQL，用 fetch join/批量抓取解决。
  • JVM 调优：按容器内存设 -Xmx，选 G1/ZGC 降低停顿。

10. 测试

  • 单元测试：JUnit 5 + Mockito，mock 掉 Repository 测 Service 逻辑。
  • Web 层测试：@WebMvcTest + MockMvc 测 Controller 而不起全容器。
  • 集成测试：@SpringBootTest 起完整上下文；用 Testcontainers 起真实 MySQL/Redis 容器，测试最接近生产。
  • 测试覆盖率 + CI 门禁，是资深团队的硬指标。

11. 可观测性

  • Actuator：暴露 /health、/metrics、/env 等端点，配合 Prometheus/Grafana。
  • 日志：用 SLF4J + Logback，按环境调级别；敏感字段别打进日志。
  • 链路追踪：Micrometer Tracing 接 Zipkin，定位跨服务慢调用。

12. 部署运维

mvn clean package -DskipTests      # 打出可执行 jar
java -jar demo.jar --spring.profiles.active=prod
  • 用 Docker 打成镜像，配合 Nginx 反向代理。
  • 进程守护用 PM2（Node）/systemd（见运维篇）或 K8s。

13. 常见坑

坑 1：事务自调用失效——同类方法互调绕过代理，@Transactional 不生效；拆到另一个 Bean 或用 AOP 代理调用。
坑 2：字段注入（@Autowired 字段）导致循环依赖、难测试；改构造注入。
坑 3：Bean 未扫描到——启动类包路径要覆盖 Controller/Service，否则 NoSuchBean。
坑 4：ORM N+1 拖垮列表接口；用 fetch join/批量。
坑 5：配置被覆盖——外部环境变量优先级高于 yml，排查“为什么配置不生效”先看生效来源。
坑 6：内存泄漏——未关闭的流/连接池/ThreadLocal，容器重启才恢复；用 MAT 分析堆转储。

14. 调试

  • IDEA 断点调试；/actuator/beans 看容器里有哪些 Bean。
  • 启动时加 --debug 看自动配置命中/未命中原因。
  • 慢接口用 APM 或日志打耗时定位。

15. 成长路线

阶段能力标志
小白能建项目、写 CRUD 接口
初级分层清晰、会用 JPA/MyBatis、基本事务
中级懂 IoC/自动配置、事务边界、安全、缓存
资深性能调优、测试体系、可观测、复杂架构设计
练习：① 用 start.spring.io 搭一个带校验的用户接口 ② 用 @ControllerAdvice 做统一异常处理 ③ 写 @Transactional 转账并故意自调用看失效 ④ 用 Testcontainers 跑一个集成测试 ⑤ 加 Actuator 并接 Prometheus。
你已进阶：理解 IoC 容器与自动配置的运作、能设计分层与事务边界、掌握安全/性能/测试/可观测——这是资深 Java 后端的全栈能力。
