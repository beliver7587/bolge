Function Calling：从小白到工具调用

Function Calling（函数调用/工具调用）让 大模型 输出“要调用哪个函数 + 什么参数”，由你执行真实操作。它是 Agent 能“办事”的关键。本教程讲清流程、工具定义与安全执行。

1. 它是什么

LLM 本身不能查数据库、发短信。Function Calling 让它“决定”调用你的函数，并填好参数；你执行后再把结果喂回模型。

一句话：Function Calling = LLM 生成“调用计划”，你来执行真动作。AI 从“只会说”变“能办事”。

2. 工作流程

1) 你给模型工具清单（函数名+参数 schema）
2) 模型返回：调用 getWeather({city:'北京'})
3) 你执行函数，拿到结果
4) 把结果作为新消息回传模型 → 模型组织自然语言回答
闭环：模型定“做什么”，你做“怎么做”，结果再交回模型“怎么说”。

3. 工具定义

tools: [{
  type:'function',
  function: { name:'getWeather', description:'查天气',
    parameters: { type:'object', properties:{ city:{type:'string'} }, required:['city'] } }
}]

清晰的描述与参数 schema 决定模型调得准不准——这是提示工程的一部分。

4. 与 Agent

Agent 的“工具箱”就是一组 Function Calling；多步规划 + 多次工具调用 + 记忆，构成能自主完成任务的智能体（见 Agent）。

5. 常见坑

坑 1 参数不可信：模型填的参数要先校验（类型/范围/权限）再执行，别直接进 SQL/系统命令。
坑 2 无限循环：模型反复调工具不收敛，要设最大步数。
坑 3 越权：工具要最小权限，避免模型借工具做危险操作（见 提示注入）。

6. 资源与路线

  1. OpenAI Function Calling 文档、LangChain Tools。
  2. 配合 LLM、Agent。
  3. 练：给模型加一个“查天气”函数，完整跑通调用闭环。
资深标志：能给模型设计“干净且受约束”的工具集，做好参数校验与权限边界，让 Agent 既强大又安全。
