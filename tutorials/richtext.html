富文本编辑 / PDF 导出：从小白到资深前端

富文本编辑器是前端最复杂的组件之一（简历工坊的核心）。本教程讲清为什么不能裸用 contenteditable、文档模型与 Schema、序列化与安全、PDF 导出——这是资深做“所见即所得”系统的硬骨头。

1. 它解决什么问题

contenteditable 原生可编辑，但光标、撤销、跨浏览器差异、结构化数据全是坑。要“所见即所得 + 可存可导出”，必须用成熟的编辑器框架把“文档模型”和“视图”分离。

一句话：富文本编辑 = 把用户输入映射成结构化文档模型，再渲染成视图并支持编辑、序列化、导出。直接操作 DOM 字符串是错误的起点。

2. 工程化起步

'use client';
import { useEditor, EditorContent } from '@tiptap/react';
import StarterKit from '@tiptap/starter-kit';

const editor = useEditor({ extensions: [StarterKit], content: '<p>你好</p>' });
return <EditorContent editor={editor} />;

TipTap（基于 ProseMirror）是当前最易上手的方案，API 友好、扩展多。

3. 核心概念

  • 文档模型（Schema）：定义“文档由哪些节点（paragraph/heading/text）组成、能嵌套什么”，是编辑器正确性的根基。
  • Selection：光标/选区位置，是编辑操作的核心坐标。
  • 命令（Command）：editor.chain().toggleBold().run() 这类原子操作，保证模型一致。
  • 受控分离：编辑器内部维护文档状态，UI 只是投影——不要试图用 React state 直接驱动每个字符。

4. 方案对比

方案特点适合
ProseMirror最严谨的 Schema/插件体系，底层要深度定制的大型编辑器
TipTap基于 PM 的友好封装，扩展生态好大多数业务（含简历）
Slate纯 React、文档即 JSON、灵活React 重度定制
LexicalMeta 出品，性能与可扩展新秀新项目、追求性能

5. 编辑器架构

  • 状态/视图分离：文档模型是真理源，视图（DOM）由它渲染；编辑产生“事务”改模型，再投影。
  • 扩展/插件：加粗、列表、表格、图片都是“扩展”，按需拼装，避免臃肿。
  • 撤销/重做：框架内置历史栈（基于事务），别自己存字符串快照。

6. 序列化与安全

  • 存储格式：优先存 JSON（结构化、可校验、可 diff），需要展示时再转 HTML；纯 HTML 易带入杂乱/恶意标签。
  • XSS 防护：渲染存储的 HTML 前必须净化（DOMPurify），尤其用户可粘贴外部内容。千万别直接 dangerouslySetInnerHTML。
  • 粘贴净化：粘贴 Word/网页会带垃圾样式与脚本，要在 paste 事件里清洗。

7. 简历工坊实战

简历工坊的链路是：富文本编辑 → 存 JSON → 实时预览 → 一键导出 PDF。关键是编辑态与导出态共用同一份内容模型，保证“所见即所得”。

8. 导出 PDF

import html2pdf from 'html2pdf.js';
const opt = { margin: 0, filename: 'resume.pdf', html2canvas: { scale: 2 }, jsPDF: { unit: 'mm', format: 'a4' } };
html2pdf().set(opt).from(element).save();
  • 中文/字体：确保字体已加载再导出，否则空白；可用 document.fonts.ready 等待。
  • 分页：A4 高度约 297mm，长内容要处理分页避免截断（css break-inside: avoid）。
  • 清晰度：html2canvas scale: 2 提高导出清晰度。

9. 性能

  • 大文档考虑虚拟滚动或分块渲染。
  • 频繁操作（如输入）走框架的事务批处理，别每键重建视图。
  • 导出 PDF 用离屏渲染，避免卡住编辑界面。

10. 常见坑

坑 1：裸用 contenteditable + 存 innerHTML → 光标乱、跨浏览器不一致、XSS。
坑 2：渲染用户 HTML 不净化 → XSS（粘贴脚本执行）。
坑 3：用 React state 强控每个字符 → 光标跳、性能崩。交给编辑器内部状态。
坑 4：PDF 导出中文空白 → 字体没等加载完。
坑 5：长简历导出截断 → 没处理分页。

11. 调试

  • TipTap 有官方调试扩展看文档 JSON；浏览器看 contenteditable 结构。
  • 导出异常先 document.fonts.ready 排查字体。

练习：① 用 TipTap 做一个带加粗/列表的编辑器 ② 把内容存 JSON 并净化后再渲染 ③ 实现“导出 PDF”并处理中文与分页 ④ 处理粘贴 Word 内容净化。
你已进阶：理解“文档模型为真理源”的编辑器哲学，能做出安全、可导出、可维护的所见即所得系统——这是资深前端的高难领域。
