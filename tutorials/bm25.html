BM25：从小白到全文检索

BM25 是经典的全文检索打分算法，衡量“查询词与文档的相关度”。它是 RAG 混合检索的关键一路，擅长精确词面匹配（如专有名词）。本教程讲清原理、与向量检索的互补，以及落地用法。

1. 它是什么

BM25 基于 TF-IDF 改进：词在文档出现越多越相关（TF），但越常见的词权重越低（IDF），并对长文档做归一。

一句话：BM25 = 关键词相关度打分。词面匹配强，专治“精确词/专有名词”。

2. 原理

score(D,Q) = Σ IDF(qi) · (f(qi,D)·(k+1)) / (f(qi,D)+k·(1-b+b·|D|/avg))
// IDF 抑制常见词，k/b 是调节参数
  • TF：词频，但饱和（出现再多边际递减）。
  • IDF：越罕见词越重要。
  • 长度归一：长文档不过分占优（b 控制）。

3. 与向量检索

BM25向量检索
匹配词面（关键词）语义（同义/改写）
强项精确词、专有名词口语化、语义相近
弱项不懂同义精确词略弱
互补：两者融合（见 RRF）效果最好。

4. 用法

// 用 Elasticsearch / OpenSearch / whoosh / bm25s
const hits = index.search("React 缓存策略");

中文要先分词（jieba 等），再建倒排索引。

5. 与 RAG

在 RAG 中，BM25 负责“词面召回”，与向量“语义召回”互补，再用 RRF 融合，提升整体召回率。

6. 常见坑

坑 1 不分词：中文整句建索引，召回极差；必须分词。
坑 2 停用词：“的/是”等要过滤，否则噪声大。
坑 3 只靠 BM25：语义改写查不到，需混合向量。

7. 资源与路线

  2. 配合 RAG、Embedding。
