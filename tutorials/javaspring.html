Java Spring：从小白到企业级框架

Spring 是 Java 企业级框架家族的总称（含 Spring Boot），核心是 IoC/DI 与 AOP。本教程讲清它的“为什么这样设计”、模块生态，以及和 Spring Boot 的关系——这是理解 Java 后端的地基。

1. 它是什么

Spring 提供了一整套企业开发基础设施：依赖注入、事务、安全、数据访问、Web MVC。Spring Boot 是它“开箱即用”的发行版。

一句话：Spring = Java 企业级开发的“标准底座”；Spring Boot = 它的零配置版本。

2. 核心：IoC/DI

IoC（控制反转）：对象的创建不再由你 new，而是交给 Spring 容器。DI（依赖注入）：容器把依赖“注入”进来。

@Service
public class OrderService {
  private final PaymentClient pay;        // 依赖
  public OrderService(PaymentClient pay) { this.pay = pay; }  // 构造注入
}
价值：解耦、易测、生命周期由容器管理。这是 Spring 一切的基础。

3. AOP 切面

AOP（面向切面编程）把“横切关注点”（日志、事务、权限）从业务里抽出来，集中到切面：

@Aspect
@Component
public class LogAspect {
  @Around("execution(* com.x.service..*(..))")
  public Object log(ProceedingJoinPoint p) throws Throwable {
    long t = System.nanoTime();
    Object r = p.proceed();
    log.info("{} 耗时 {}ms", p.getSignature(), (System.nanoTime()-t)/1e6);
    return r;
  }
}
资深：日志/监控/权限用 AOP 统一织入，业务代码保持干净。

4. 模块家族

  • Spring MVC：Web 层（Controller/视图）。
  • Spring Data：统一数据访问（JPA、JDBC）。
  • Spring Security：认证授权（见 Spring Boot 安全）。
  • Spring Cloud：微服务（网关、注册中心、配置中心）。

5. 与 Boot 关系

传统 Spring 要配 XML/大量 bean；Spring Boot 用自动配置 + starter 把这些“隐藏”起来。日常开发 90% 时间用的是 Boot，但理解底层 Spring 才能在出问题时定位。

6. 事务

@Transactional
public void transfer(Long from, Long to, BigDecimal amt) {
  // 两个更新要么都成功，要么都回滚
}
坑：自调用（同类内方法调带 @Transactional 的方法）事务不生效——代理没介入。

7. 配置方式

早期 XML，现多用 Java Config + 注解；多环境用 profile。敏感配置走配置中心/环境变量。

8. 常见坑

坑 1 循环依赖：两个 Bean 互注，启动失败；重构或 @Lazy。
坑 2 事务自调用：见第 6 节。
坑 3 误用单例可变状态：Controller/Service 默认单例，存可变字段会线程不安全。

9. 学习路线

  1. 先学 Java 基础（面向对象、集合、泛型）。
  2. 再学 Spring Boot 直接上手（见 Spring Boot）。
  3. 最后回头理解 IoC/AOP 原理与事务边界。
资深标志：能说清“容器如何装配 Bean、代理如何实现 AOP/事务”，在调优与排查 Spring 故障时不被黑盒难住。
