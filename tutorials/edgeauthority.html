端侧权威运算

把“谁说了算”放在客户端/边缘侧的架构思想 —— 让玩家的设备本地算物理/碰撞，服务器只做校验与同步，降低延迟、提升手感。联机游戏常用。学完你能理解游戏网络架构。

1. 这是什么

端侧权威（Client/Edge Authority） 指游戏的关键运算（移动、碰撞、物理）由客户端（玩家设备）或边缘节点直接计算，而不是全交服务器。

对比：服务器权威：所有逻辑在服务器算，客户端只发输入；最防作弊但延迟高、手感钝。端侧权威：本地即算即现，顺滑但需防作弊。

2. 为什么需要

  • 低延迟手感：本地立即响应，不用等服务器往返（RTT）。
  • 省服务器算力：大量客户端各自算，服务器只校验。
  • 弱网友好：先本地跑，网络差也不卡。

3. 基本模式

玩家输入 → 客户端立即本地模拟（移动/碰撞） │ ├─ 本地直接渲染（顺滑） │ └─ 把“输入 + 结果摘要”发给服务器 → 服务器校验/对账 → 有争议以服务器为准广播

4. 与服务器对账

端侧权威不能“完全信客户端”（会作弊），所以要：

  • 服务器定期用确定性算法重算，发现偏差就纠正/踢人。
  • 关键结果（如击杀、得分）由服务器最终裁定。
  • 用固定步长（deterministic tick）保证两端算出来一致。

5. 实战：联机判定

玩家本地用 AABB 算出“我打中了敌人”，把事件上报；服务器用相同规则复核，确认命中才扣血并广播。这样既顺滑又难作弊。

6. 常见坑

坑 1：完全信任客户端，外挂横行；必须有服务器对账。
坑 2：浮点/帧率不一致导致两端结果不同；用固定步长与整数/定点运算。
坑 3：只端侧不算最终状态，断网后状态分歧；服务器持有“真值”并定期同步。
坑 4：本地预测与服务器纠正打架，画面“回弹”；用平滑插值缓解释放。

7. 下一步

  1. 用 AABB + 本地预测做一个单机判定。
  2. 学 Socket.IO / WebSocket 做联机同步。
  3. 了解服务器权威与反作弊。
  4. 看网页游戏平台，端侧权威实现。
毕业：能区分端侧/服务器权威、用本地预测+服务器对账做联机——游戏网络架构你已入门。
