Embedding：从小白到向量嵌入

Embedding（向量嵌入）把文字变成高维向量，语义相近的向量也相近。它是 RAG、语义搜索、推荐的基础。Memora 用它对知识分块建索引。本教程讲清“为什么需要 embedding、怎么用、存哪”。

1. 它是什么

Embedding 是神经网络把文本/图片映射成的稠密向量（如 1536 维）。向量间的距离 = 语义距离。

一句话：Embedding = 把“意思”编码成“一串数字”。相似的意思，数字也接近。

2. 向量是什么

embedding("苹果手机") ≈ [0.12, -0.03, ..., 0.88]   // 1536 维
embedding("iPhone")    ≈ [0.11, -0.02, ..., 0.85]   // 接近上面

传统关键词检索只认字面；向量检索认语义——“苹果手机”和“iPhone”能匹配。

3. 怎么得到

// 调模型服务（OpenAI / 通义 / 本地 bge 等）
const vec = await embedModel.embed("用户的问题");
// 批量给文档分块向量化后入库
坑：检索与入库必须用同一个模型，否则向量空间不一致，匹配全错。

4. 相似度

常用余弦相似度（夹角越小越相似）或点积。查询向量与库里每个向量算距离，取最近 Top-K。

score = cos(q, d) = (q·d) / (|q||d|)

6. 与 RAG

Embedding 是 RAG 的检索环节：先把知识切块向量化入向量库，用户提问时把问题向量化，取最相关块喂给 LLM 作答。

7. 常见坑

坑 1 模型不一致：见第 3 节。
坑 2 分块过大/过小：块太大噪声多，太小丢上下文；按语义断句 + 重叠窗口。
坑 3 中文分词：中文要先切词/按句，别整段塞，影响向量质量。

8. 资源与路线

  1. OpenAI Embeddings、HuggingFace bge 等开源模型。
  2. 接着学 RAG、BM25、LLM。
  3. 练：把一段文档切块向量化，用 FAISS 做语义检索 demo。
资深标志：能设计分块策略、选对向量库与距离度量，并理解“检索质量决定了 RAG 上限”。
