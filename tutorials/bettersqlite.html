better-sqlite3：从小白到嵌入式数据库

better-sqlite3 是 Node.js 上最快的 SQLite 库，同步 API 但底层用事务批量写，简单又高性能。它适合本地/嵌入式存储，是 MySQL 之外轻量级场景的好选择。本教程讲清它为什么用同步、以及和 MySQL 的取舍。

1. 它是什么

SQLite 是单文件嵌入式数据库；better-sqlite3 是它的 Node 绑定，主打同步、零回调、事务友好。

一句话：better-sqlite3 = 嵌入式 SQLite + 同步 API。小、快、零依赖服务。
适合：本地应用、CLI、原型、单实例小服务。不适合：高并发多写/需要网络访问的客户端（用 MySQL）。

2. 起步

npm i better-sqlite3
const Database = require('better-sqlite3');
const db = new Database('app.db');   // 一个文件就是一个库

3. 同步 API

const row = db.prepare('SELECT * FROM user WHERE id=?').get(1);
为什么同步还快：SQLite 本身毫秒级，同步反而免去异步开销；用事务批量写性能极高。

4. 增删改查

db.prepare('INSERT INTO user(name) VALUES(?)').run('王越');
const list = db.prepare('SELECT * FROM user').all();

5. 事务

const insertMany = db.transaction((rows) => {
  for (const r of rows) db.prepare('INSERT INTO user VALUES(?)').run(r);
});
insertMany([1,2,3]);   // 一个事务，原子且快
资深：批量写务必包事务，否则逐条 commit 极慢。

6. 预处理

prepare 编译一次、多次执行，防 SQL 注入又提性能。参数化查询（?）天然免疫注入。

7. 与 MySQL

better-sqlite3MySQL

并发写单进程内多连接

8. 常见坑

坑 1 文件锁：多进程同时写会锁，多实例场景慎用或加 WAL 模式。
坑 2 大库进仓库：.db 文件别提交 Git，加 .gitignore。
坑 3 同步阻塞：单次大查询会阻塞事件循环，拆小批量。
