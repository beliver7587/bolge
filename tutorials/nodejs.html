Node.js：从小白到资深后端

Node.js 是把 Chrome V8 引擎搬到服务器端的JavaScript 运行时。它不是框架，而是“让 JS 跑在服务端”的基础——事件驱动、非阻塞 I/O，天然适合高并发接口、网关与实时服务。本教程讲透事件循环、单线程模型、流与背压、多进程、健壮性与安全。

1. 它解决什么问题

传统服务端（如 Java 线程池）每个连接占一个线程，高并发下线程上下文切换开销大。Node 用单线程 + 事件循环 + 非阻塞 I/O：一个线程就能扛大量并发连接，特别适合 I/O 密集型（接口转发、文件/网络读写、实时推送）。

一句话：Node 让你用 JS 写服务端，并以“少量线程处理海量并发连接”的模型，在高 I/O 场景高效又省内存。
适合：API 网关、BFF、实时服务、CLI、前端构建工具。
不适合：CPU 密集型（如大量同步计算会阻塞事件循环）——这种用 Worker 或换语言。

2. 工程化起步

  • 装 LTS（推荐 20/22）：用 nvm 或 n 管理多版本。
  • 包管理：npm 自带；pnpm 省磁盘、严格依赖；yarn 经典。
  • package.json："type":"module" 开启 ESM（现代写法）。
node -v && npm -v
npm init -y && npm pkg set type=module

3. 事件循环原理

这是 Node 的心脏。核心要点：

  • 单线程执行 JS：你的代码在同一个线程跑，所以别写长时间同步计算会卡住所有人。
  • 事件循环阶段：timers → pending → poll（I/O 回调）→ check（setImmediate）→ close。每轮处理一批回调。
  • 微任务优先：Promise.then/process.nextTick 在阶段切换间清空，先于宏任务（setTimeout）。
  • 非阻塞 I/O：网络/文件请求交给 libuv 线程池，完成后回调入队，主线程继续跑别的——所以“单线程”并不等于“不能并发”。
坑底：在请求处理函数里跑重计算（如大循环、同步压缩），会阻塞事件循环，整台服务器的其他请求都变慢。CPU 活交给 Worker 或拆批。

4. 模块系统

  • ESM（import/export，推荐）：静态、可被 tree-shaking。
  • CommonJS（require/module.exports）：老生态仍多。
  • 互操作：ESM 里 import CJS 通常可行；CJS 里 require ESM 不行（ESM 是异步的）——这就是“双包危机”的痛点。
  • 内置模块用 node: 前缀（node:fs）更清晰、避免歧义。

5. 文件与流

import { createReadStream, createWriteStream } from 'node:fs';
// 流：边读边写，内存恒定，处理大文件/代理转发必备
createReadStream('big.iso').pipe(createWriteStream('out.iso'));
  • Stream：大文件别 readFile 全读进内存，用流分块；背压（backpressure） 自动让快的写端等慢的读端，防内存爆。
  • 小文件用 node:fs/promises 的异步 API 即可。

6. HTTP 服务

import http from 'node:http';
const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ msg: 'hello' }));
});
server.listen(3000);

原生 http 偏底层；实际用 Express/Fastify 等框架，提供路由与中间件模型（洋葱圈：请求依次穿过中间件，响应再反向穿过）。

7. 进程与性能

  • cluster：Node 单进程只用一核，用 cluster 或 PM2 起多个进程（每核一个）吃满多核。
  • worker_threads：同进程内多线程，做 CPU 密集任务（如加密、压缩）而不阻塞事件循环。
  • 内存：默认单进程约 2GB 上限，大对象/泄漏会 OOM；用 --max-old-space-size 调。

8. 健壮性与优雅关闭

process.on('unhandledRejection', (e) => { console.error(e); /* 别静默 */ });
process.on('SIGTERM', () => {
  server.close(() => process.exit(0));   // 先停收新请求，再退出
});
  • 漏掉 unhandledRejection 监听，未捕获 Promise 错误可能导致进程不稳定。
  • 优雅关闭：收到 SIGTERM（如 K8s 滚动发布）要停收新流量、跑完在途请求再退出，别直接杀。

9. 安全

  • 依赖供应链：npm audit 查漏洞；锁文件（package-lock）固定版本；用 SCA 工具。
  • 原型污染：别把用户输入直接 merge 进对象（__proto__ 攻击）；用安全深拷贝。
  • 密钥走环境变量 / 配置中心，绝不进仓库。

10. 测试

  • 单元/集成用 vitest 或 jest；HTTP 层用 supertest 测接口。
  • CI 跑 lint + test + audit 作为质量门。

11. 与 Bun/Deno

Node.jsBunDeno
定位生态最成熟更快、内置工具链安全默认、TS 原生
现状事实标准崛起中小众
选型：求稳、要生态 → Node；求极致启动/运行速度、现代工具链 → Bun（兼容大多数 npm 包）。

12. 常见坑

坑 1：ESM/CJS 混用报错 → 统一项目模块系统，CJS 里别 require ESM。
坑 2：事件循环被重计算阻塞 → 拆批或用 Worker。
坑 3：大文件用 readFileSync 占爆内存 → 改流。
坑 4：忘记 res.end() → 请求挂起超时。
坑 5：unhandledRejection 未监听 → 隐性崩溃。
坑 6：依赖漏洞不过审 → 定期 audit 与升级。

13. 调试

  • node --inspect 接 Chrome DevTools 断点调试。
  • clinic.js 做性能剖析（定位事件循环延迟、CPU 热点）。
  • 结构化日志（pino）配合日志平台。

14. 成长路线

阶段能力标志
小白能写脚本、起 HTTP 服务
初级会用框架、模块系统、异步
中级懂事件循环、流、cluster、健壮处理
资深性能调优、安全供应链、架构与排障
练习：① 用流复制一个大文件并观察内存恒定 ② 写一个阻塞事件循环的“坏接口”并用 clinic 定位 ③ 用 cluster 起 4 进程 ④ 实现 SIGTERM 优雅关闭 ⑤ 跑 npm audit 修一个漏洞。
你已进阶：理解单线程事件循环的本质与边界，能用流/集群/Worker 做出高并发且健壮的服务——这是资深 Node 后端的分水岭。
