BM25：从小白到资深

BM25 是搜索引擎同款的关键词相关性算法，按“词频饱和、词稀有度、文档长度”给文档打分。它是 RAG 混合检索里的关键词主力——精准命中“型号/订单号/专名”。本教程讲透公式原理、倒排索引、中文分词、调参、与向量混合及评估。

1. 它解决什么问题

向量检索看“语义相近”，但遇到“订单号、型号、专有名词”这类字面对才相关的查询会失灵。BM25 看“字面命中”，正好补位。

一句话：BM25 捕“词命中”（精确），向量捕“意思近”（语义）——生产 RAG 两者混合，缺一不可。

2. 工程化选型

  • 轻量：flexsearch / minisearch / lunr（浏览器/Node 内建索引）。
  • 内置：SQLite FTS5（一行 SQL 做全文检索，零额外服务）。
  • 大规模：Elasticsearch / OpenSearch（分布式、分词插件齐全）。

3. 核心公式

score(D, Q) = Σ IDF(qi) · (f · (k+1)) / (f + k·(1 - b + b·|D|/avgDL)) f: 词在文档 D 的频率（词频） |D|: 文档长度 avgDL: 语料平均长度 IDF(qi): 词稀有度（越罕见权重越高） k≈1.5 控制词频饱和，b≈0.75 控制长度惩罚
  • 词频饱和：出现 1 次和 10 次相关度差别大，但 100 次和 110 次几乎无差（不会无限涨）。
  • 长度归一：长文档天然词多，按 b 惩罚，避免长文占便宜。

4. 倒排索引

BM25 建立在倒排索引之上：记录“每个词 → 出现在哪些文档（posting list）及词频/位置”。查询时只取相关词的 posting list 求交并打分，极快。

  • 分词（tokenize）：把文本切成词项；英文按空格、中文需专门分词。
  • 词干/归并：run/running 归并，提升召回（按语言）。
  • 停用词：去掉“的/的”等无区分度词，省空间提速。

5. 中文分词

中文是头号坑：中文没有空格，直接按字符或大粒度切会严重掉命中。方案：① 用 jieba 等分词器按词切；② 或二元分词（bigram）保召回；③ 选自带中文支持的引擎（ES 的 ik 插件）。

6. 调参与解释

  • k1（默认 ~1.5）：越大词频越“不饱和”，长文档里多次命中更受重视。
  • b（默认 ~0.75）：越接近 1，长度惩罚越强，越抑制长文。
  • 多数场景用默认即可；极端长文档/短文本可调。

7. 与向量混合

在 RAG 里：向量路召回“语义近”，BM25 路召回“词命中”，两路分数量纲不同、不能直接相加——用 RRF 按排名融合，再上 rerank。这是生产标配。

8. 生产要点

  • 增量更新：文档增删要增量改索引，别每次全量重建（慢）。
  • 内存/磁盘：倒排索引随语料增长；大规模交给 ES 托管。
  • 字段加权：标题命中比正文命中更重要，可做字段级 BM25。

9. 评估

  • Precision@K / Recall@K：topK 里相关比例 / 覆盖多少相关项。
  • nDCG：考虑排名位置的指标，更适合排序质量。
  • 对比“纯向量”与“BM25+向量”：常能看到精确词查询显著提升。

10. 常见坑

坑 1：中文不分词直接搜 → 命中率极低。
坑 2：停用词/大小写未归一 → 无关词干扰排序。
坑 3：只靠 BM25 做语义搜索 → 漏同义不同词，必须配向量。
坑 4：每次全量重建索引 → 慢；用增量。
坑 5：把 BM25 分数和向量分数直接相加 → 量纲不同，应走 RRF。

11. 调试

  • 打印每个命中词的 IDF 与词频贡献，定位为何某文档排前/排后。
  • 看分词结果，确认中文是否被正确切词。
