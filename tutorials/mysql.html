MySQL：从小白到资深后端

MySQL 是最流行的开源关系型数据库（RDBMS），业务主数据的归宿。本教程讲透InnoDB 架构、事务隔离与 MVCC、索引 B+树原理、执行计划、锁与并发、分库分表与调优——这是资深后端必须啃下的硬骨头。

1. 它解决什么问题

关系型数据库用“表”组织结构化数据，靠 SQL 增删改查，并承诺 ACID。相比 Redis（内存键值、快但易失）或文档库，MySQL 适合需要一致性与持久化的业务主数据（订单、账户、用户）。

一句话：MySQL = 落盘的关系数据 + 事务一致性；Redis 做缓存加速，两者互补而非替代。

2. 工程化起步

docker run -d --name mysql -e MYSQL_ROOT_PASSWORD=123456 -p 3306:3306 mysql:8
mysql -h 127.0.0.1 -P 3306 -u root -p     # 连上进入 mysql> 提示符

客户端用 DBeaver/Navicat/TablePlus 图形化；生产用 8.x（默认 InnoDB、utf8mb4）。

3. InnoDB 架构

  • 缓冲池（Buffer Pool）：把磁盘页缓存到内存，读写先走内存，是性能核心。
  • WAL（写前日志）：修改先写 redo log（保证崩溃可恢复），再异步刷盘——这是“快且安全”的关键。
  • undo log：记录变更前状态，支撑事务回滚与 MVCC 快照读。

4. 事务与隔离

ACID：原子性、一致性、隔离性、持久性。隔离级别解决三类并发问题：

级别脏读不可重复读幻读
读未提交可能可能可能
读已提交 RC否可能可能
可重复读 RR（默认）否否基本否
串行化否否否
MVCC：通过 undo log + 版本链 + 一致性视图，让“读不阻塞写、写不阻塞读”——RR 下普通 SELECT 是快照读，不加锁。

5. 索引原理

InnoDB 用 B+树 索引：有序、矮胖、叶子串成链表，范围查询高效。

  • 聚簇索引：主键即数据本身（叶子存整行）；二级索引叶子存主键值 → 查非索引列要回表。
  • 覆盖索引：索引已含所需列，免回表，最快。
  • 最左前缀：联合索引 (a,b,c) 只能从 a 起命中；跳 a 则失效。
CREATE INDEX idx_name_age ON user(name, age);  -- 单独按 age 查用不上此索引
EXPLAIN SELECT name,age FROM user WHERE name='x';  -- 覆盖索引，Extra: Using index

6. 执行计划

用 EXPLAIN 看 SQL 怎么执行，重点字段：

  • type：const > ref > range > index > ALL（ALL 是全表扫描，要警惕）。
  • key：实际用到的索引；rows：估算扫描行数；Extra：是否 Using filesort/Using temporary（排序/临时表慢）。

7. 查询优化

  • 只查所需列，杜绝 SELECT *（利于覆盖索引、减 IO）。
  • 索引失效：列上套函数、隐式类型转换、LIKE '%x' 前模糊、OR 含非索引列。
  • 深分页：LIMIT 1000000,10 慢 → 用“游标/延迟游标”（WHERE id > last_id LIMIT 10）。
  • JOIN 用小表驱动大表，关联列要有索引。

8. 表与类型设计

  • 三大范式减少冗余，但过度范式会多表 JOIN——按查询取舍做适度反范式。
  • 类型选最贴合的（TINYINT 别用 BIGINT）；时间用 DATETIME/TIMESTAMP。
  • 字符集一律 utf8mb4（真 UTF-8，支持 emoji）。

9. 锁与并发

  • InnoDB 默认行锁，但靠索引命中；无索引的更新会升级为表锁。
  • 间隙锁（Gap Lock）：RR 下锁范围防幻读，也可能导致锁等待。
  • 死锁：两事务互相等锁；InnoDB 会检测并回滚代价小的一方——业务要设计固定加锁顺序。

10. 连接池

import mysql from 'mysql2/promise';
const pool = mysql.createPool({ host:'localhost', user:'root', password:'xxx', database:'demo', connectionLimit: 10 });
const [rows] = await pool.query('SELECT * FROM user WHERE id = ?', [1]);  // 参数化防注入
防注入：永远用参数化 ? 占位，绝不字符串拼接 SQL。

11. 高可用与扩展

  • 主从复制：主库写、从库读，做读写分离与备份。
  • 分库分表：单表过千万/容量瓶颈时，按业务键（用户ID）水平拆分；用 ShardingSphere 等中间件。
  • 热点大表考虑冷热分离、归档。

12. 备份与恢复

  • 逻辑备份 mysqldump；物理/增量靠 binlog（可定点恢复）。
  • 定期演练恢复，别等出事才发现备份不可用。

13. 常见坑

坑 1：用 utf8（非真 UTF-8）存 emoji 报错 → 必须 utf8mb4。
坑 2：SQL 拼接 → 注入；用参数化。
坑 3：无主键/索引 → 全表扫描极慢。
坑 4：隐式类型转换（字符串列传数字）致索引失效。
坑 5：大事务长时间持锁 → 阻塞、主从延迟。
坑 6：深分页 LIMIT 大偏移 → 慢。

14. 调试诊断

  • 开慢查询日志 slow_query_log，定位慢 SQL。
  • EXPLAIN + SHOW PROCESSLIST 看阻塞；pt-query-digest 聚合分析。
  • SHOW ENGINE INNODB STATUS 看锁与死锁。
