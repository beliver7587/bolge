Git：从小白到版本控制

Git 是分布式版本控制，记录代码每一次变更，让协作与回滚成为可能。本教程讲清三区模型、分支策略与冲突解决——这是团队开发的必备技能。

1. 它是什么

Git 把项目历史存成提交（commit）的有向图，每人本地都有完整仓库，离线也能提交。

一句话：Git = 分布式版本控制。每一次提交都是一次快照，可随时回到任意时刻。

2. 起步

git init
git config --global user.name "王越"
git config --global user.email "me@x.com"
git clone https://github.com/u/repo.git

3. 三区模型

区含义
工作区你正在编辑的文件
暂存区git add 后待提交
仓库git commit 后永久记录
流程：改文件 → add → commit。理解三区，Git 就不玄学。

4. 提交与分支

git add -A
git commit -m "feat: 加登录"
git branch dev && git checkout dev   # 或 git switch -c dev
  • 分支极轻量，鼓励“一个功能一个分支”。
  • 主干常叫 main/master。

5. 合并与变基

git checkout main && git merge dev     # 合并（保留分叉历史）
git rebase main                          # 变基（历史更线性）
坑：别对已经推送到远程的公共分支做 rebase，会改写他人历史。

6. 远程协作

git push origin main
git pull            # fetch + merge
git fetch           # 只拉不合并，先看再合

7. 回退与撤销

  • git checkout -- file：丢弃工作区改动。
  • git reset --soft HEAD~1：撤回提交保留改动。
  • git revert：生成新提交抵消旧提交（安全，可推远程）。

8. 常见坑

坑 1 大文件进仓库：用 .gitignore 排除 node_modules/构建产物；大文件用 LFS。
坑 2 强推破坏：git push --force 会覆盖远程，慎用于自己分支。
坑 3 冲突：合并冲突要手动解决再提交，别盲目接受某一侧。

9. 资源与路线

  1. 官方 git-scm.com、Learn Git Branching 交互练习。
  2. 练：建分支开发 → 合并 → 用 revert 回退一次提交。
  3. 团队用 GitHub/GitLab 的 PR/MR 做代码评审。
资深标志：能设计分支策略（如 Git Flow/Trunk），用 rebase 保持历史干净，并在冲突时判断“该保留哪段逻辑”而非机械接受。

完整流程：Git 协作流程

1. 本地工作
git init / git clone 
git checkout -b feature/login
git add . && git commit -m "feat: login"
2. 远程同步
git remote add origin 
git push -u origin feature/login
git pull origin main --rebase
3. 合并
# 发起 Pull Request / Merge Request
# 代码审查通过后再合并到 main
# 冲突解决：git rebase --continue / git merge --abort
要点：提交信息要规范；feature 分支小步快跑；不要提交机密。
