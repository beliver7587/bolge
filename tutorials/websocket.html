WebSocket：从小白到双向长连接

WebSocket 是一次握手后保持的全双工长连接协议，客户端和服务器可随时互发数据。它是实时游戏、聊天、流式输出的底层基础，也是 Socket.IO 的内核。本教程讲清握手、API 与心跳重连。

1. 它是什么

HTTP 是“请求—响应”一问一答，且服务端不能主动推。WebSocket 在一次升级握手后，建立持久双向通道，双方随时发消息。

一句话：WebSocket = 持久双向通道。适合需要“服务端主动推”的实时场景。
适合：聊天、实时游戏、行情推送、SSE 之外的双向流。不适合：普通请求—响应（用 HTTP 更简单）。

2. 握手

客户端发一个带特殊头的 HTTP 请求，服务端同意后将连接“升级”为 WebSocket：

GET /ws HTTP/1.1
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: ...

3. 客户端 API

const ws = new WebSocket('wss://x.com/ws');
ws.onopen = () => ws.send('hi');
ws.onmessage = (e) => console.log(e.data);
ws.onclose = () => {};
  • 用 wss://（加密）如同 HTTPS，生产必备。
  • 数据可是文本或二进制（ArrayBuffer/Blob）。

4. 服务端

import { WebSocketServer } from 'ws';
const wss = new WebSocketServer({ server });
wss.on('connection', (ws) => {
  ws.on('message', (m) => ws.send('echo:' + m));
});

Node 用 ws 库；Spring 有 @ServerEndpoint；各语言都有实现。

5. 心跳与重连

  • 心跳：定时互发小包（ping/pong），探测连接存活，灭掉“假死”连接。
  • 重连：onclose 里指数退避重连，避免雪崩。
坑：中间代理（Nginx）默认会断空闲长连接，要调长超时或靠心跳保活。

6. 与 HTTP

HTTPWebSocket
模式一问一答双向长连接
服务端推不行（需轮询）随时推
开销每次握手一次握手持续用

7. 与 Socket.IO

WebSocket 是协议；Socket.IO 是库，封装了房间/广播/重连/降级。要简单双向通道用原生 WS，要全套实时能力用 Socket.IO。

8. 常见坑

坑 1 代理超时：见第 5 节，靠心跳。
坑 2 离线消息：WS 不持久，断开期间消息丢失；要可靠投递得自己加队列/重发。
坑 3 鉴权：握手是普通 HTTP，可在握手头或 query 里带 token 校验。
