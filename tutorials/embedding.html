向量检索 / Embedding：从小白到资深

Embedding 把文本/图片映射成高维向量，语义相近则向量相近；向量检索按距离找最近内容。它是语义搜索与 RAG 召回的灵魂。本教程讲透向量数学、ANN 索引、切块策略、混合检索、生产要点与评估——这是做 RAG/语义召回的硬功。

1. 它解决什么问题

关键词搜索看“字是否一样”，向量搜索看“意思是否接近”。搜“怎么让钱生利息”也能命中“银行理财入门”——因为二者向量距离近。

一句话：Embedding 把“语义”变成可在数学空间里比较的稠密向量；向量检索 = 在向量空间里找最近的邻居。
适合：语义搜索、推荐、RAG 知识召回、去重、聚类。
不适合：精确匹配（订单号、型号）——那是 BM25 的强项。

2. 工程化选型

  • Embedding 供应商：OpenAI text-embedding-3、国产智谱 embedding-3 等（注意维度/速率/成本）。
  • 向量库：轻量用 chroma、PostgreSQL + pgvector（复用现有 DB）、Qdrant/Milvus（大规模）、Pinecone（云托管）、FAISS（本地索引库）。

3. 向量数学

// 余弦相似度：向量夹角的 cos，范围 [-1,1]，越接近 1 越相似
function cosine(a, b) {
  let dot=0, na=0, nb=0;
  for (let i=0;i<a.length;i++){ dot+=a[i]*b[i]; na+=a[i]*a[i]; nb+=b[i]*b[i]; }
  return dot / (Math.sqrt(na)*Math.sqrt(nb));
}
  • 向量通常归一化到单位长，则余弦相似度 = 内积（更快）。
  • 距离度量：余弦、内积、欧氏（L2）——同一库内要统一。

4. 嵌入模型

  • 维度（如 1536/768）决定存储与计算量；维度不一致无法比。
  • 多语言场景选多语言模型，否则中英向量空间不同。
  • 同一次系统的“写入”与“查询”必须用同一个模型。

5. 向量库与索引

暴力比对（精确 KNN）在大库上太慢，向量库用近似最近邻（ANN）：

  • HNSW：图索引，召回高、查询快，但建索引占内存。
  • IVF：聚类分桶，先粗筛再精比，省内存。
  • 召回率 vs 延迟：ANN 牺牲少量精度换速度；调参（efSearch/hnsw_m）平衡。
资深：理解“近似”的含义——ANN 可能漏召回真正相关项，所以常与精确/关键词路互补。

6. 切块策略

文档不能直接整篇塞（太长会稀释向量语义）。切块是关键：

  • 块大小：太大检索不精准，太小丢上下文——通常 200~800 token 并留重叠（overlap）。
  • 元数据：每块带 source/章节/时间，便于过滤与解释。
  • 按语义边界（段落/标题）切，优于硬按字数切。

7. 检索链路

// 写入：切块 → 各自 embed → 入库
for (const chunk of chunkDoc(doc)) {
  const v = await embed(chunk.text);
  await col.add({ ids:[chunk.id], embeddings:[v], documents:[chunk.text], metadatas:[{source:doc.id}] });
}
// 查询：问句 embed → ANN 检索 topK → 送 RAG
这是 Memora 记忆/检索的核心链路：知识切块嵌入入库，提问时取最相关片段再交给大模型。

8. 混合检索

纯向量检索易召回“字面无关但真相关”或“字面对但无关”的内容。与 BM25 关键词路并用、再用 RRF 融合排名，质量显著提升。

经验：生产级 RAG 几乎都做“向量 + 关键词”混合 + 重排（rerank），单路向量 rarely 足够。

9. 生产要点

  • 一致性：写入/查询模型、维度、距离度量必须一致。
  • 成本与速率：Embedding 有费用与限流；批量 + 缓存已算过的向量。
  • 增量更新：文档变更要重新 embed 受影响块，并删旧块，避免脏数据。
  • 可解释：返回相似度分数与出处，便于排查。

10. 评估

  • 用标注集算召回率/命中率（topK 内是否含正确答案）。
  • 加 rerank 模型（如 cross-encoder）对召回结果二次精排。
  • 调 chunk 大小、topK、混合权重做 A/B。

11. 常见坑

坑 1：写入与查询用不同模型/维度 → 检索全错。
坑 2：切块太大/太小 → 不精准或丢上下文。
坑 3：只靠向量忽略关键词 → 订单号/型号类查不准。
坑 4：ANN 召回不全当“没有” → 用混合检索兜底。
坑 5： Embedding 成本/限流没批处理缓存 → 慢且贵。
坑 6：文档更新后旧向量残留 → 脏召回。

12. 调试

  • 用 t-SNE/UMAP 把向量降维可视化，看语义是否聚拢。
  • 打印 topK 相似度分布，异常低分往往切块/模型有问题。

13. 成长路线

阶段能力标志
小白能生成 embedding、入库、做相似检索
初级会切块、选向量库、搭 RAG 链路
中级懂 ANN 索引、混合检索、rerank
资深评估体系、生产调优、召回质量负责
练习：① 手算两段文本的余弦相似度 ② 用 pgvector/chroma 建库并 ANN 检索 ③ 调 chunk 大小看召回变化 ④ 做向量+BM25+RRF 混合 ⑤ 用标注集算召回率。
你已进阶：理解向量空间的数学与近似索引的权衡、能用混合检索+评估做出可靠召回——这是资深 AI 后端做 RAG 的底座能力。
