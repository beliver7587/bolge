Vite：从小白到构建优化

Vite 是新一代前端构建工具，主打秒级冷启动与极速热更新。它在开发期用浏览器原生 ESM、生产期用 Rollup 打包。本教程讲清它“为什么快”、配置怎么写、以及构建优化与排错。

1. 它解决什么问题

传统打包器（Webpack）冷启动要“先打包整个应用”才能起服务，项目越大越慢；改动一个文件也要重新构建依赖图，HMR 卡顿。

一句话：Vite = 开发期「不打包、按需编译」+ 生产期「Rollup 打包」。开发快，线上也小。
  • 开发期：基于浏览器原生 ESM，源码按需转换，不必预打包全部。
  • 生产期：用 Rollup 做 tree-shaking 与代码分割，产物更小更稳。

2. 工程化起步

1

创建

npm create vite@latest app -- --template react-ts
cd app && npm i && npm run dev
2

三个脚本

"dev": "vite"            # 开发服务器
"build": "tsc && vite build"  # 类型检查 + 打包
"preview": "vite preview" # 本地预览产物

tsc 只做类型检查（--noEmit），真正打包是 Vite/Rollup。

3. 开发服务器原理

  • 原生 ESM：浏览器直接 import 模块，Vite 只转换「当前请求到的文件」，不做全量打包。
  • 按需编译：打开页面才编译用到的模块，冷启动与项目规模基本解耦。
  • HMR：改一个文件，只通过 WebSocket 推这一块的更新，毫秒级。
资深视角：为什么比 Webpack 快？Webpack 要建完整依赖图再启动；Vite 把“建图”拆散到每个请求，启动只做极少量工作。

4. 配置文件

// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
export default defineConfig({
  plugins: [react()],
  resolve: { alias: { '@': '/src' } },
  server: { port: 3000, proxy: { '/api': 'http://localhost:8080' } },
});
坑：alias 在 JS 里用 '@/x'，但在 CSS 里要写 @import '@/styles' 需额外配 css.preprocessorOptions 或 resolve.alias 也被 CSS 解析。

5. 生产构建

npm run build   # 产出 dist/
  • Rollup：做 tree-shaking（删未用代码）、作用域提升、代码分割。
  • 入口拆分：build.rollupOptions.output.manualChunks 把大库拆成独立 chunk，利于缓存。
  • 产物分析：rollup-plugin-visualizer 看谁占了体积。

6. 插件机制

Vite 插件复用 Rollup 插件接口，并扩展开发期钩子：

export default function myPlugin() {
  return {
    name: 'my-plugin',
    transform(code, id) { /* 改源码 */ return code; },
  };
}
常用插件：@vitejs/plugin-react、unplugin-auto-import、vite-plugin-pwa、vite-tsconfig-paths。

7. 框架集成

  • React：@vitejs/plugin-react（用 Babel/SWC 转 JSX）。
  • Vue 3：@vitejs/plugin-vue 编译 .vue。
  • Next.js：自带基于 SWC 的构建，不是直接用 Vite，但理念同源。

8. 环境变量

// .env
VITE_API=https://api.x
// 代码中
const api = import.meta.env.VITE_API;
规则：只有 VITE_ 前缀的变量才会暴露给客户端；私密配置放 .env.local（不入库）或服务端。

9. 静态资源

  • 代码中 import img from './a.png' 会被处理成带哈希的 URL。
  • public/ 目录下的文件原样拷贝到根，适合 favicon、robots 等。
  • 小资源可转 base64 内联（assetsInlineLimit）。

10. 依赖预构建

Vite 首次启动会用 esbuild 把 node_modules 里的 CJS/大依赖预编译成 ESM，加速后续加载。optimizeDeps 可手动包含/排除。

坑：新增依赖后没预构建会导致“页面白屏报错”；删 node_modules/.vite 或重启 dev 即可重建。

11. 库模式

build: { lib: { entry: 'src/index.ts', formats: ['es','umd'], name: 'MyLib' } }

用同一套 Vite 配置打包成可发布的 npm 库，比手写 Rollup 配置省事。

12. 与 Webpack

ViteWebpack
开发启动秒级（按需编译）随规模变慢
生态新、增长快成熟、插件多
学习配置少概念多

13. 常见坑

坑 1 路径别名只在 JS 生效：CSS 里用别名需额外配置。
坑 2 HMR 失效：状态在模块顶层、或循环依赖，热更新会整页刷新；把状态收进组件。
坑 3 大依赖拖慢：把一个超大 CJS 库塞进入口，预构建慢；用 manualChunks 拆出。

14. 优化手段

  • build.target 设高一点减少降级代码。
  • manualChunks 把 react/antd 等拆 vendor。
  • 按需引入 UI 库（见 Ant Design 的 babel 插件）。

15. 资源与路线

  1. 官方文档 vitejs.dev。
  2. 配套学 TypeScript、React/Vue。
  3. 练：配 alias + proxy + manualChunks，分析产物体积。
资深标志：能解释 Vite 为什么快、知道构建慢该查预构建还是 chunk 拆分——而不只是 npm run dev 一把梭。
