WebSocket

浏览器原生的全双工实时通信协议 —— 一次握手后服务端可主动推消息，无需轮询。学完你能用原生方式做实时通信。

1. 这是什么

WebSocket 是 HTML5 的通信协议，在单个 TCP 连接上提供全双工通道。相比 HTTP 请求-响应，它让服务器能主动随时给浏览器发数据。

对比：HTTP 轮询是“客户端反复问有没有新消息”；WebSocket 是“连上后服务端有消息直接推”。
适合：实时行情、监控、游戏、消息推送。
注意：它是底层协议，没房间/重连等便利功能，要自己写或用 Socket.IO。

2. 环境准备

浏览器端原生支持，无需安装。服务端用 Node 的 ws 库：

npm install ws

3. 浏览器端

const ws = new WebSocket('ws://localhost:8080');
ws.onopen = () => ws.send('你好服务端');
ws.onmessage = (e) => console.log('收到：', e.data);
ws.onclose = () => console.log('已关闭');

4. 服务端（Node）

import { WebSocketServer } from 'ws';
const wss = new WebSocketServer({ port: 8080 });
wss.on('connection', (ws) => {
  console.log('客户端连上');
  ws.on('message', (data) => {
    console.log('收到：', data.toString());
    ws.send('你发了：' + data);     // 回给该客户端
  });
});

5. 收发消息

只能发字符串或二进制（ArrayBuffer/Blob）。要传对象先 JSON.stringify。

ws.send(JSON.stringify({ type: 'chat', text: 'hi' }));
// 接收端
const obj = JSON.parse(e.data);

6. 心跳保活

长时间空闲连接可能被代理/系统关闭，需定期发心跳：

// 客户端每 30 秒发一次 ping
setInterval(() => { if (ws.readyState === 1) ws.send('ping'); }, 30000);

8. 常见坑

坑 1：生产环境经 Nginx 反代需开启 WebSocket Upgrade，否则 400。
坑 2：ws 收到的数据是 Buffer，要 data.toString() 才是字符串。
坑 3：页面用 https 时 WebSocket 地址要用 wss://，否则被浏览器拦截。
坑 4：不处理断线重连，网络波动后消息发不出去；自己实现重连逻辑或换 Socket.IO。
