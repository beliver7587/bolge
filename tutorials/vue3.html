Vue 3：从小白到组合式专家

Vue 3 是渐进式前端框架：模板写界面、响应式数据自动驱动视图。相比 React 的“显式状态→UI”，Vue 更“约定式”、上手更平缓。本教程讲清响应式本质、Composition API 与工程化落地。

1. 它解决什么问题

原生 JS 改数据要手动操作 DOM，数据一多极易“界面和数据对不上”。Vue 把“数据”和“视图”绑定：数据变了，视图自动更新。

一句话：Vue = 声明式模板 + 响应式系统 + 组件化。你写“数据和模板的关系”，框架负责更新 DOM。
渐进式：可以从“一个 <script> 引入”渐进到“整套工程化 SPA/SSR”，按需采用，学习坡度比 React 缓。

2. 工程化起步

1

脚手架

npm create vue@latest myapp
# 选 TypeScript / Router / Pinia / Vitest
cd myapp && npm i && npm run dev

底层基于 Vite，秒级热更新。

2

单文件组件 SFC

<script setup lang="ts">
import { ref } from 'vue';
const count = ref(0);
</script>
<template><button @click="count++">{{ count }}</button></template>

.vue 把模板、逻辑、样式放一个文件，<script setup> 是最推荐的写法。

3. 模板语法

  • 插值：{{ count }} 显示响应式值。
  • 指令：v-if/v-else 条件、v-for 循环、v-bind(:) 绑定属性、v-on(@) 绑定事件、v-model 双向绑定表单。
  • 修饰符：@click.stop 阻止冒泡、v-model.trim 去空格。
<li v-for="(item, i) in list" :key="item.id">{{ i }} {{ item.name }}</li>
<input v-model="text" @keyup.enter="add" />

4. 响应式原理

Vue 3 用 Proxy 代理对象：读取时收集依赖，修改时触发更新。

API用途
ref(x)包装基本类型，用 .value 访问（模板里自动解包）
reactive(obj)代理对象，直接读写属性即响应
toRefs把 reactive 解构成若干 ref，便于解构不丢响应
坑：解构 reactive 会丢失响应——用 toRefs；reactive 重新赋值整个对象也不行，要用 Object.assign 原地改。

5. Composition API

Composition API 用函数组织逻辑，比 Options API（data/methods 平铺）更易复用与 TS 推断。

import { ref, onMounted } from 'vue';
const list = ref<string[]>([]);
onMounted(async () => { list.value = await fetchList(); });
资深做法：把“取数/防抖/键盘”等逻辑抽成组合式函数（文件名 useXxx），组件只管渲染——这是 Vue 版的自定义 Hook。

6. 组件与 Props

// 子组件
const props = defineProps<{ title: string; count?: number }>();
const emit = defineEmits<{ (e: 'change', v: number): void }>();
emit('change', 1);
  • defineProps 声明入参，defineEmits 声明回调（单向数据流，子改父靠 emit）。
  • 插槽（见第 9 节）用来分发内容。

7. 状态管理 Pinia

全局状态用 Pinia（Vuex 的现代替代品），概念比 Redux 轻：

export const useCart = defineStore('cart', () => {
  const items = ref<Item[]>([]);
  const add = (i: Item) => items.value.push(i);
  const total = computed(() => items.value.reduce((s, i) => s + i.price, 0));
  return { items, add, total };
});
对比：Pinia ≈ Zustand 的 Vue 版——轻量、按需订阅；服务端数据仍交给请求库，别塞进 store。

8. 计算与侦听

  • computed：派生值，依赖变才重算，有缓存。
  • watch：观察变化做副作用（请求、日志）。
  • watchEffect：自动收集依赖立即执行。
const full = computed(() => `${first.value} ${last.value}`);
watch(count, (n, o) => console.log(`从${o}到${n}`));

9. 插槽

  • 默认插槽：<slot /> 接收子内容。
  • 具名插槽：<slot name="header" /> + <template #header>。
  • 作用域插槽：子把数据回传给插槽，实现“列表项由父定制”。
资深：作用域插槽是 Vue 组件高复用的关键，类似 React 的 render props。

10. 组合式函数

// useFetch.ts
export function useFetch<T>(url: string) {
  const data = ref<T | null>(null);
  const loading = ref(true);
  onMounted(async () => { data.value = await (await fetch(url)).json(); loading.value = false; });
  return { data, loading };
}

组合式函数让逻辑跨组件复用且类型友好，是 Composition API 的杀手锏。

11. 路由

vue-router 提供声明式路由、嵌套路由、懒加载：

const routes = [{ path: '/user/:id', component: () => import('./User.vue') }];
  • 鉴权：beforeEach 守卫里判断登录态再 next()/重定向。
  • 懒加载：动态 import 拆包，首屏更小。

12. 与 React 差异

维度Vue 3React
视图模板 DSLJSX（就是 JS）
更新机制Proxy 自动依赖收集显式 setState / 调度
心智约定式、平缓显式、灵活但更自由
怎么选：团队偏模板/平缓上手选 Vue；需要极致灵活、生态广选 React。两者底层思想（组件、单向流、响应式/声明式）是相通的。

13. SFC 与构建

  • vite 用 @vitejs/plugin-vue 编译 .vue。
  • <style scoped> 自动加哈希作用域，避免样式冲突。
  • TS 支持在 <script setup lang="ts"> 中。

14. 常见坑

坑 1 响应丢失：解构 reactive、或把 ref 当普通变量（忘了 .value）导致不更新。
坑 2 v-for 没 key：用 index 当 key 做可增删列表会状态错位，用稳定 id。
坑 3 异步改响应式：在 await 后修改已被卸载组件的 ref，会警告——注意生命周期。

15. 生态与 SSR

  • Nuxt：Vue 的 Next.js 等价物，提供 SSR/SSG、文件路由。
  • uni-app：用 Vue 语法一套代码发到 H5/小程序/App。
  • UI 库：Element Plus、Naive UI 等。

16. 调试

  • Vue DevTools：看组件树、props、Pinia 状态、事件。
  • @vue/runtime-core 警告：响应式相关错误会给出明确提示。
