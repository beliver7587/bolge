Provider：从小白到模型供应商

Provider 是 大模型 的提供方。同一套代码通过统一网关切换 OpenAI / 通义 / DeepSeek / 本地模型，是生产落地的解耦关键。本教程讲清怎么不绑定单一厂商。

1. 它是什么

Provider 提供模型 API（推理端点）。你的应用不直接写死某家，而是经统一层调用，便于替换与降级。

一句话：Provider = 模型供应商。统一接入层让你“换模型像换配置”。

2. 常见 Provider

Provider特点
OpenAI生态全、能力强，但需合规/费用
通义/智谱/DeepSeek国内合规、便宜、中文好
本地模型Ollama/vLLM，数据不出内网

3. 统一接入

// 用 one-api / litellm 做网关，代码只认 OpenAI 兼容协议
const client = new OpenAI({ baseURL: 'https://gw.internal/v1', apiKey: 'x' });

网关后面可挂多家 Provider，按策略路由，应用无感切换。

4. 成本与限额

  • 按 token 计费（输入 + 输出），长上下文/大输出是费用大头。
  • 设速率限制与预算告警，避免失控（Agent 循环尤其费钱）。

5. 选型与切换

做法：核心链路用稳定大模型，批量/低成本场景用便宜模型；通过网关配置按场景路由，不写死。

6. 常见坑

坑 1 写死供应商：换模型要改代码，耦合重；用网关解耦。
坑 2 密钥泄露：Provider key 是钱也是权限，走环境变量 + 网关，别进前端/仓库。
坑 3 超时/限流：Provider 会限流，需重试 + 退避 + 降级。

7. 资源与路线

  1. 各 Provider 文档、one-api / litellm 项目。
  2. 配合 LLM、Agent。
  3. 练：用 one-api 接两家 Provider，代码零改切换。
资深标志：把“模型供应”做成可替换的基础设施，用网关 + 限额 + 重试把成本与可用性都控住。

完整流程：封装多 Provider

1. 统一配置
providers:
  openai: {base_url:"https://api.openai.com/v1", key:"sk-..."}
  deepseek: {base_url:"https://api.deepseek.com/v1", key:"sk-..."}
  qwen: {base_url:"https://dashscope.aliyuncs.com/compatible-mode/v1", key:"sk-..."}
2. 统一调用接口
function chat(provider, model, messages) {
  return axios.post(cfg[provider].base_url + '/chat/completions', {...}, headers)
}
3. 路由与降级
按模型名或成本路由；失败时自动切换备用 provider
记录 token 消耗与响应时间
要点：OpenAI SDK 兼容格式最通用，统一 base_url 即可切换多家。
