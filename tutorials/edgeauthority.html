端侧权威运算架构

运算放玩家设备、服务器只中转 —— 一台 2 核机扛上百房间的秘诀。

1. 这是什么

这是网页游戏平台最核心的设计思想：以火柴人为例，一台“房主”设备（开大屏的电脑）既是客户端又是服务器逻辑端——它本地算物理/碰撞/战斗、渲染画面；云端服务器只做消息中转，完全不解析游戏内容。这就是“端侧权威运算”。

2. 三种角色

角色设备职责
房主端（Host）PC 大屏运行引擎、算战斗、渲染、广播状态
控制端（Pad）手机只采输入（摇杆/按钮）并上报
中转服务器云端按房间转发字符串，不解析内容

3. 为什么省钱

关键洞察：普通网游把“谁打中谁”放服务器算，服务器又贵又易成瓶颈；本项目把运算下放房主设备，服务器只做“微信群转发”，所以一台 2 核 2G 机器能扛上百房间。且手机端改不了任何数据（手里没运算逻辑），天然防作弊。

4. 数据流（手机按跳 → 大屏跳起，<100ms）

① 手机按跳 → ② 20Hz 打包输入 → ③ WS 发服务器 ④ 服务器原样转房主 → ⑤ 房主引擎算跳跃 → ⑥ 广播状态 ⑦ 服务器转发 → ⑧ 手机收到更新 UI
延迟低的原因：延迟主要发生在“手机→房主”，同 WiFi 下 <10ms；而“房主→手机”只是看画面，玩家对“看”的延迟不敏感。

5. 常见坑

坑 1：房主掉线=整局散（房主是权威源）——可加“房主转移/托管”缓解。
坑 2：房主作弊改内存就“无敌”——这是架构软肋，休闲局可接受，认真防要上轻量校验端。
坑 3：房主网络差拖垮全房间——要控制广播带宽（30Hz 状态 + 20Hz 输入上报）。
