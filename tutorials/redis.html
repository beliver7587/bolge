Redis

内存中的键值数据库 —— 读写极快（微秒级），常做缓存、会话、排行榜。简历工坊用它缓存热点数据。学完你能用 Redis 给系统提速。

1. 这是什么

Redis 把数据放内存里，所以快；同时可持久化到磁盘防丢。典型用途：缓存、限流、会话存储、消息队列、排行榜。

对比：MySQL 落盘、适合主数据；Redis 内存、适合“快”和“临时”数据。
核心思想：把慢查询（DB）的结果暂存到 Redis，下次直接命中缓存，系统快几十倍。

2. 环境准备

docker run -d --name redis -p 6379:6379 redis:7

本地客户端连：redis-cli -h 127.0.0.1 -p 6379。

3. 基础命令

SET name 小王          # 存字符串
GET name               # 取
EXPIRE name 60         # 60 秒后过期
TTL name               # 看剩余时间
DEL name               # 删除

类型用途

5. 从代码用

Node 用 ioredis：

import Redis from 'ioredis';
const r = new Redis();
await r.set('name', '小王', 'EX', 60);
const v = await r.get('name');

6. 缓存实战

async function getUser(id) {
  const key = 'user:' + id;
  let data = await r.get(key);
  if (data) return JSON.parse(data);     // 命中缓存
  data = await db.query('SELECT * FROM user WHERE id=?', [id]);  // 回源 DB
  await r.set(key, JSON.stringify(data), 'EX', 300);             // 写缓存 5 分钟
  return data;
}
套路：先查缓存→命中返回；未命中查 DB→写入缓存→返回。

7. 常见坑

坑 1：缓存和数据库不一致：更新 DB 后要删/更新缓存（Cache Aside）。
坑 2：缓存雪崩：大量 key 同时过期，请求全压到 DB；过期时间加随机抖动。
坑 3：缓存穿透：查不存在的数据，缓存不命中一直打 DB；用空值缓存或布隆过滤器。
坑 4：内存爆掉：没设 maxmemory + 淘汰策略，数据无限增长；设 maxmemory-policy allkeys-lru。
坑 5：把 Redis 当主数据库用又没开持久化，重启丢数据。
