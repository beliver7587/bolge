SSE

服务端推送事件（Server-Sent Events）—— 服务端能一条条把数据推给浏览器，用来做“打字机式”的 AI 回复、实时进度条。Memora 用它流式输出。学完你能做流式界面。

1. 这是什么

SSE 是基于 HTTP 的单向（服务端→客户端）流式推送：浏览器建一条长连接，服务端随时推文本片段，自动重连。

对比：WebSocket 双向全双工；SSE 只下不上、走普通 HTTP，更易与现有 Web 框架/反代兼容。
典型用途：大模型逐字输出、日志流、行情推送。

2. 服务端

用 Express：

app.get('/stream', (req, res) => {
  res.set({ 'Content-Type': 'text/event-stream', 'Cache-Control': 'no-cache', Connection: 'keep-alive' });
  let i = 0;
  const timer = setInterval(() => {
    res.write(`data: 第${i++}条\n\n`);   // 每条以 \n\n 结尾
    if (i > 5) { clearInterval(timer); res.end(); }
  }, 1000);
});

3. 浏览器端

const es = new EventSource('/stream');
es.onmessage = (e) => console.log('收到：', e.data);
es.onerror = () => { es.close(); };

5. 实战：打字机

大模型返回按 token 切片，服务端用 SSE 逐片 data: 推送，前端把 e.data 累加到页面，就是聊天机器人“逐字出现”的效果。

6. 常见坑

坑 1：每条消息必须以空行 \n\n 结束，否则浏览器不触发 onmessage。
坑 2：经 Nginx 反代时缓冲会延迟推送；设 proxy_buffering off。
坑 3：连接数限制：浏览器对同域 EventSource 并发有限；注意及时 close()。
坑 4：需要带鉴权时，EventSource 不能直接设自定义 Header；用 cookie 或 URL 参数。
