PixiJS / WebGL：从小白到 GPU 渲染

PixiJS 是基于 WebGL 的 2D 渲染库：把图形/精灵批处理交给 GPU，能轻松渲染成千上万个对象。本教程讲清它的场景图模型、渲染循环与性能要点——这是网页游戏画面的引擎。

1. 它解决什么问题

原生 Canvas 2D 靠 CPU 逐帧画，对象一多（几百个精灵 + 特效）就掉帧。PixiJS 用 WebGL 批处理，把同类绘制合并成少量 GPU 调用，性能数量级提升。

一句话：PixiJS = WebGL 的“友好封装”，让你用“场景图”而非裸 GL 写高性能 2D。
适合：2D 游戏、粒子、数据可视化大屏。不适合：简单静态图（直接用 Canvas/图片即可）。

2. 起步

import { Application, Sprite, Assets } from 'pixi.js';
const app = new Application();
await app.init({ width: 800, height: 600, background: '#0a0e17' });
document.body.appendChild(app.canvas);

PixiJS v8 用 await app.init() 异步初始化（WebGL 上下文）。

3. 核心概念

  • Stage：根容器，所有可见对象挂在它下面。
  • Container：分组容器，可嵌套，便于整体移动/隐藏。
  • Sprite：精灵，贴一张纹理（Texture）。
  • Texture：纹理，图片在 GPU 上的表示。
const sprite = Sprite.from('hero.png');
sprite.x = 100; sprite.anchor.set(0.5);  // 锚点居中
app.stage.addChild(sprite);

4. 渲染循环

app.ticker.add((ticker) => {
  sprite.x += ticker.deltaTime * 2;  // 与帧率无关的移动
});
资深：用 deltaTime 而非固定步长，保证不同帧率下速度一致（高刷屏不会变快）。

5. 精灵与图集

  • 图集（Atlas）：把多张小图拼成一张大图 + JSON，减少纹理切换，提升批处理率。
  • AnimatedSprite：多帧纹理播放动画（行走、爆炸）。

6. 文本与图形

import { Text, Graphics } from 'pixi.js';
const t = new Text({ text: '得分', style: { fill: 0xffffff } });
const g = new Graphics().circle(0,0,30).fill(0x4ade80);

Graphics 画矢量（圆/矩形/线），Text 渲染文本。

7. 交互

sprite.eventMode = 'static';   // 开启交互
sprite.on('pointerdown', () => { /* 点击 */ });

用 eventMode 替代旧版 interactive，按需开启以保证性能。

8. 滤镜特效

Pixi 内置/社区滤镜：模糊、发光、位移贴图、颜色矩阵。特效很炫但要算 GPU，别给全屏每帧加重滤镜。

9. 性能

  • 批处理：同纹理、同 blend 才能合并绘制调用，尽量用图集。
  • 避免每帧 new：对象/纹理复用，别在 ticker 里创建。
  • 对象池：子弹/粒子用池复用，减少 GC。

10. 与 Canvas2D

PixiJS/WebGLCanvas 2D

规模千级对象流畅数百即吃力
上手概念多简单直接

11. 常见坑

坑 1 内存：纹理不销毁会显存泄漏，用 texture.destroy() 释放。
坑 2 全开交互：给所有对象开 eventMode 会变慢，只在需要的对象上开。
坑 3 分辨率：高 DPI 下设 resolution: devicePixelRatio 保持清晰。
