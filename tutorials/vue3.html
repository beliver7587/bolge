Vue 3：从小白到资深前端

Vue 是渐进式前端框架，国内项目占比极高。本教程不止教模板语法，而是讲透它的响应式系统（Proxy 实现）、组合式 API 心智、编译期优化，并和 React 做选型对比，帮你成为能驾驭大型 Vue 工程的资深工程师。

1. 它解决什么问题

和 React 一样，Vue 也是声明式 UI 框架：你描述“状态→界面”，框架负责更新 DOM。差别在心智模型与写法。

一句话：Vue 用模板 + 响应式数据，改动数据自动更新视图，且内置了路由、状态管理、构建（Vite）等全家桶，开箱即用程度高。
适合：中后台、国内业务系统、需要快速上手的团队、跨端（uni-app）。
不适合：极致定制的设计系统（模板约束比 JSX 强）。

2. 工程化起步

npm create vue@latest my-app      # 官方脚手架，选 TS/Router/Pinia
cd my-app && npm install && npm run dev

生成 src/：main.ts（创建 app）、App.vue（根组件）、components/。组件是 .vue 单文件组件（SFC），含 <template><script><style> 三部分。

3. 响应式原理

这是 Vue 的心脏，资深必懂。

  • Vue 2 用 Object.defineProperty 劫持属性，但监听不到新增/删除属性与数组下标，要 Vue.set 补丁。
  • Vue 3 改用 Proxy：对整个对象做代理，任意读写、增删、数组操作都能拦截，且懒代理（用到才代理深层）。
  • 依赖收集 → 派发更新：组件渲染时“读”了某个响应式属性，就建立“这个属性 → 这个组件的渲染 effect”的依赖；属性被“写”时，触发对应 effect 重新渲染。
import { reactive, effect } from 'vue';
const state = reactive({ count: 0 });
effect(() => console.log('count =', state.count)); // 读 → 收集依赖
state.count++;                                    // 写 → 触发 effect
坑底：响应式靠“读时收集”。如果你把响应式对象的属性解构出来（const { count } = state），拿到的是普通值，失去响应性。要用 toRefs 或保持引用访问。

4. 组合式 API

Vue 3 主推组合式 API（<script setup>），把“同一逻辑的响应式状态与函数”聚在一起，比选项式 API（data/methods 分散）更易复用与维护。

<script setup lang="ts">
import { ref, computed, onMounted } from 'vue';
const count = ref(0);                       // 基本类型用 ref，访问要 .value
const double = computed(() => count.value * 2);
function inc() { count.value++; }
onMounted(() => console.log('挂载完成'));
</script>
  • ref：包裹基本类型（模板里自动解包，不用 .value）；reactive：包裹对象。
  • computed：派生状态，带缓存。watch/watchEffect：监听变化做副作用。
  • 组合式函数（composable）：把逻辑抽成 useXxx()，跨组件复用——等价于 React 的自定义 Hook。

5. 模板与编译优化

  • 指令：v-if/v-show、v-for、v-bind(:)、v-on(@)、v-model（双向绑定）。
  • 编译期优化：Vue 3 编译器会把静态节点提升（不重复创建）、给动态节点打“补丁标记（patch flag）”，diff 时只比对动态部分——比 Vue 2 快很多。
  • v-model 本质是 :value + @input 的语法糖，自定义组件可用 modelValue/update:modelValue。
坑：v-for 必须带 :key（稳定 id），且 v-if 和 v-for 同元素时，v-if 优先级更高（Vue 3）——避免在同一节点混用。

6. 组件通信

  • 父→子：props（只读，子组件改要 emit 事件）。
  • 子→父：defineEmits 声明事件，emit('update', val)。
  • 插槽：<slot/> 默认插槽、具名 <slot name="header">、作用域插槽（子传数据给插槽内容）。
  • 跨层：provide/inject（类似 React Context，但要小心重渲染范围）。
  • 透传：未被声明为 props 的属性会落进 $attrs，可 inheritAttrs: false 手动绑定到指定元素（如把 class 透传到根 input）。

7. 状态管理 Pinia

Vuex 的继任者，更简洁、TS 友好。

// stores/counter.ts
import { defineStore } from 'pinia';
export const useCounter = defineStore('counter', () => {
  const n = ref(0);
  const double = computed(() => n.value * 2);
  function inc() { n.value++; }
  return { n, double, inc };
});
选型：局部状态用 ref/reactive；跨组件共享用 Pinia；服务端数据别存 Pinia（用 TanStack Query 类方案，同 React 思路）。

8. 路由

vue-router：<router-view/> 渲染匹配路由，<router-link> 跳转。支持嵌套路由、动态路由 :id、路由守卫（beforeEach 做鉴权）、路由懒加载（() => import()）。

9. 性能优化

  • v-once：一次性渲染静态内容，之后不更新。
  • shallowRef / shallowReactive：只对顶层做响应式，处理大对象时显著省开销。
  • 大列表用虚拟滚动（vue-virtual-scroller）。
  • 路由级懒加载 + Vite 分包减小首屏。

10. 与 React 对比

Vue 3React
视图写法模板（约束强、易上手）JSX（灵活、门槛高）
响应式内置 Proxy 自动追踪手动 setState/调度
心智框架帮你管更新你描述 UI=fn(state)
全家桶官方 Router/Pinia 统一生态丰富但需自选
选型：团队 Vue 背景、要快上手、中后台 → Vue；追求极致灵活/大型设计系统、React 生态（含 RN 跨端）→ React。两者资深能力高度互通。

11. 常见坑

坑 1：解构 reactive 丢响应性——用 toRefs 或保留引用。
坑 2：忘记 .value（在 <script> 里访问 ref 必须 .value，模板里不用）。
坑 3：v-for 没 key、或 key 用 index 导致状态错乱。
坑 4：异步改数据后立刻读 DOM，拿到旧值——用 nextTick() 等 DOM 更新完。
坑 5：在 setup 顶层写副作用没清理（定时器/监听），组件卸载后泄漏——在 onUnmounted 清理。

12. 调试

  • Vue DevTools：看组件树、props/state、Vuex/Pinia 状态、时间线。
  • @vue/reactivity 可单独调试响应式。
  • 生产构建用 vite build，配 sourcemap 便于排查。
