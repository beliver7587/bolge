Bun：从小白到资深后端

Bun 是用 Zig 写的新一代 JS 运行时与一体化工具链：直接跑 TS、自带包管理/测试/打包，启动与安装速度远超 Node.js。本教程讲清它为何快、兼容性边界、性能取舍与部署要点——帮你在“尝鲜”与“生产选型”间做对判断。

1. 它解决什么问题

Node 生态分散：运行时是 Node、装包用 npm、测试用 jest、打包用 esbuild/webpack。Bun 想“一个工具全包”：运行时 + 包管理 + 测试 + 构建，且全部更快。

一句话：Bun = 运行时 + 工具链一体化，且兼容绝大多数 npm 包，目标是更省心、更高速的 JS 开发体验。
适合：新项目、CLI、对启动/安装速度敏感的场景。
不适合：强依赖 Node 专属原生模块、或要求极致生态稳定性的生产系统（先用 Bun 试兼容）。

2. 工程化起步

curl -fsSL https://bun.sh/install | bash     # macOS/Linux
bun -v
bun init                                      # 生成 package.json
bun install                                    # 装依赖，秒级（比 npm 快数倍）

Bun 兼容现有 package.json 与 node_modules，可渐进替换 npm。

3. 核心能力

const txt = await Bun.file('a.txt').text();   // 读文件，API 简洁
await Bun.write('b.txt', txt);                // 写文件
console.log(Bun.env.API_KEY);                  // 环境变量（也兼容 process.env）
  • 原生 TS：bun run server.ts 直接跑 TypeScript，无需 tsc/ts-node 预编译。
  • 内置 API：文件、环境变量、哈希、SQLite（bun:sqlite）等开箱即用。
  • 内置工具：bun test（测试）、bun build（打包）替代 jest/esbuild。

4. HTTP 服务

Bun.serve({
  port: 3000,
  fetch(req) {
    return new Response(JSON.stringify({ msg: 'hi from Bun' }), {
      headers: { 'Content-Type': 'application/json' },
    });
  },
});

Bun.serve 基于 Web 标准 fetch/Response，比 Node 原生 http 简洁，性能也更优。生产仍可用 Express/Elysia 等框架（Bun 兼容大多 npm 框架）。

5. 兼容与边界

  • 兼容：绝大多数纯 JS npm 包、Node 的 process/Buffer 等 API 兼容层。
  • 边界：依赖特定 Node 原生模块（如某些 C++ addon）或老库可能不兼容；worker_threads 等部分 API 覆盖不全。
资深判断：上生产前先用 Bun 跑完整测试套件，确认没有隐式依赖 Node 专属行为。

6. 性能

  • 为何快：用 JavaScriptCore 引擎、Zig 写系统调用层、更少抽象开销；bun install 并行解析 + 缓存。
  • 启动/冷启动：显著快于 Node，利于 Serverless/CLI。
  • 基准仅供参考，真实收益取决于业务（I/O 密集差异小，启动/安装收益明显）。

7. 测试与构建

// math.test.ts
import { expect, test } from 'bun:test';
test('add', () => expect(1 + 1).toBe(2));
// 运行：bun test

bun build 可作 esbuild 替代；bun test 内置断言与覆盖率，省去 jest 配置。

8. 部署

  • CI/启动命令用 bun run 而非 node；镜像用官方 oven/bun 基础镜像。
  • 自带 --watch 热重载；生产建议用进程管理（PM2 或容器）守护。

9. 与 Node 选型

BunNode.js
生态稳定成长中最成熟
速度快（启动/安装）稳
工具链一体化需组合
选型：新项目、要速度与一体化工具链 → Bun；生产要求极致稳定/依赖 Node 原生能力 → Node。

10. 常见坑

坑 1：某些 Node 专属原生模块不兼容 → 先跑测试验证再上生产。
坑 2：Windows 用 npm 全局装 bun 后 PATH 未生效 → 重开终端或手动加。
坑 3：部署忘了运行时是 Bun，仍用 node 启动 → 改用 bun run。
坑 4：版本迭代快，跨小版本偶有 breaking → 锁版本（bun.lockb）。

11. 调试

  • bun --inspect 接 DevTools；bun test --coverage 看覆盖。
  • 兼容 Node 生态调试工具。

12. 成长路线

阶段能力标志
小白能装 Bun、跑 TS、起服务
初级会用 bun install/test 替代 npm/jest
中级懂兼容边界、性能取舍
资深做生产选型、验证兼容性、落地部署
练习：① 把一个 Express 项目改用 bun install + bun run ② 用 bun test 写测试 ③ 用 Bun.serve 写个接口对比 Express 吞吐 ④ 打 Bun 官方镜像部署一次。
你已进阶：理解“一体化工具链”的收益与兼容代价，能在速度与稳定间做出有依据的选型——这是资深对运行时的判断力。
