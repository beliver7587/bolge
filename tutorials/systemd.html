systemd

Linux 的系统与服务管理器 —— 让后端进程开机自启、崩溃重启、统一管日志。比 PM2 更底层、更通用。学完你能用系统自带方式守护服务。

1. 这是什么

systemd 是现代 Linux 的初始化系统，负责启动和管理服务（叫 unit）。你写的后端可以注册成一个 service，由系统接管生命周期。

对比：PM2 是 Node 专属；systemd 是系统级、语言无关，更适合生产长期驻留服务。

2. 环境准备

主流 Linux（Ubuntu/CentOS/Debian）默认自带 systemd，无需安装。

3. 写 unit 文件

新建 /etc/systemd/system/my-api.service：

[Unit]
Description=My API Service
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/home/ubuntu/app
ExecStart=/usr/bin/node /home/ubuntu/app/server.js
Restart=on-failure        # 崩溃自动重启
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target

4. 启停与开机

sudo systemctl daemon-reload         # 改了配置先重载
sudo systemctl start my-api
sudo systemctl enable my-api         # 开机自启
sudo systemctl status my-api

5. 看日志

journalctl -u my-api -f               # 实时看该服务日志

6. 常见坑

坑 1：改了 service 文件没 daemon-reload，不生效。
坑 2：User/路径/权限不对，服务起不来；确认 WorkingDirectory 与 ExecStart 路径可访问。
坑 3：环境变量没在 unit 里设，应用读不到；用 Environment= 或 EnvironmentFile=。
坑 4：Restart 设了 always 但程序启动即退出，systemd 会疯狂重启；用 on-failure 或排查启动错误。
坑 5：端口被占用或没放行防火墙，服务起了但访问不了。
