MyBatis-Plus：从小白到数据层主力

MyBatis-Plus（MP）是 MyBatis 的增强工具：单表 CRUD 几乎零 SQL，还带条件构造器、分页、代码生成。它是简历工坊数据层的主力。本教程讲清它怎么把“写 SQL”变成“写 Java”。

1. 它解决什么问题

原生 MyBatis 每个表要写 Mapper 接口 + XML 映射 + 一堆基础 SQL。MP 在 MyBatis 之上“增强”：单表操作用内置 API，复杂 SQL 仍可用 XML。

一句话：MP = MyBatis + 通用 Mapper + 条件构造器 + 分页/生成器。简单的不用写 SQL，复杂的不受限。

2. 工程化起步

<dependency>
  <groupId>com.baomidou</groupId>
  <artifactId>mybatis-plus-boot-starter</artifactId>
</dependency>

在 Spring Boot 配好数据源（见 MySQL）即可。

3. 实体映射

@TableName("user")
public class User {
  @TableId(type = IdType.AUTO) private Long id;
  private String name;
  @TableField("email") private String mail;
}
  • @TableName：类→表；@TableId：主键；@TableField：字段（名不同才标）。

4. 基础 Mapper

public interface UserMapper extends BaseMapper<User> {}  // 白送 CRUD
userMapper.insert(user);
User u = userMapper.selectById(1L);
userMapper.updateById(user);
价值：单表增删改查零 SQL，开发提速显著。

5. 条件构造器

QueryWrapper<User> w = new QueryWrapper<>();
w.eq("status", 1).like("name", "王").orderByDesc("id");
List<User> list = userMapper.selectList(w);
  • 链式构造 eq/ne/gt/like/in/orderBy 等，拼出 WHERE。
  • 复杂联表仍写 XML/注解 SQL，MP 不抢这块。

6. 分页

@Bean public MybatisPlusInterceptor mp() {
  MybatisPlusInterceptor i = new MybatisPlusInterceptor();
  i.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
  return i;
}
Page<User> p = userMapper.selectPage(new Page<>(1,10), w);
坑：不注册分页插件，selectPage 不会分页，会查全表！这是新手最常踩的。

7. 代码生成器

用 AutoGenerator 按数据库表一键生成 Entity/Mapper/Service/Controller，进一步省样板。

8. 乐观锁 / 逻辑删除

  • 乐观锁：@Version 字段，更新时校验版本防并发覆盖。
  • 逻辑删除：@TableLogic，删除变 UPDATE 标记，数据不真删。

9. 与 JPA

MyBatis-PlusSpring Data JPA
风格SQL 可控对象/方法名驱动
复杂查询写 XML 更顺需 Specification/QueryDSL
国内生态更流行较通用

10. 常见坑

坑 1 分页插件漏配：见第 6 节。
坑 2 字段名不一致：数据库下划线、Java 驼峰，开 mapUnderscoreToCamelCase 或显式 @TableField。
坑 3 全表更新：update 忘给 WHERE 会全表更新，MP 有防止全表操作的保护。

11. 最佳实践

  • 单表用 MP，联表/报表用 XML。
  • 复杂查询抽成 XML，保持可维护。
  • 用逻辑删除 + 乐观锁保数据安全。
