Node.js

让 JavaScript 跑在服务端的运行时 —— Memora 与游戏中转服务都基于它。

1. 这是什么

浏览器之外，JS 需要运行环境。Node.js 用 Chrome 的 V8 引擎把 JS 带到服务器端，让你用同一门语言写前端和后端。它还内置了文件、网络等系统能力，是 Express、PM2 等工具的地基。

2. 事件循环

Node 是单线程 + 异步非阻塞：一个线程处理大量并发请求，遇到 I/O（读文件、查库）不干等，先去处理别的，完了再回调。这让它特别适合“很多连接、但每次不重”的场景（如聊天、API）。

记忆：CPU 密集型（如大规模计算）不是 Node 强项，那种用多进程/其他语言。

3. 第一个服务

// server.js
const http = require('http');
const srv = http.createServer((req, res) => {
  res.end('Hello from Node!');
});
srv.listen(3010, () => console.log('跑在 3010'));
node server.js   # 终端运行，访问 http://localhost:3010

4. npm 包管理

npm 是 Node 的包管理器（装第三方库、管依赖）：

npm init -y        # 生成 package.json
npm install express # 装依赖，写进 package.json
npm run start      # 运行 scripts 里定义的命令

5. 常见坑

坑 1：回调地狱——用 async/await 替代层层回调。
坑 2：版本兼容性：某些原生模块（如 isolated-vm）在 Node 22 编译失败，要锁 Node 20（Memora 真实踩坑）。
坑 3：require 与 import 混用（CommonJS vs ESM）会报错，项目里保持一致。
