PM2：从小白到进程守护

PM2 是 Node.js 进程管理器：崩溃自动重启、零停机 reload、集群多进程、集中日志。没有它，Node 服务一崩就下线。本教程讲清守护、集群与开机自启。

1. 它是什么

PM2 在后台托管你的 Node 进程，监控并自重启；还能用多进程吃满多核 CPU。

一句话：PM2 = Node 的“看门狗 + 集群 + 日志中心”。进程挂了它负责拉起。

2. 起步

npm i -g pm2
pm2 start dist/main.js --name api
pm2 startup          # 配置开机自启
pm2 save             # 保存当前进程列表

3. 常用命令

命令作用
pm2 ls查看进程
pm2 logs看日志
pm2 restart重启
pm2 reload零停机重载
pm2 delete删除进程

4. 集群模式

pm2 start dist/main.js -i max   // 按 CPU 核数开多实例

多实例共享端口，吃满 CPU，单进程崩不影响整体。

5. ecosystem

// ecosystem.config.js
module.exports = { apps: [{ name:'api', script:'dist/main.js', instances:'max', env:{PORT:3000} }] };
pm2 start ecosystem.config.js

6. 日志

  • pm2 logs 实时；日志默认按进程归档到 ~/.pm2/logs。
  • 配合 Docker 时日志进 stdout，由容器平台收集。

7. 与 systemd

要让“服务器重启后 PM2 自动起”，用 pm2 startup 生成 systemd 单元，再 pm2 save。Nginx 也常由 systemd 管。

8. 常见坑

坑 1 忘了 save：新加进程没 pm2 save，重启后丢失。
坑 2 内存泄漏累积：设 max_memory_restart 自动重启防溢出。
坑 3 端口冲突：集群多实例不能用固定端口绑定，要让系统分配。

9. 资源与路线

  1. 官方 pm2 文档。
  2. 配合 Node、Nginx、systemd。
  3. 练：用 PM2 集群起一个 Node 服务并配置开机自启。
资深标志：用集群 + 内存上限 + 开机自启把服务做成“生产级守护”，而不是 node app.js 裸跑。

完整流程：PM2 管理 Node 进程

1. 安装与启动
npm install -g pm2
pm2 start index.js --name api
pm2 start index.js -i max  # 集群模式
2. 常用命令
pm2 list
pm2 logs api
pm2 restart api
pm2 reload api  # 零停机重载
3. 开机自启
pm2 startup
pm2 save
# 系统重启后自动恢复
要点：生产环境用 ecosystem.config.js 管理多应用、环境变量、日志策略。
