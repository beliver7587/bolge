Redis：从小白到内存缓存

Redis 是内存键值数据库，读写极快，常用作缓存、会话、排行榜。简历工坊用它在 MySQL 前扛热点流量。本教程讲清数据类型、缓存模式与三大坑（击穿/穿透/雪崩）。

1. 它是什么

Redis 把数据放内存，单线程处理命令，因此极快（十万级 QPS）。它不只是缓存，还是数据结构服务器。

一句话：Redis = 内存 KV + 丰富数据结构 + 持久化可选。快，是它的最大卖点。

2. 起步

redis-cli
SET name "王越" EX 60      # 存，60 秒过期
GET name
DEL name

生产用 Docker 起，配密码与持久化，客户端用连接池。

3. 数据类型

类型用途
String缓存值、计数器（INCR）
Hash对象属性（用户信息）
List队列、最新列表
Set/ZSet去重、排行榜（ZSet 有序）

4. 缓存模式

// 读：缓存优先
const hit = await redis.get(key);
if (!hit) { const v = await db.query(); redis.set(key, v, 'EX', 60); }
  • Cache-Aside：应用自己管读写缓存（最常用）。
  • 写时更新数据库后删缓存（或更新），保持最终一致。

5. 过期与淘汰

  • 过期：EXPIRE 设 TTL，到点删除（惰性 + 定期删）。
  • 淘汰：内存满时按策略（LRU/LFU）清键。

6. 持久化

  • RDB：定时快照，恢复快但有丢失窗口。
  • AOF：记录每条写命令，更持久但文件大。
  • 缓存场景常关持久化（丢了能从 DB 重建）。

7. 与 MySQL

典型分层：请求先查 Redis，命中即返；未命中查 MySQL 并回填。热点数据放 Redis 扛量，DB 兜底。

8. 其他用途

  • 会话存储：多实例共享登录态。
  • 排行榜：ZSet 按分数排序。
  • 限流：INCR + EXPIRE 做简单计数限流。
  • 消息队列：List/BRPOP 简易队列（严肃场景用专业 MQ）。

9. 常见坑

坑 1 缓存击穿：热点 key 过期瞬间大量请求打到 DB；用互斥锁或逻辑过期重建。
坑 2 缓存穿透：查不存在的数据，缓存永远不命中；用空值缓存或布隆过滤器。
坑 3 缓存雪崩：大量 key 同时过期；给 TTL 加随机抖动分散。
坑 4 大 key：超大 Hash/List 阻塞单线程；拆分或改用分片。
