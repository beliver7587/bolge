供应商抽象：从小白到资深

供应商抽象 把“用哪家大模型”从业务里抽出来——定义一个统一接口，为每家写实现，业务只依赖接口。换 OpenAI/国产/本地模型只需改配置。本教程讲透统一接口、消息归一化、多实现、工厂切换、降级容灾、缓存与可观测——这是 AI 应用不被厂商绑死、还能高可用的关键。

1. 它解决什么问题

  • 避免绑死：各家 API 参数、返回结构、模型名不同，直接调会写死。
  • 价格/可用性波动：需随时切换或做降级（一家 429/挂了换另一家）。
  • 合规：部分场景要求用国产/私有模型。

2. 统一接口

把业务真正用到的能力都纳入接口，别只抽 chat 漏了 stream/embed/tools：

// llm/provider.js  —— 统一契约，业务只认它
export class LLMProvider {
  async chat(messages, opts = {}) { throw new Error('not impl'); }
  async *stream(messages, opts = {}) { throw new Error('not impl'); }   // 流式
  async embed(texts) { throw new Error('not impl'); }                   // 嵌入（见 Embedding）
}

3. 消息归一化

归一化是痛点：某家用 content 字符串，某家用 content 数组（含多模态）；某家 tool 返回结构不同。在接口层把消息/参数统一成内部格式，业务无感。

4. 实现多家

多数国产/本地模型兼容 OpenAI 协议，只需换 baseURL 与模型名即可复用同一实现：

// openaiCompatible.js
import OpenAI from 'openai';
export class CompatibleProvider extends LLMProvider {
  constructor({ baseURL, apiKey, model }) {
    super(); this.model = model;
    this.c = new OpenAI({ baseURL, apiKey });
  }
  async chat(messages, opts) {
    const r = await this.c.chat.completions.create({ model: this.model, messages, ...opts });
    return r.choices[0].message.content;
  }
  async *stream(messages, opts) {
    const s = await this.c.chat.completions.create({ model: this.model, messages, stream: true, ...opts });
    for await (const c of s) yield c.choices[0]?.delta?.content || '';
  }
}
// OpenAI / DeepSeek / 智谱 / 本地 Ollama 都可用此类，仅配置不同

5. 工厂与配置

function createLLM() {
  const name = process.env.LLM_PROVIDER || 'openai';
  switch (name) {
    case 'openai':  return new CompatibleProvider({ baseURL:'https://api.openai.com/v1', apiKey: process.env.OPENAI_KEY, model:'gpt-4o-mini' });
    case 'deepseek':return new CompatibleProvider({ baseURL:'https://api.deepseek.com/v1', apiKey: process.env.DEEPSEEK_KEY, model:'deepseek-chat' });
    case 'local':   return new CompatibleProvider({ baseURL:'http://localhost:11434/v1', apiKey:'ollama', model:'qwen2.5' });
    default: throw new Error('未知供应商');
  }
}

6. 降级容灾

资深：一家限流/超时，自动切备胎。可用“主+备”列表 + 简单熔断器（连续失败 N 次暂时跳过该家）。
async function chatWithFallback(messages, providers) {
  for (const p of providers) {
    try { return await p.chat(messages); }
    catch (e) { console.warn('供应商失败，切换:', e.message); }
  }
  throw new Error('全部供应商不可用');
}

7. 缓存与可观测

  • 缓存：相同 prompt 的确定性回答可缓存（尤其分类/抽取），降成本降延迟。
  • 可观测：记录每次调用的供应商、模型、token 用量、耗时、错误，便于成本与质量监控。

8. 常见坑

坑 1：只抽象 chat 漏了 stream/embed → 切换时发现不兼容；接口要覆盖常用能力。
坑 2：没归一化消息格式 → 切厂商要改业务；在适配层统一。
坑 3：一家超时直接 500 → 加超时+降级。
坑 4：Key 写死 → 失去抽象意义；配置化/环境变量。
