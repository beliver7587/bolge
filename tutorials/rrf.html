RRF：从小白到资深

倒数排名融合（RRF）把多个检索结果列表按“排名”而非“分数”合并——巧妙规避了不同算法分数尺度不一致的问题。它是 RAG 混合检索的关键一步。本教程讲透排名融合原理、实现要点、参数与变体、与重排配合及评估。

1. 它解决什么问题

多种检索（BM25、向量、重排）返回的是不同尺度的分数：BM25 可能 9.3、向量 0.81、rerank 0.002。直接加权相加会被某一“数值大”的路压倒。RRF 不看分数，只看“排第几”。

一句话：RRF 把“BM25 第3、向量第1”这样的名次，转成可相加的融合分——鲁棒地取长补短。

2. 工程化

RRF 是无依赖的纯函数，几十行就能实现，常放检索服务里：

// lists: 每个是已排序的 id 数组（名次从 1 开始）
function rrf(lists, k = 60) {
  const score = new Map();
  for (const list of lists) {
    list.forEach((id, i) => {
      score.set(id, (score.get(id) || 0) + 1 / (k + i + 1));
    });
  }
  return [...score.entries()].sort((a, b) => b[1] - a[1]);
}

3. 融合公式

RRF_score(d) = Σ_L 1 / (k + rank_L(d)) k 常数（常取 60） rank_L(d) 是文档 d 在列表 L 中的名次（第1名=1） 最终按 RRF 总分降序输出

名次越靠前（rank 小），贡献越大且递减平缓；k 越大，排名差距被“压平”，越偏向多路都靠前的项。

4. 为什么用排名而非分数

  • 尺度无关：无论 BM25 是 0~10 还是向量 0~1，名次都在 1~N，可直接相加。
  • 鲁棒：不敏感于各算法的分数分布/异常值；即使某路分数“虚高”也不致独大。
  • 无训练：不需要学习各路权重，开箱即用。

5. 实现要点

  • 名次从 1 开始；数组下标要 +1。
  • 跨列表去重：同一文档在 BM25 和向量都出现，分数应累加——用 id 做 key 的 Map 天然合并。
  • 空列表处理：某路无结果时跳过，别让空数组污染。

6. 参数与变体

  • k：太小（如 1）让第 1 名压倒一切，丧失融合意义；太大则各名次差异被抹平。常用 10~60。
  • 加权 RRF：若某路更可信，可乘权重 w_L / (k + rank)。
  • 对比 min-max 归一化：把各路分数归一到 [0,1] 再加权——但需各路分数分布稳定，否则不如 RRF 稳。

7. 在 RAG 中的位置

典型链路：多路召回（BM25 + 向量）→ RRF 粗融取 Top-20 → rerank 精排取 Top-5 → 送大模型。RRF 负责“广撒网合并”，rerank 负责“精中选精”。

const fused = rrf([bm25Top20, vecTop20], 60);
const reranked = await reranker.rerank(q, fused.slice(0, 20), 5);

8. 评估

融合是否真有效，用评测集量化：对比“单路”与“RRF 融合”的 Recall@K / nDCG@K。多数情况下融合优于任一路，尤其查询类型多样时。

9. 常见坑

坑 1：直接把不同算法原始分相加 → 尺度不一，某路独大；用排名。
坑 2：k 太小 → 第 1 名压倒一切，融合无意义；常用 60。
坑 3：各路窗口不一致（一路 1000、一路 20） → 稀释融合；取相同较小窗口（20~50）。
坑 4：忘去重跨列表 id → 分数错乱。
坑 5：把 RRF 当最终排序 → 它只是粗融，质量不够，仍需 rerank。

10. 调试

  • 打印融合前后每个文档的 RRF 分与各路名次，确认“两路都靠前”的项被推高。
  • 调 k 观察 topK 变化，选 Recall@K 最优。
