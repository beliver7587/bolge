MyBatis-Plus：从小白到资深后端

MyBatis-Plus（MP）是国内 Java 后端的持久层事实标准：在 MyBatis 之上提供通用 Mapper/Service，单表 CRUD 零 SQL，复杂查询仍由你掌控。本教程讲透通用 Mapper 原理、Lambda 条件构造、逻辑删除/乐观锁/多租户插件、代码生成与性能优化。

1. 它解决什么问题

原生 MyBatis 每个表都要写 Mapper 接口 + XML + SQL，单表 CRUD 大量重复。MP 在 MyBatis 之上注入“通用方法”，单表操作开箱即用，同时保留 XML/注解写复杂 SQL 的能力。

一句话：MyBatis 让你“完全手写 SQL”；MP 把“通用 CRUD”默认实现好，复杂 SQL 你再补——既省事又不失灵活。
适合：管理后台、表单多的业务（单表操作占多数）。
不适合：极致复杂动态 SQL 且团队已熟练手写——但 MP 仍可 coexist。

2. 工程化起步

<dependency>
  <groupId>com.baomidou</groupId>
  <artifactId>mybatis-plus-spring-boot3-starter</artifactId>  <!-- Spring Boot 3 用此 starter -->
  <version>3.5.7</version>
</dependency>

在 Spring Boot 启动类加 @MapperScan("com.example.demo.mapper") 扫描 Mapper 接口；配置 mybatis-plus.mapper-locations 指向 XML（如有）。

3. 核心机制

@TableName("user")
public class User {
  @TableId(type = IdType.AUTO) private Long id;
  @TableField("user_name")     private String name;   // 列名映射
  @TableLogic                 private Integer deleted; // 逻辑删除
  @Version                     private Integer version; // 乐观锁
}
  • BaseMapper<T>：注入通用 CRUD（insert/selectById/updateById/delete...），无需写 XML。
  • IService<T> + ServiceImpl：再包一层业务通用方法（批量、链式）。
  • 注解：@TableName/@TableId/@TableField 做对象-表映射；@TableField(fill=...) 配自动填充（如 create_time）。
  • 主键策略：IdType.AUTO（数据库自增）/ ASSIGN_ID（雪花算法，分布式推荐）。

4. CRUD 与分页

userMapper.insert(user);
userMapper.selectById(1L);
userMapper.selectPage(new Page<>(1, 10), null);  // 分页

@Bean
public MybatisPlusInterceptor mpInterceptor() {
  var i = new MybatisPlusInterceptor();
  i.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL)); // 分页插件必加
  return i;
}
坑：不注册分页插件，selectPage 会返回全部而非分页。

5. 条件构造器

// 推荐 Lambda 形式：字段名用方法引用，重构安全、防拼错
LambdaQueryWrapper<User> w = new LambdaQueryWrapper<>();
w.gt(User::getAge, 18).like(User::getName, "王").orderByDesc(User::getId);
userMapper.selectList(w);
  • 优先 LambdaQueryWrapper（编译期检查字段），少用字符串 QueryWrapper（字段名写错无感知）。
  • 条件值来自用户输入时，MP 用预编译参数绑定，不易 SQL 注入；但别用 last("...") 拼用户输入。

6. 代码生成器

用 AutoGenerator + 模板，连上数据库一键生成 Entity/Mapper/Service/Controller，省去样板。逆向工程对中后台极提效，但要生成后人工核对字段与业务。

7. 企业插件

  • 逻辑删除 @TableLogic：删除变 UPDATE 置 deleted=1，查询自动带条件——数据不物理丢失，合规友好。
  • 乐观锁 @Version：更新时带版本号，并发修改冲突则失败重试，避免丢失更新。
  • 多租户：TenantLineInnerInterceptor 自动给查询加租户 ID 条件，SaaS 隔离利器。

8. 性能与优化

  • 只查所需列：select(User::getId, User::getName) 避免 select *。
  • 批量：用 saveBatch 而非循环 insert；调大 rewriteBatchedStatements=true（MySQL）走真批量。
  • 大分页：深翻页用“游标/延迟游标”或按 ID 分段，避免 limit 1000000,10 全表扫描。
  • N+1：关联查询用 leftJoin/一次批量查，而非循环中单查。

9. 与 JPA 对比

MyBatis-PlusSpring Data JPA
SQL 掌控强（可手写）弱（自动生成）
学习/上手中低
复杂查询灵活受限（需 Specification）
国内生态极好一般
选型：要 SQL 可控、国内协作 → MP；要开发极快、跨库、少写 SQL → JPA。两者都能与 Spring Boot 无缝集成。

10. 常见坑

坑 1：忘了 @MapperScan → 启动找不到 Mapper Bean。
坑 2：字段名与列名不一致导致 null → 用 @TableField 映射。
坑 3：主键自增未标 IdType.AUTO → 插入报错。
坑 4：分页插件漏配 → 不分页。
坑 5：逻辑删除字段 + 唯一索引冲突（deleted 相同导致唯一键重复）→ 唯一索引要含租户/删除标记。
坑 6：用 last() 拼接用户输入 → SQL 注入。

11. 调试

  • 开 mybatis-plus.configuration.log-impl=StdOutImpl 看实际 SQL 与参数。
  • p6spy 打印带参数的完整 SQL，定位慢查询。

12. 成长路线

阶段能力标志
小白会用 Mapper 做 CRUD、分页
初级Lambda 条件、字段映射
中级逻辑删除/乐观锁/多租户、代码生成
资深性能调优、复杂 SQL 设计、插件扩展、选型有据
练习：① 用 MP 写用户管理 CRUD + 分页 ② 用 LambdaQueryWrapper 做多条件搜索 ③ 加逻辑删除与乐观锁并处理并发更新 ④ 用 p6spy 观察一条分页 SQL。
你已进阶：理解“通用 Mapper 省去样板、复杂 SQL 仍归你管”的平衡，能设计高性能、可审计的持久层——这是资深 Java 后端的核心能力。
