uni-app：从小白到跨端开发

uni-app 用 Vue 语法一套代码发布到 H5、微信/支付宝小程序、App（iOS/Android）。本教程讲清它怎么消弭多端差异、配置怎么写、以及跨端开发的真实取舍。

1. 它解决什么问题

同一业务要维护 Web、微信小程序、App 三套代码，人力三倍。uni-app 让你的 Vue 代码“编译”到各端运行时，大幅复用。

一句话：uni-app = Vue 语法 + 跨端编译 + 统一 API。写一次，发多端。
适合：需要同时覆盖 H5/小程序/App 的业务。不适合：只做 Web 的项目（直接用 Vue 更轻，何必跨端抽象）。

2. 工程化起步

npx degit dcloudio/uni-preset-vue#vite-ts myapp
cd myapp && pnpm i
# 用 HBuilderX 或 CLI 运行到各端

底层可走 Vite，开发体验和 Vue 项目一致。

3. 语法

基本就是 Vue 3：<script setup>、ref/reactive、模板指令通用。只是要把浏览器专属 API 换成 uni 的跨端 API。

<template><view class="card">{{ msg }}</view></template>
<script setup>const msg = ref('hi')</script>
注意：标签用 <view> 而非 <div>（小程序无 div），uni 会按端映射。

4. 页面与路由

路由在 pages.json 里声明：

{
  "pages": [
    { "path": "pages/index/index", "style": { "navigationBarTitleText": "首页" } }
  ],
  "tabBar": { "list": [ { "pagePath": "pages/index/index", "text": "首页" } ] }
}
  • 页面即文件夹，新增页要在 pages 注册。
  • 跳转用 uni.navigateTo，替代 router.push。

5. 生命周期

  • 组件生命周期同 Vue（onMounted 等）。
  • 页面级多了 onLoad/onShow/onPullDownRefresh 等，对应小程序规范。

6. 跨端 API

uni.request({ url, success: (res) => {} });   // 替代 fetch（小程序无 fetch）
uni.showToast({ title: 'ok' });                  // 替代 alert
统一：网络、存储、导航、弹窗都走 uni.*，uni 负责按端翻译成对应实现。

7. 条件编译

端差异用注释条件编译隔离：

// #ifdef MP-WEIXIN
console.log('只在微信小程序执行');
// #endif
// #ifdef H5
console.log('只在 H5 执行');
// #endif

8. 状态管理

可用 Pinia（见 状态管理 思路，Vue 版即 Pinia）或 Vuex 管理全局状态，跨端通用。

9. 打包发行

  • H5：编译成普通 Web 包。
  • 小程序：编译成各平台小程序代码，再进各自开发者工具上传。
  • App：云打包或本地打包成 iOS/Android 安装包。

10. 与 Vue

uni-app 的语法是 Vue 的子集/超集：会 Vue 3 几乎零成本上手，只是要避开浏览器专属 API 与 DOM 操作（小程序没有 DOM）。

11. 常见坑

坑 1 DOM 操作：小程序无 DOM，document.querySelector 不可用，要用 ref/data 驱动。
坑 2 平台差异：某端特有 API 必须条件编译，否则其它端报错。
坑 3 体积：App 端引入大 SDK 会显著增大包体，按需引入。

12. 资源与路线

  1. 官方 uni-app 文档。
  2. 先学 Vue 3 与 Vite。
  3. 练：做一个能跑在 H5 和小程序的待办，体验条件编译。
资深标志：能清晰划分“跨端共用逻辑”与“端差异代码”，用条件编译把平台耦合降到最低，而不是满屏 ifdef。
