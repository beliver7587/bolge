HTML：从小白到资深前端

HTML 是网页的结构语言，是一切前端的根。CSS 管样子、JS 管行为，但“内容是什么”由 HTML 决定。本教程从“会写标签”讲到“语义化、可访问性、SEO、现代 API”——这是资深前端对结构与质量的理解。

1. 它解决什么问题

没有 HTML，浏览器不知道哪段是标题、哪段是导航、哪段是按钮。HTML 用标签描述内容的“含义（语义）”，而不是“长什么样”。

一句话：HTML 给内容打上语义，浏览器、搜索引擎、屏幕阅读器、CSS/JS 才能正确理解并正确处理它。
资深视角：“结构正确”比“样式漂亮”更基础。语义错的页面，SEO 差、读屏软件瞎、可维护性烂——这三类问题根源常在 HTML。

2. 文档结构与元数据

<!DOCTYPE html>                       <!-- 声明 HTML5 -->
<html lang="zh-CN">                      <!-- lang 利于 SEO 与读屏 -->
<head>
  <meta charset="UTF-8">                 <!-- 字符编码，必须最前 -->
  <meta name="viewport" content="width=device-width, initial-scale=1"> <!-- 移动端适配 -->
  <title>页面标题</title>                 <!-- 搜索引擎结果里展示 -->
  <meta name="description" content="一句话描述"> <!-- SEO 摘要 -->
</head>
<body> ... </body>
</html>
坑：忘写 lang、viewport 或把 charset 放后面，会导致乱码或移动端缩放异常。

3. 语义化标签

用“有含义”的标签替代一堆 <div>：

<header>顶部</header>
<nav>导航</nav>
<main>
  <article>一篇独立内容</article>
  <section>主题区块</section>
</main>
<aside>侧边</aside>
<footer>底部</footer>
  • 好处：SEO 能识别结构、屏幕阅读器有“地标导航”、CSS/JS 选择更稳、代码自解释。
  • 何时用 div：纯粹为了样式分组、无语义含义时，才用 <div>。

4. 文本与媒体

  • 标题 h1~h6 体现层级（每页一个 h1）。
  • 列表 ul/ol/li、强调 strong/em（别用 b/i，那是纯样式）。
  • 图片 <img alt="描述">：alt 是给读屏和加载失败看的，必填。
  • 响应式图 <picture> + srcset：按屏幕密度/宽度出不同图。
  • 视频 <video controls>、用 <figure><figcaption> 配图注。

5. 表单

表单是用户“把数据交给服务器”的入口，语义与无障碍尤其重要。

<form action="/submit" method="post">
  <label for="email">邮箱</label>
  <input id="email" name="email" type="email" required
         autocomplete="email" placeholder="you@example.com">
  <button type="submit">提交</button>
</form>
  • label for 与 input id 关联，点击文字也能聚焦、读屏能播报名。
  • 原生校验属性 required/type=email/min/max/pattern，不写 JS 也能拦。
  • autocomplete 提升体验与转化。
资深：表单语义正确 = 可访问 + 移动端友好 + 校验省事。后端仍要再用 zod/服务端校验（前端校验只是便利，不可信）。

6. 表格

<table>
  <thead><tr><th scope="col">名称</th></tr></thead>
  <tbody><tr><td>项目A</td></tr></tbody>
</table>

scope="col/row" 让读屏知道表头对应关系；表格只用于“表格数据”，勿用于布局（布局用 CSS Grid/Flex）。

7. 链接与导航

  • <a href="https://x.com" target="_blank" rel="noopener noreferrer">：开新窗要 rel 防 window.opener 钓鱼。
  • 导航用 <nav><ul><li><a>，可读屏“跳到导航”。
  • href="#id" 做页内锚点。

8. 可访问性 a11y

  • 所有可交互元素用原生 <button>/<a>，别用 div 假按钮（无键盘、无读屏）。
  • 图片 alt、表单 label、用 aria-* 补充复杂组件语义。
  • 颜色对比度达标、支持键盘操作、焦点可见。
  • 地标标签（header/nav/main/footer）帮读屏用户快速跳转。
坑：用 <div onclick> 当按钮——键盘 Tab 不到、回车不触发、读屏不识别。这是高频可访问性事故。

9. SEO 基础

  • 语义标签让爬虫理解结构；title/description 影响展示。
  • 开放图谱 og:* 控制分享卡片；canonical 避免重复页。
  • 结构化数据（JSON-LD）帮搜索引擎出富结果。
  • 配合 Next.js 做 SSR/SSG，内容才对爬虫可见。

10. 现代 HTML5 API

  • <dialog>：原生模态框，自带焦点管理与 Esc 关闭。
  • <details>/<summary>：原生折叠，无需 JS。
  • <template>：存放不渲染的模板，JS 克隆用。
  • Web Components：customElements + Shadow DOM，做框架无关的组件（了解即可，日常多用框架）。

11. 常见坑

坑 1：满屏 <div> 无语义，SEO/a11y 全废。
坑 2：图片没 alt，读屏读“图片”、加载失败无提示。
坑 3：<div onclick> 当按钮，键盘不可达。
坑 4：表单 <input> 无 label 关联，用户不知道填什么。
坑 5：用表格做页面布局，语义错乱、响应式难做。
坑 6：只信前端校验，后端没校验 → 脏数据/安全漏洞。

12. 调试与校验

  • 浏览器 DevTools Elements 面板看真实 DOM 结构。
  • W3C HTML 校验器查语法错误。
  • Lighthouse 跑可访问性/SEO 评分。

13. 成长路线

阶段能力标志
小白会写标题/段落/图片/链接
初级会表单、表格、基本布局结构
中级语义化、可访问性、SEO 意识
资深用结构保障质量（a11y/SEO/可维护）、懂现代 API 取舍
练习：① 把一个 div 堆砌的页面重构成语义化结构 ② 写一份带 label/校验的注册表单 ③ 用 Lighthouse 给现有页打 a11y 分并修到 90+ ④ 用 <picture> 做响应式图。
你已进阶：理解“结构即质量”——语义、可访问、可被检索，这是资深前端对 HTML 的基本功。
