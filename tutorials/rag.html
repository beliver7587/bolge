RAG 检索增强生成

让 AI“开卷考试”而不是“闭卷” —— 解决幻觉与知识截止。

1. 这是什么

RAG = Retrieval-Augmented Generation（检索增强生成）。一句话：在让大模型回答前，先去“资料库”里翻出最相关的几段，贴到问题旁边，再让模型基于这些资料作答并标注出处。相当于让 AI 开卷考试。

2. 为什么需要它

闭卷（纯大模型）开卷（RAG）
只靠记忆答，遇公司规定/最新政策就瞎编（幻觉）现查现答，有据可依
不知道你公司的内部信息你给什么资料它就懂什么
答案不可溯源带 [1][2] 引用，可查出处

3. RAG 四步

用户提问 → ① 把问题向量化（见 Embedding） → ② 在知识库找语义最相近的片段（向量检索） → ③ 把“问题 + 检索片段”拼成提示词 → ④ 模型基于片段生成答案，标注出处

4. 分块与混合检索

  • 分块：文档太大先切小块（如 180 字）去检索，命中小块再返回所属大块（700 字）给模型读，叫 Small-to-Big。
  • 混合检索：向量（懂语义）+ BM25（精确词）两路召回，用 RRF 融合，取长补短。

5. 常见坑

坑 1：把整本文档塞进提示词，成本和噪声爆炸——要“精准召回 Top-5”。
坑 2：检索到的资料被投毒（含恶意指令），要加 提示注入防护。
坑 3：向量接口挂了就 500——做好降级到 BM25（Memora 实测）。
