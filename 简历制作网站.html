0.5小白术语扫盲（必读，5 分钟）

看不懂下面任何一个词，先读完这一节再继续

① 服务器 / 云服务器 是什么？

就是一台"一直开着、有公网 IP、你能远程登录"的电脑，放在机房里。阿里云/腾讯云/华为云 等厂商按小时或按月出租。本项目就部署在这么一台机器上，对外提供网站服务。

② 公网 IP / 域名 / DNS

  • 公网 IP：服务器在互联网上的"门牌号"，形如 49.235.163.168。别人在浏览器输入这个 IP 就能访问你的服务器（前提是开了 80/443 端口）。
  • 域名：人能记住的地址，如 jianli.wylab.asia。它最终会被解析（DNS）到上面那个 IP。
  • DNS 解析（A 记录）：在域名控制台把域名指向服务器 IP。解析后，浏览器输入域名就等于输入 IP。

③ SSH 是什么？怎么连？

SSH 是一种"远程登录服务器"的安全协议。你在自己电脑上敲命令，命令其实是在服务器上执行的。连接方式：

  • Windows 用户：推荐装 Termius 或直接使用 PowerShell / CMD（Win10+ 自带 ssh 命令）。也可以用 Putty。
  • Mac / Linux 用户：直接用系统自带终端 Terminal。
# 在你的个人电脑（不是服务器）上执行：
ssh ubuntu@49.235.163.168
# 含义：以 ubuntu 这个用户名，登录到 IP 为 49.235.163.168 的机器
# 第一次会问是否信任，输入 yes；然后输入密码。

⑤ 端口 是什么？

一台服务器上可以跑很多程序，用端口号区分它们。比如：

  • 网站默认 80（http）、443（https）
  • 本项目后端 8081、前端 4000、MySQL 3306、Redis 6379

浏览器访问网站只认 80/443（默认不写端口）。所以我们要用 Nginx 把 80/443 转发到 4000/8081，让用户只访问 80/443 就能用到内部服务——这就是"反向代理"，第 5 章细讲。

⑥ 前后端分离 是什么？

本项目其实有 两个程序：

  • 前端（Next.js，跑在 4000 端口）：负责页面、按钮、填表、预览——用户"看得到"的部分。
  • 后端（Spring Boot，跑在 8081 端口）：负责数据库读写、登录鉴权、AI 调用——用户"看不见"但真正干活的"大脑"。

前端和后端通过 HTTP 接口（API） 说话：前端说"我要保存这段简历"，后端就写数据库。本项目里这些接口都挂在 /api 路径下。

⑦ 反向代理 / Nginx / HTTPS / systemd

这些第 4、5 章会手把手用到，这里先给一句定义：

  • Nginx：一个高性能的"门面"程序，本课用它把 80/443 的请求分发给前端/后端，并负责 HTTPS。
  • 反向代理：Nginx 站在前面替用户找后端，用户无感知。
  • HTTPS：给网站加 SSL 证书，地址栏出现小锁，数据加密传输。
  • systemd：Linux 的"服务管理器"，让后端/前端开机自动启动、崩溃自动重启。

1项目概览

是什么 · 架构图 · 技术栈 · 数据模型

简历工坊是一个「在线简历制作与分享平台」：用户注册登录后，用模板快速创建简历，在编辑器里分模块填写/拖拽排序/自定义主题与分栏布局，调用大模型（通义千问 qwen-plus）一键润色，导出 PDF，并生成只读分享链接。还包含模板广场、管理员后台、导入（文本/Word/PDF/图片 OCR 识别成简历）。

对个人项目而言，它覆盖了前后端分离、JWT 鉴权、文件上传、AI 集成、富交互编辑器、PDF 生成、反向代理与 HTTPS、服务器部署等最常被追问的点，是很好的「全栈 + DevOps」故事载体。

2.2一次「打开简历并保存」的请求流转

1) 浏览器 GET https://jianli.wylab.asia/resumes
       └─ Nginx 命中 location /  → 前端 :4000 (Next.js 返回 HTML/JS)
2) 前端 JS 发 GET /api/resume/list   (注意：/api 同源，浏览器无感知跨域)
       └─ Nginx 命中 location /api/ → 后端 :8081
3) 后端查 MySQL → 返回简历列表 JSON → 前端渲染卡片
4) 用户点击进入编辑器 → GET /api/resume/{id}
       └─ 后端聚合 resume_basic + 各模块子表 → 一个 ResumeContent 对象
5) 用户改内容 → 前端 Zustand 标记 dirty → 1.2s 后自动 PUT /api/resume/{id}/save
       └─ 后端把各模块"upsert"进对应子表（一次保存多个模块）

重点：/api 与页面同源（都在同一个域名下），所以前端 axios 的 baseURL:"/api" 是相对路径，浏览器不会触发跨域。

2.6项目的难点与亮点

  • 难点① 编辑器实时预览 + 模块拖拽 + 分栏布局：用 Zustand 维护一份草稿，分页线用 ResizeObserver 按 A4 比例动态画"第 N 页"分隔线。
  • 难点② AI 润色不编造事实：prompt 约束"只润色表达、不虚构数据"，且不覆盖用户未改的字段。
  • 难点③ 小内存服务器 OOM 治理：1.6GB 内存跑 next build 必 OOM，靠加 2GB swap 解决。
  • 亮点① 全链路同源部署：Nginx 统一入口，前后端同域，规避跨域与证书复杂度。
  • 亮点② 模板广场 + 分享 + 导入：形成"创建→美化→分享→复用模板"的闭环。

3.1后端实现（Spring Boot + MyBatis-Plus）

后端是一个标准 Spring Boot 应用，打成 app.jar 运行在 8081 端口，统一上下文路径 /api。配置几乎全部通过环境变量注入（12 因子原则），便于在不同服务器无缝迁移。

3.1.1配置：环境化、可移植（application.yml）

server:
  port: 8081
  servlet:
    context-path: /api          # 所有接口前缀 /api
spring:
  datasource:
    url: jdbc:mysql://${DB_HOST:localhost}:${DB_PORT:3306}/${DB_NAME:resume_platform}?...
    username: ${DB_USER:root}
    password: ${DB_PASSWORD:password}
  data:
    redis:
      host: ${REDIS_HOST:127.0.0.1}
      port: ${REDIS_PORT:6379}
  servlet:
    multipart:
      max-file-size: 20MB        # 文件上传上限
      max-request-size: 20MB
mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true
  global-config:
    db-config:
      logic-delete-field: isDeleted   # 全局逻辑删除
      logic-delete-value: 1
      logic-not-delete-value: 0
jwt:
  secret: ${JWT_SECRET:}              # 无默认值，缺失则拒绝启动
  access-expire: 7200                 # access token 2h
  refresh-expire: 604800              # refresh token 7d
ai:
  enabled: ${AI_ENABLED:true}
  base-url: ${AI_BASE_URL:https://dashscope.aliyuncs.com/compatible-mode/v1}
  api-key: ${AI_API_KEY:}
  model: ${AI_MODEL:qwen-plus}
app:
  upload:
    dir: /opt/resume-platform/uploads  # 上传文件落盘位置
    url-prefix: /uploads
逐行解释：
  • server.port: 8081：后端监听 8081 端口（前面说的前端是 4000，互不冲突）。
  • context-path: /api：所有接口自动带 /api 前缀，例如登录接口实际是 /api/auth/login。这点对 Nginx 反代至关重要（见 4.9、5.3）。
  • ${DB_HOST:localhost}：环境变量占位写法。意思是"如果系统里有 DB_HOST 这个环境变量就用它，否则用默认值 localhost"。这就是"配置环境化"——同一份 jar，改环境变量就能换数据库，不用改代码重新打包。
  • max-file-size: 20MB：允许上传最大 20MB 文件，超过会报错。
  • logic-delete-field: isDeleted：声明"逻辑删除字段叫 isDeleted"，MyBatis-Plus 会自动在查询时过滤、删除时改标记。
  • jwt.secret: ${JWT_SECRET:}：注意冒号后没有默认值。意味着"必须提供 JWT_SECRET 环境变量，否则启动失败"——防止开发者忘记设密钥。
  • ai.base-url：通义千问的 OpenAI 兼容接口地址；compatible-mode 让我们可以用 OpenAI 的 SDK 直接调用国产大模型。

3.1.2鉴权：JWT 双令牌

流程：登录成功后签发 access token（2h） + refresh token（7d）。access 短时有效，被盗损失小；过期后用 refresh 换新。refresh token 落库 refresh_token 表，可主动吊销。

// 前端拿到的数据结构（TokenVO）
{ accessToken, refreshToken, userId, username, nickname }

3.2.1接口层 + 双令牌自动刷新（services/api.ts）

用 axios 实例，baseURL:"/api"（同源相对路径）；请求拦截器注入 Bearer；响应拦截器在 401 时用 refresh token 自动换新并重放原请求。

const api = axios.create({ baseURL: "/api", timeout: 15000 });

api.interceptors.request.use((config) => {
  const token = getToken();                 // localStorage 取 access
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

let refreshing = false;
let pending = [];
api.interceptors.response.use(
  (resp) => resp,
  async (error) => {
    const original = error.config;
    if (error.response?.status === 401 && !original._retry) {
      const rt = getRefreshToken();
      if (rt && !refreshing) {
        refreshing = true; original._retry = true;
        const { data } = await axios.post("/api/auth/refresh", { refreshToken: rt });
        setTokens(data.data.accessToken, data.data.refreshToken);
        pending.forEach(cb => cb(data.data.accessToken)); pending = [];
        refreshing = false;
        original.headers.Authorization = `Bearer ${data.data.accessToken}`;
        return api(original);               // 重放原请求
      }
      clearTokens(); location.href = "/login";
    }
    return Promise.reject(error);
  }
);
这段代码在做什么（逐段）：
  • axios.create({ baseURL: "/api" })：创建一个"专用请求器"，之后所有请求都不用写完整域名，只写 /auth/login 即可，它会自动拼成 当前域名/api/auth/login。这就是同源部署的优势。
  • request 拦截器：每次发请求前自动把 access token 塞进请求头 Authorization: Bearer xxx，后端据此知道"你是谁"。
  • response 拦截器：当后端返回 401（未授权/过期） 时，自动拿 refresh token 去换新 access，换到后把刚才失败的那个请求重发一次。用户完全无感。
  • refreshing / pending：如果同一瞬间有 10 个请求都 401，只让第一个去刷新，其余 9 个排队等结果，避免把 refresh token 用废。

3.2.3编辑器：实时预览 + 自动保存 + 模块排序（app/editor/[id]/page.tsx）

核心是一个 Zustand 草稿 store（store/editor.ts），编辑任意字段都置 dirty=true；监听 dirty 后 防抖 1.2s 自动 PUT 保存。

// 自动保存（防抖）
useEffect(() => {
  if (dirty && loaded) {
    if (saveTimer.current) clearTimeout(saveTimer.current);
    saveTimer.current = setTimeout(save, 1200);   // 1.2s 后落库
  }
}, [dirty, loaded, save]);

// 模块顺序：单列用 moduleOrder 数组，basic 固定首位
const moveModule = (key, dir) => {
  const order = [...(content.moduleOrder || DEFAULT_MODULE_ORDER)];
  const i = order.indexOf(key), j = i + dir;
  if (i < 0 || j < 0 || j >= order.length) return;
  if (order[j] === "basic" || order[i] === "basic") return;
  [order[i], order[j]] = [order[j], order[i]];     // 交换
  setModuleOrder(order);
};
防抖（debounce）是什么？ 你打字很快，如果每敲一个字就保存一次，服务器会疯掉。防抖的意思是"你停止打字 1.2 秒后，我才保存一次"。setTimeout(save, 1200) 就是 1.2 秒计时器；你又打字时 clearTimeout 把它清掉重新计时。这就是"自动保存"的精髓。

useEffect(() => {

4.3勘察环境（看清楚这台机器有什么）

# 系统/资源/已装组件
cat /etc/os-release | head -3
nproc                      # CPU 核数
free -h                    # 内存（看 total 那列）
df -h /                    # 磁盘还剩多少
swapon --show || echo NO_SWAP     # 有没有 swap（没有会显示 NO_SWAP）
for b in node npm java mysql redis-server nginx certbot; do
  command -v $b || echo "MISSING: $b"     # 逐个检查这些程序装了没
done
  • cat /etc/os-release | head -3：cat 打印文件内容，| 把结果交给 head -3 只取前 3 行，用来确认系统版本。
  • free -h：-h 是"人类可读"（GB/MB）。看 Mem 那行的 total 知道内存多大。
  • swapon --show：显示已启用的 swap。如果提示没有，说明没配 swap（小内存机器必配，见 4.4）。
  • for b in ... ; do command -v $b || echo "MISSING: $b"; done：一个 Shell 循环，依次检查 node/npm/java/mysql... 有没有安装。装了的会打印路径，没装的会打印 MISSING: xxx。
真实踩坑：旧服务器只有 1.6GB 内存且无 swap，跑 next build 直接 OOM 卡死。新服务器 3.6GB + 已带 2GB swap 才稳。所以小内存机器务必加 swap。

4.4初始化：装依赖 + 加 swap（逐命令解释）

# 1) 用非交互模式安装，避免安装 MySQL 时卡在密码提示
export DEBIAN_FRONTEND=noninteractive

# 2) 更新软件源 + 安装所需程序
sudo apt-get update
sudo apt-get install -y mysql-server redis-server default-jre \
                        certbot python3-certbot-nginx

# 3) 加 2GB swap（根因治理：防 OOM）
sudo fallocate -l 2G /swapfile      # 划出 2GB 空间当 swap 文件
sudo chmod 600 /swapfile            # 只有 root 能读写（安全）
sudo mkswap /swapfile               # 把它格式化成 swap
sudo swapon /swapfile               # 立即启用
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab   # 写进 fstab，开机自动启用

# 4) 安装 Node 22（前端要求，与开发环境一致）
cd /tmp
sudo curl -fsSL https://nodejs.org/dist/v22.18.0/node-v22.18.0-linux-x64.tar.xz -o node22.tar.xz
sudo tar -xJf node22.tar.xz -C /opt          # 落地到 /opt/node-v22.18.0-linux-x64
/opt/node-v22.18.0-linux-x64/bin/node -v      # 校验版本，应输出 v22.18.0
  • export DEBIAN_FRONTEND=noninteractive：告诉 apt"别弹交互式问询（比如让你输 MySQL root 密码）"，否则脚本会卡住等你输入。
  • sudo apt-get update：刷新软件列表，相当于"看看仓库里有什么新版本"。
  • sudo apt-get install -y 包名：-y 表示"全部选 yes 直接装"。装了 MySQL（数据库）、Redis（缓存）、JRE（跑 Java 用，注意只要 JRE 不要 JDK，因为只运行不编译）、certbot（申请证书）。
  • fallocate -l 2G /swapfile：fallocate 快速分配 2GB 文件；-l 2G 指定大小。swap 是"用磁盘当内存"，内存不够时系统把不常用的数据暂存到它，防止程序因内存不足被杀死（OOM）。
  • chmod 600：把权限设为"仅 owner 可读写"，避免别人读 swap 里的敏感数据。
  • echo '...' | sudo tee -a /etc/fstab：把一行配置追加到 /etc/fstab（开机自动挂载文件）。tee -a 是"边显示边追加写入"，加 sudo 是因为 fstab 只有 root 能改。
  • 为什么 Node 用 tar 包而不是 apt install nodejs？Ubuntu 自带源版本偏旧；用官方二进制最稳妥，路径明确为 /opt/node-v22.18.0-linux-x64/bin/。

4.5数据库：启动 / 建库 / 建用户（逐 SQL 解释）

MySQL 装好后需要：① 确保它在运行；② 建一个专用于本项目的数据库；③ 建一个专用账号（不要用 root 跑业务）。

# 确保 MySQL 运行并开机自启
sudo systemctl enable --now mysql

# 以 root 登录 MySQL（刚装好本地 root 通常用 unix socket 免密）
sudo mysql

# 进入 MySQL 交互界面后，依次执行下面这些 SQL：
CREATE DATABASE IF NOT EXISTS resume_platform CHARACTER SET utf8mb4;
CREATE USER IF NOT EXISTS 'resume_app'@'localhost' IDENTIFIED BY '<强密码>';
GRANT ALL PRIVILEGES ON resume_platform.* TO 'resume_app'@'localhost';
FLUSH PRIVILEGES;
EXIT;
  • systemctl enable --now mysql：enable 让开机自启，--now 表示"现在就启动"。
  • sudo mysql：以 root 进 MySQL 命令行（在 Ubuntu 上刚安装默认允许 root 用系统账户免密登录）。
  • CREATE DATABASE ... CHARACTER SET utf8mb4：建库并指定字符集为 utf8mb4（支持中文和 emoji，避免乱码）。IF NOT EXISTS 表示"没有才建，有就跳过"。
  • CREATE USER 'resume_app'@'localhost'：建一个只能从本机（localhost）登录的数据库用户，密码是 <强密码>（换成你自己的，比如 24 位随机串）。
  • GRANT ALL PRIVILEGES ON resume_platform.*：只把 resume_platform 这一个库的全部权限给 resume_app，不给其它库。这就是"最小权限原则"。
  • FLUSH PRIVILEGES：让权限修改立即生效。
为什么建专用账号而不是用 root？最小权限原则——万一你的项目被攻破、密码泄露，攻击者最多动这一个库，动不了整台机器的数据库。root 一旦泄露，全盘裸奔。

4.7部署后端（systemd 逐行解释）

# 1) 把 jar 放到运行目录，并建立 uploads 目录
sudo mkdir -p /opt/resume-platform/uploads
sudo mv /tmp/app.jar /opt/resume-platform/app.jar

# 2) 写 systemd 服务文件（这是"让后端开机自启+崩溃重启"的关键）
sudo tee /etc/systemd/system/resume-platform.service <'EOF'
[Unit]
Description=Resume Platform Backend
After=network.target mysql.service redis.service
[Service]
Type=simple
User=root
WorkingDirectory=/opt/resume-platform
ExecStart=/usr/bin/java -Xmx512m -Xms256m -jar /opt/resume-platform/app.jar
SuccessExitStatus=143
Environment=DB_HOST=127.0.0.1
Environment=DB_NAME=resume_platform
Environment=DB_USER=resume_app
Environment=DB_PASSWORD=<强密码>
Environment=REDIS_HOST=127.0.0.1
Environment=JWT_SECRET=<≥32字节随机串>
Environment=CORS_ALLOWED_ORIGINS=https://jianli.wylab.asia
Environment=AI_ENABLED=true
Environment=AI_API_KEY=<你的DashScope Key>
Environment=AI_MODEL=qwen-plus
Restart=on-failure
[Install]
WantedBy=multi-user.target
EOF

# 3) 让 systemd 重新加载配置，并启动+设为开机自启
sudo systemctl daemon-reload
sudo systemctl enable --now resume-platform
sleep 8; systemctl is-active resume-platform     # 看是否在运行（应输出 active）
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8081/api/auth/login   # 应返回 405/200 之类，非 000
systemd 服务文件逐行解释：
  • [Unit] Description：服务描述，随便写。
  • After=network.target mysql.service redis.service：声明"等网络和 MySQL、Redis 起来后再启动我"，避免后端先起却连不上数据库。
  • [Service] Type=simple：前台运行模式（java 默认前台跑）。
  • User=root：以 root 身份运行。生产更规范应建专用用户，这里为简化用 root（仅内网/信任环境）。
  • WorkingDirectory：工作目录，相对路径从这里算。
  • ExecStart=...java -Xmx512m -Xms256m -jar app.jar：启动命令。-Xmx512m 限制最大堆内存 512MB，-Xms256m 初始 256MB，防止 Java 吃光内存把系统拖垮。
  • SuccessExitStatus=143：143 是 SIGTERM（停止信号）的退出码，声明它"算正常退出"，否则 systemd 会以为崩溃了。
  • Environment=...：把 3.1.1 里那些 ${DB_HOST} 等占位符在这里真正赋值。这就是"环境化配置"的落地点。
  • Restart=on-failure：进程非正常退出就自动重启——崩溃自愈。
  • [Install] WantedBy=multi-user.target：声明"多用户模式下要启动我"，enable 时才会开机自启。
随机串怎么生成？在服务器上执行 openssl rand -base64 48 即可得到一段足够长的随机密钥，复制到 JWT_SECRET 即可。

4.9配置 Nginx 反向代理（整个 conf 逐行）

sudo tee /etc/nginx/sites-enabled/resume-platform.conf <'EOF'
server {
    listen 80;
    server_name jianli.wylab.asia;          # 只认这个域名的请求
    client_max_body_size 20m;               # 允许上传大文件
    location /uploads/ {                     # (1) 静态文件直出
        alias /opt/resume-platform/uploads/;
        expires 7d; try_files $uri =404;
    }
    location /api/ {                         # (2) 后端 API
        proxy_pass http://127.0.0.1:8081;    # 注意：无末尾 /，保留 /api 前缀
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    location / {                             # (3) 前端
        proxy_pass http://127.0.0.1:4000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
EOF
sudo rm -f /etc/nginx/sites-enabled/default     # 删默认站点，避免冲突
sudo nginx -t && sudo systemctl reload nginx     # 检查语法并重载
整个配置逐行解释：
  • listen 80：在 80 端口（http）接收请求。
  • server_name jianli.wylab.asia：只有 Host 是这个域名的请求才匹配本 server 块。只写域名不写 IP，这样裸 IP 访问会落到别处（同机其它项目），域名精确归本项目。
  • client_max_body_size 20m：允许请求体（上传文件）最大 20MB。默认只有 1MB，不设这个上传头像都会 413 报错。
  • location /uploads/ { alias ...; }：凡是 /uploads/xxx 的请求，Nginx 直接从磁盘目录读文件返回，不经过后端，性能极高。注意 alias 路径末尾也要有 /。
  • location /api/ { proxy_pass http://127.0.0.1:8081; }：核心。把 /api/... 转发给本机 8081（后端）。注意 proxy_pass 后面没有末尾的 /，所以 /api/login 会原样转成 8081/api/login，正好对上后端的 context-path:/api。
  • proxy_set_header X-Real-IP / X-Forwarded-For：把真实访客 IP 传给后端，否则后端看到的都是 127.0.0.1，限流/审计会失真。
  • location / { proxy_pass http://127.0.0.1:4000; }：兜底规则，其余所有请求（页面、JS、CSS）都交给前端 4000。
  • Upgrade/Connection "upgrade"：WebSocket 升级握手必需（防御性配置）。

验证：curl -H 'Host: jianli.wylab.asia' http://localhost/ 应返回前端 HTML；curl http://localhost/api/auth/login 应非 000（到后端链路通）。

5反向代理（Nginx 讲解）

什么是反向代理 · 为什么用它 · 配置逐行拆解 · 限流/SSL/坑

5.1先讲清楚：正向代理 vs 反向代理

正向代理（VPN 那种）反向代理（Nginx 这种）
代理对象客户端（帮"我"访问外部）服务器（帮"服务器"收外部请求）
谁配置客户端/浏览器服务端运维
客户端知情？知道（自己设了代理）不知道（以为直接连的就是网站）
本项目作用—统一入口、TLS 终止、动静分离、限流、隐藏后端端口

一句话：反向代理是"架在真实服务器前面的门面"。用户只跟 Nginx 打交道（一个域名、80/443 端口），Nginx 再把请求按规则分发给后端 8081、前端 4000 或直接返回静态文件。

5.2为什么这个项目必须用 Nginx

  • 同源，免跨域：前端(:4000)、后端(:8081)都藏在同一个域名后，浏览器看不出是两个服务。
  • TLS 终止：HTTPS 加解密只在 Nginx 做，后端/前端继续用明文 http 通信，省 CPU。
  • 静态资源高性能：/uploads/ 由 Nginx 直接读磁盘返回，比后端吐文件快几个数量级。
  • 限流/防刷：用 limit_req 给 /api 限流，保护后端。
  • 端口收敛：公网只开 80/443，MySQL/Redis 只监听 127.0.0.1。

5.3本项目 Nginx 配置逐行拆解

server {
    listen 80;
    server_name jianli.wylab.asia;
    client_max_body_size 20m;
    location /uploads/ {
        alias /opt/resume-platform/uploads/;
        expires 7d; try_files $uri =404;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    location / {
        proxy_pass http://127.0.0.1:4000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
最容易踩的坑：proxy_pass 加不加末尾 / 语义不同！
  • proxy_pass http://127.0.0.1:8081;（无 /）→ /api/xxx 原样转发为 8081/api/xxx，匹配后端 context-path ✅
  • proxy_pass http://127.0.0.1:8081/;（有 /）→ 把 /api 前缀截掉转成 8081/xxx，后端 404 ❌

5.3.1location 匹配优先级

规则：精确 = > 前缀最长匹配（可 ^~ 打断正则）> 正则 ~ > 普通前缀。本项目 /uploads/、/api/ 是前缀匹配，/ 是兜底普通前缀。

5.3.2为什么要传这些 header？

Header作用
Host后端有时按 Host 区分多域名
X-Real-IP / X-Forwarded-For把真实客户端 IP 透传，否则后端看到的都是 127.0.0.1
X-Forwarded-Proto告诉后端"用户用的是 https"
Upgrade/ConnectionWebSocket 升级握手必需

5.4限流：保护后端不被刷（可选增强）

limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;
server {
  location /api/ {
      limit_req zone=api_limit burst=20 nodelay;
      proxy_pass http://127.0.0.1:8081;
  }
}

burst=20 nodelay：允许瞬间 20 个突发请求立即处理，更多则排队/拒绝。

5.5HTTPS：certbot 自动改写

用 certbot --nginx 签发并自动改配置，最终得到 443 server + 80 跳 443。证书 90 天有效，自动续期。

6.1架构与总体

Q1用一句话介绍你的项目

"这是一个在线简历制作与分享平台。用户可以注册登录、用模板创建简历，在富交互编辑器里分模块填写、拖拽排序、自定义主题与分栏布局，调用大模型一键润色，导出 PDF，并生成只读分享链接；还有模板广场、管理后台、文件/文本/图片导入。技术栈是 Spring Boot + MyBatis-Plus + MySQL + Redis 做后端，Next.js + React + AntD + Zustand 做前端，Nginx 反代，部署在云服务器上。"
加分：开场先把"是什么 + 技术栈 + 部署形态"三句话说完。

Q2为什么采用前后端分离？

① 前后端可以并行开发；② 前端可独立部署、后端专注业务与数据；③ 一份后端 API 可被 Web、小程序/App 复用；④ 职责清晰。代价是多了一层接口联调与可能的跨域处理（本项目用同源反代规避了）。

Q3为什么选 Next.js 而不是纯 React(Vite) 或 Vue？

Next.js 的 App Router 支持 Server Component、内置路由与构建优化，next start 本身就是一个生产级 Node 服务，省去单独配 Express。Vue 生态也 OK，只是个人更熟 React。

Q4前后端怎么通信？跨域怎么解决的？

前端用 axios，baseURL:"/api" 是相对路径；Nginx 把 /api 反代到后端 8081。因为前端页面和 API 在同一个域名下，浏览器认为是同源，生产环境天然没有跨域问题。
若被追问"开发时怎么办"：开发用 Next 的 rewrites 或前端 devServer 代理把 /api 指到后端，同样同源。

6.2鉴权与安全

Q5为什么用 JWT？为什么是"双 token"？

JWT 无状态：后端不需存 session，靠签名校验，易水平扩展。但无法即时吊销，于是拆成 access（2h）+ refresh（7d）：access 短命被盗损失小，refresh 长命只用来换新。refresh token 落库，可主动吊销。
加分：说明 refresh token 落库，支持"踢下线"。

Q6token 存在哪？localStorage 安全吗？

本项目存在 localStorage（简单、跨标签页共享）。风险是 XSS 可被 JS 读取。更安全的做法是 HttpOnly Cookie（抗 XSS，但需防 CSRF）。取舍：localStorage 适合工具类应用；高安全应改 Cookie。

Q7access token 被盗了怎么办？

① access 只有 2h 过期；② refresh 在服务端有记录，可吊销 refresh；③ 关键操作加二次校验；④ 未来引入设备指纹/IP 异常检测。核心是缩短暴露窗口 + 可吊销。

Q8前端 401 自动刷新 token，多个请求同时 401 怎么处理？

用"单飞"机制：第一个 401 触发刷新并置 refreshing=true，其余 401 进 pending 队列等待；刷新成功后统一用新 token 重放。避免 N 个请求同时刷新把 refresh token 用废。
加分：这叫"请求合并/防并发刷新"，是 axios 拦截器经典写法。

Q9API Key / JWT Secret 怎么保管？

AI 的 API Key 只放在后端（环境变量），绝不下发前端；JWT Secret 也是服务端环境变量，缺失则应用拒绝启动。所有密钥不进代码仓库。

6.3数据库与后端实现

Q10为什么多张子表而不是一个 JSON 大字段？

简历是"一个主体 + 多个模块"，每个模块是子表一行，resume_id 关联，sort 控制顺序。好处：模块可自由增删、按模块独立更新、可做统计检索；代价是保存要聚合多表——用一个事务 upsert 保证一致性。

Q11一次保存多个模块，怎么保证一致性？

前端把整份 ResumeContent 一次性 PUT 给后端，后端在 @Transactional 里 upsert basic、批量 upsert 各模块、删前端已移除的行，最后更新主表 styleConfig。任一步失败整体回滚。

Q12逻辑删除 vs 物理删除？

全部业务表用 is_deleted 软删除，MyBatis-Plus 全局自动处理。好处：可恢复、可审计；代价是数据累积、查询略重（可定时归档）。

Q13MyBatis-Plus 是什么？

MyBatis 的增强：单表 CRUD 零 SQL、内置分页、条件构造器 QueryWrapper、逻辑删除/自动填充。本项目用它快速实现各子表增删改查。

Q14文件上传怎么做？大文件/OOM 怎么办？

后端接收 multipart 落盘到 /opt/resume-platform/uploads，返回 /uploads/xxx；Nginx 用 location /uploads/ 直出。限制：Spring 配 max-file-size:20MB、Nginx 配 client_max_body_size:20m。OOM 方面：限制单文件、用流而非全量读内存，服务器配 swap 兜底。

Q15AI 润色怎么实现的？怎么保证不编造事实？

后端调用通义千问 qwen-plus（OpenAI 兼容接口），支持全文和逐段。prompt 约束"只优化表达、不虚构数据、尽量量化"。返回后只替换被润色字段，不覆盖用户其它内容。
加分：把 AI 放后端是为了密钥安全 + 限流 + 审计。

Q16分享链接安全吗？

分享是只读公开（无需登录）。防护：① 分享码随机串无法枚举；② 后端可加访问频率限制；③ 用户可随时取消分享使链接失效。

Q17数据库索引怎么设计？

按用户列简历 → user_resume(user_id)；按分享码查 → resume_share(share_code) 唯一索引；各子表 resume_id 索引；登录查账号 → username/phone 索引。原则："高频查询列建索引、外键列建索引、避免过多索引拖慢写入"。

Q18权限模型怎么设计？

用户表带 is_admin 和四个能力位（can_export_pdf / can_ai_optimize / can_share / resume_limit）。后端接口按权限校验，前端据能力位禁用按钮。这是 SaaS 常见的"功能开关"模式。

6.4前端实现

Q19为什么选 Zustand 而不是 Redux？

Zustand API 极简（create 一个 store，组件直接订阅），没有 Provider 嵌套、没有 action/reducer 样板。本项目状态不复杂，Zustand 恰到好处。Redux 在超大型项目里更有优势。

Q20编辑器实时预览和自动保存怎么做的？

编辑区与预览区共享同一个 Zustand 草稿；任何字段变更置 dirty=true；监听 dirty 后 1.2s 防抖自动 PUT /api/resume/{id}/save。类似飞书/Notion 的自动保存。

Q21模块拖拽排序怎么实现？

用 HTML5 拖拽 API：每个模块块 draggable，onDragStart 记录 key，onDragOver 时交换 moduleOrder 数组；分栏布局把模块拖进左/右栏容器。状态变化实时驱动预览重排。

Q22PDF 导出为什么放前端？

用 html2pdf.js 把渲染好的 DOM 直接截图合成 PDF，所见即所得，样式与预览 100% 一致。代价是依赖浏览器环境、超大简历可能偏慢——但简历体量小，完全够用。
加分：能对比"后端排版更可控、可服务端批量，但样式难与前端完全一致"的取舍。

Q23简历分页线怎么算的？

预览容器宽度已知，按 A4 长宽比（≈1.414）算出每页高度；用 ResizeObserver 监听尺寸，遍历每个 .rp-block 测量 offsetTop+offsetHeight，超页则整块下移并在顶部插"第 N 页"分隔线。仅编辑态显示，导出 PDF 时隐藏。

Q24生产构建为什么要做代码混淆？

对仅客户端 bundle 做 webpack-obfuscator（变量名 hex 化、字符串 base64）。但要诚实：前端代码无法 100% 加密。核心密钥（AI Key、JWT Secret）都在后端，前端混淆只是防"白嫖样式/逻辑"。

Q25移动端怎么适配的？

用 window.innerWidth 判断断点：≥1100px 左侧模块导航 + 右侧预览；中屏抽屉化；<720px 移动布局（顶部菜单 + 预览抽屉）。预览宽度可拖拽。

6.5部署与 DevOps

Q26你是怎么部署的？systemd 是什么？

三个常驻服务都用 systemd 管理并开机自启：resume-platform(后端 jar)、resume-frontend(next start)、以及系统 MySQL/Redis/Nginx。systemd 是 Linux 的初始化与服务管理器，负责拉起、守护（崩溃自动重启）、日志、开机启动。

Q27为什么要加 swap？OOM 怎么排查？

旧服务器 1.6GB 无 swap，next build 直接 OOM 卡死。加 2GB swap 兜底。排查：dmesg | grep -i oom、free -h、journalctl，限制 JVM 堆（-Xmx512m）。
加分：OOM Killer 会挑进程杀，可能误杀关键服务，所以要从资源规划上避免。

Q28为什么数据库/Redis 只监听 127.0.0.1？

安全基线：只暴露必要端口。公网只开 80/443，MySQL/Redis 绑定本机回环，即使密码泄露外部也无法直连。

Q29proxy_pass 末尾加不加 / 有什么区别？

不加（本项目）：/api/xxx 转成 8081/api/xxx，匹配 ✅。加 /：截掉 /api 转成 8081/xxx，404 ❌。

Q30HTTPS 怎么做的？

用 Let's Encrypt 免费证书，certbot --nginx 一键签发并自动改写配置：加 443、80 跳 443、装定时续期。

6.6刁钻题与扩展性

Q31如果访问量涨 10 倍，怎么扩展？

① 后端无状态（JWT）可多实例 + 负载均衡（Nginx upstream）；② 数据库读写分离/主从，热数据进 Redis；③ 静态资源/上传文件上对象存储 + CDN；④ 前端静态化走 CDN；⑤ 加监控告警。

Q32如果 AI 接口很慢/挂了，怎么不影响主流程？

AI 是增强非核心：① 前端 AI 按钮独立、可失败降级；② 后端调 AI 设超时与熔断；③ 即使 AI 不可用，创建/编辑/导出/分享照常。

Q33怎么做备份和回滚？

备份：① 定时 mysqldump；② 上传目录打包；③ 代码进 Git。回滚：① Git tag；② jar 保留上一版；③ 数据库用备份回滚。本项目迁移时先完整导出再导入，正是"可回档"实践。

Q34灰度发布 / 蓝绿怎么做？

小项目用"反向代理层切流量"：新版本起在另一端口，Nginx 先把少量流量切过去验证，再全量。核心：新版本先小流量验证，出问题秒级切回。

Q35如果交给你重做，你会改进什么？

① token 改 HttpOnly Cookie；② 引入 CI/CD；③ 上传文件迁对象存储+CDN；④ 加监控与日志集中；⑤ 简历版本历史/协作；⑥ 加单元测试。

Q36最大的难点与收获？

难点：富交互编辑器的实时预览 + 分页线计算，以及小内存 OOM 治理。收获：完整走通"需求→前后端→AI→部署→反代→HTTPS"全栈闭环。
