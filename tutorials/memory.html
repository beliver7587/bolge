四层记忆：从小白到资深

AI 的上下文窗口有限，不能把所有历史一股脑塞进去。四层记忆按“时效与用途”分层管理：工作/情景/语义/程序记忆，分别用不同技术存储与检索。它是 Agent 长期“记得你”的底座（Memora 即如此）。本教程讲透分层原理与各层工程实现、隐私与留存。

1. 它解决什么问题

上下文窗口是“金贵资源”：塞太多 → 超窗报错、烧钱、注意力稀释。四层记忆让“该短期的不留痕、该长期的精准召回”。

一句话：像人一样分层——眼前的事（工作）、最近聊的（情景）、长期知道的事实（语义）、天生会的技能（程序）。

2. 四层模型

层存什么时效技术
工作记忆当前对话的 messages本轮内存
情景记忆历史对话记录中短期DB + 摘要
语义记忆提炼的长期事实（偏好/资料）长期向量库 Embedding
程序记忆固定指令/技能/工具永久系统提示 + 配置

3. 工作记忆

即当前发给模型的 messages。管理策略：

  • 滑动窗口：只保留最近 N 轮。
  • 摘要压缩：超长时把早期对话摘要成一段，省 token。
  • 不变量前置：system 指令始终在最前，不被截断。
if (messages.length > 20) messages = [systemMsg, ...(await summarize(messages.slice(1)))];

4. 情景记忆

每轮对话落库，需要时用（时间/关键词/向量）取回最近若干轮做“续上上下文”：

await db.insert('turn', { user: q, ai: a, ts: Date.now() });
// 召回：取最近 10 轮 + 也许按语义相似的历史片段
const recent = await db.query('SELECT * FROM turn ORDER BY ts DESC LIMIT 10');
资深：情景记忆不仅是“全量回放”，可按相关性检索关键历史，避免无脑塞满。

5. 语义记忆

把“用户偏好、关键事实”从对话中抽取成句子，生成向量入库；对话时检索相关事实拼进提示，让 AI 长期“记得你”：

const facts = await extractFacts(history);          // 抽取“用户喜欢简洁回答”等
for (const f of facts) vecDB.add(embed(f), f);
// 对话时召回相关长期事实
const rel = vecDB.search(embed(question), 5);
  • 抽取质量：用更强的模型/提示抽取；冲突事实要做合并或时间戳取新。
  • 去重/更新：同一事实别重复存储；用户改了偏好要更新而非叠加。

6. 程序记忆

固定的人设、可用工具列表（Function Calling）、业务规则、技能模板——放在 system 提示或配置里，每次都带，不随对话变化，类似“天生会的本能”。

版本化：程序记忆变更要灰度，避免一次改坏所有对话行为。

7. 隐私与留存

  • 留存期：情景/语义记忆设 TTL 与删除能力，满足“被遗忘权”。
  • 敏感过滤：写入前脱敏（手机号/身份证），避免长期记忆存隐私。
  • 注入防护：记忆里可能混入恶意指令，召回时按 提示注入防护 处理。

8. 常见坑

坑 1：不分层的把所有历史塞进上下文 → 超窗又烧钱；按层取舍。
坑 2：语义记忆抽取质量差 → 召回无关/错事实；用强抽取+校验。
坑 3：情景记忆不清理 → 隐私/过期信息长期留存；设留存期。
坑 4：忽略注入 → 记忆里藏毒劫持后续对话。
坑 5：事实冲突不处理 → AI 一会儿这样一会儿那样。

9. 成长路线

阶段能力标志
小白能分层概念、做工作记忆截断
初级会情景落库、语义抽取入库
中级事实冲突处理、程序记忆版本化
资深留存/隐私治理、检索质量负责
练习：① 给对话加滑动窗口+摘要 ② 落库历史对话并按时间召回 ③ 抽用户偏好入向量库并召回 ④ 处理两条冲突事实（取新）⑤ 给记忆加 TTL 与脱敏 ⑥ 在召回记忆上做注入防护。
你已进阶：理解“上下文窗口不是记忆”，能用四层结构让 AI 短期不丢、长期不忘、技能稳定——这是资深 AI 后端做有记忆系统的核心能力。
