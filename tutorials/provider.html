供应商抽象

把“用哪家风模型”做成配置 —— 换供应商只改 .env，业务代码零改动。

1. 这是什么

我们一般不自己训练模型，而是调用别人家的大模型 API（智谱、OpenAI、SiliconFlow…），按量付费。调用要带 API Key（像门票）。供应商抽象就是把“到底用哪家模型”做成可配置项，业务代码通过一个统一接口调用，换家供应商只改配置、不碰代码。

2. 为什么抽象

价值：各家 API 格式不一、价格与稳定性波动。抽象后，今天用智谱、明天换 SiliconFlow 的 Qwen，只改 .env 几行，检索与编排层完全不动——避免被单一供应商绑定。

3. 配置示例

# .env —— 设计写智谱，线上实际跑 Qwen
AI_PROVIDER=zhipu
ZHIPU_BASE_URL=https://api.siliconflow.cn/v1
ZHIPU_MODEL=Qwen/Qwen2.5-7B-Instruct
ZHIPU_EMBED_MODEL=BAAI/bge-m3
EMBED_DIM=1024

4. 代码形态

// 统一入口，内部按 AI_PROVIDER 选择具体实现
const llm = createLLM(process.env.AI_PROVIDER);
const ans = await llm.chat(messages);

5. 常见坑

坑 1：把 Key 写死在代码里提交到 Git——务必走环境变量（Memora 的红线）。
坑 2：各家模型能力/价格不同，切换后不回归测试就上生产。
坑 3：只抽象对话不抽象嵌入，换家还得改向量代码——两层都要抽。
