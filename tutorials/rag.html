RAG

检索增强生成（Retrieval-Augmented Generation）—— 让大模型先查资料再回答，避免胡说。Memora 的核心能力。学完你能做一个“基于自己文档的问答”。

1. 这是什么

RAG = 先检索相关资料，再把资料喂给大模型生成答案。它解决大模型“不知道你私有数据、且会编造”的问题。

一句话：不让模型凭记忆编，而是先翻出真文档，再让模型照着回答。
适合：企业知识库、客服、个人文档问答、法律/医疗辅助。

2. 整体流程

用户提问 │ ▼ [向量化问题] → [向量库检索 Top-K 相关段落] ← 离线的“建库”：文档切块→向量→入库 │ ▼ [把 问题+检索段落 拼成 Prompt] │ ▼ [大模型生成答案（只依据给定资料）]

3. 切块与入库

见 向量检索：把文档切成 300~800 字的小块，每块生成 embedding 存入向量库。

// 伪代码
chunks = split(doc, size=500, overlap=80)
for c in chunks:
    vec = embed(c)
    vectorDB.add(vec, c)

4. 检索

qvec = embed(question)
hits = vectorDB.search(qvec, topK=4)    // 返回最相关 4 段
提升：纯向量检索不够，常叠加 BM25 关键词，用 RRF 融合排序。

5. 组装 Prompt

const context = hits.map(h => h.text).join('\n---\n');
const prompt = `你是基于资料的助手，只根据下面资料回答，资料没有就如实说不知道。
资料：
${context}
问题：${question}`;

6. 生成答案

const ans = await llm.chat([{ role:'user', content: prompt }]);
return ans;

7. 常用坑

坑 1：切块太大/太小导致检索不准；按语义边界（段落/标题）切更好。
坑 2：只喂检索结果却不说“依据资料”，模型仍会编造；务必在 prompt 里约束。
坑 3：检索召回无关内容，答案跑偏；加重排（rerank）或混合检索。
坑 4：上下文超长超出模型窗口；控制 Top-K 与块大小。
坑 5：忽视 提示注入防护，资料里藏的指令可能劫持模型。

8. 下一步

  1. 用 RAG 做一个“产品手册问答”。
  2. 学 向量检索、BM25、RRF。
  3. 学 Agent 让模型能调用工具。
  4. 看 Memora，RAG + 记忆完整实现。
毕业：能搭一条“检索→拼 Prompt→生成”链路——让大模型基于你的资料回答，你已掌握。
