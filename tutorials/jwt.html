JWT / bcrypt：从小白到认证安全

JWT 是无状态身份凭证，bcrypt 是密码哈希算法。两者是后端登录鉴权的基石（简历工坊、Memora 都用到）。本教程讲清 JWT 结构、登录流程与防护要点。

1. 它是什么

JWT（JSON Web Token）把用户信息签名成一段令牌，服务端不存会话即可验证“你是谁”。bcrypt 把密码哈希存储，即使库泄露也难反推明文。

一句话：JWT = 无状态令牌（证明身份）；bcrypt = 防拖库（保护密码）。

2. JWT 结构

三段 base64：header.payload.signature。payload 放用户 id、过期时间等（别放密码等敏感字段）。

// 伪结构：base64(header).base64(payload).HMAC(payload, 密钥)
注意：JWT 只签名不加密，payload 可被解码读取——敏感信息别塞进去，或改用 JWE 加密。

3. 认证流程

// 登录：校验 bcrypt 密码 → 发 JWT
const ok = await bcrypt.compare(inputPwd, user.pwdHash);
const token = jwt.sign({ uid: user.id }, SECRET, { expiresIn: '7d' });
// 之后请求：Authorization: Bearer <token>

中间件校验签名与过期，取出 uid 注入请求上下文。

4. bcrypt 哈希

const hash = await bcrypt.hash(pwd, 12);   // 注册时存 hash
const ok = await bcrypt.compare(pwd, hash); // 登录时比对
价值：bcrypt 自带盐与慢哈希，抗暴力破解；明文密码绝不进库。

5. 安全要点

  • 密钥：JWT 签名密钥用强随机值，绝不硬编码/进库（用环境变量）。
  • 过期：access token 短命（分钟级），配 refresh token 续期。
  • 存储：前端存 httpOnly cookie 防 XSS 窃 token，比 localStorage 安全。

6. 与 Session

JWTSession
状态无状态（服务端不存）有状态（存服务端）
扩展跨服务易（验签名即可）需共享存储
注销需黑名单或短过期直接删

7. 常见坑

坑 1 密钥泄露：等于任何人能伪造任意身份；用环境变量 + 定期轮换。
坑 2 token 不过期：长期有效的 token 丢了就永久沦陷，务必过期 + 续期。
坑 3 密码明文：没用 bcrypt，库一泄露密码全裸，立即整改。

完整流程：JWT 鉴权

1. 签发 Token
const jwt = require('jsonwebtoken');
const token = jwt.sign({userId:1,role:'user'}, SECRET, {expiresIn:'2h'});
2. 客户端携带
Authorization: Bearer <token>
3. 服务端校验
const payload = jwt.verify(token, SECRET);
if (!payload) return 401;
要点：SECRET 要复杂且保密；敏感信息不要放 payload；刷新 Token 用 refreshToken。
