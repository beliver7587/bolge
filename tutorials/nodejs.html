Node.js：从小白到服务端运行时

Node.js 让 JavaScript 跑在服务端，基于事件循环处理高并发 I/O。Memora 与游戏中转服务都构建在它之上。本教程讲清它“为什么适合 I/O 密集”、事件循环怎么转、以及异步编程的正确姿势。

1. 它是什么

Node.js 是 Chrome V8 引擎 + 事件循环 + 标准库，让 JS 脱离浏览器跑在服务器。单线程、非阻塞 I/O 是它最核心的特征。

一句话：Node = V8 + 事件循环。擅长“大量并发连接 + I/O 等待”的场景。
适合：API 服务、实时通信（Socket.IO）、CLI、BFF。不适合：CPU 密集型计算（会阻塞单线程）。

2. 工程化起步

1

安装与版本

装 LTS（如 20.x）。用 nvm 管理多版本。

2

项目初始化

npm init -y
node index.js   // 跑脚本

现代推荐 TypeScript + 或 直接用 TS 跑。

3. 模块系统

// CommonJS（老）
const fs = require('fs');
module.exports = x;
// ESM（新，推荐）
import fs from 'node:fs';
export default x;
坑："type":"module" 决定默认是 ESM；混用两种语法会报错，统一一种。

4. 事件循环

单线程上靠“事件循环”调度：同步代码先跑完，再把回调（定时器、I/O、微任务）按阶段排队执行。

console.log('1');
setTimeout(() => console.log('2'), 0);
Promise.resolve().then(() => console.log('3'));
console.log('4');   // 输出 1 4 3 2
资深：微任务（Promise）先于宏任务（setTimeout）执行，理解这点能解释一大类“顺序不对”的 bug。

5. 异步与回调

早期用回调，易“回调地狱”。现在一律 Promise/async：

fs.readFile('a.txt', (err, data) => { if(err) ... });  // 旧

6. Promise / async

async function read() {
  const data = await fs.promises.readFile('a.txt', 'utf8');
  return data;
}
  • await 暂停函数直到 Promise 完成，代码像同步一样读。
  • 错误处理用 try/catch 或 .catch。

7. 流与缓冲

大文件用 Stream 分块处理，不占内存：

fs.createReadStream('big.mp4').pipe(res);  // 边读边发
价值：流式处理是 Node 扛大文件/代理的核心能力。

8. 内置模块

  • fs 文件、path 路径、http/https 网络。
  • child_process 调外部命令；crypto 加密。

9. 与 Express

裸 Node 写 Web 麻烦，用 Express 这类框架做路由/中间件。Node 也支撑 React 的 SSR 与构建工具。

10. 进程与部署

  • 用 PM2 守护、集群多进程吃满 CPU。
  • Docker 镜像 + Nginx 反代。
  • CPU 密集任务交给 Worker Threads 或拆服务。

11. 常见坑

坑 1 阻塞事件循环：在请求里跑重计算/同步大循环，全站卡住；交给 worker 或异步分片。
坑 2 未捕获异常：unhandledRejection 不处理会崩进程；监听并优雅退出。
坑 3 回调/await 混用：统一 async，避免顺序混乱。

12. 与 Bun

Bun 是更快的替代运行时，兼容多数 Node API 但生态仍在追赶。新项目可试，生产要评估兼容性。
