MySQL：从小白到关系型数据库

MySQL 是最流行的开源关系型数据库，用 SQL 管理结构化数据。简历工坊、游戏后端都靠它存业务数据。本教程讲清表设计、索引、事务与优化——这是后端必会的“数据底座”。

1. 它是什么

关系型数据库把数据存成“表（行+列）”，用 SQL 增删改查，靠约束保证一致。MySQL 稳定、生态全，是 Web 后端默认选择。

一句话：MySQL = 关系型 + SQL + ACID。结构清晰、强一致。

2. 起步

mysql -u root -p
CREATE DATABASE app CHARSET utf8mb4;
USE app;
CREATE TABLE user (id BIGINT PRIMARY KEY AUTO_INCREMENT, name VARCHAR(64));

生产用 Docker 起实例，连接池交给框架（见 Spring Boot）。

3. 数据模型

  • 库（database）→ 表（table）→ 行（row）/ 列（column）。
  • 类型：INT/BIGINT、VARCHAR、DECIMAL、DATETIME、JSON（5.7+）。
  • 约束：主键、外键、唯一、非空。

4. SQL 基础

SELECT id, name FROM user WHERE status=1 ORDER BY id DESC LIMIT 10;
INSERT INTO user(name) VALUES ('王越');
UPDATE user SET name='新' WHERE id=1;
DELETE FROM user WHERE id=1;

5. 索引

索引（默认 B+ 树）像书的目录，加速查询但拖慢写入。

CREATE INDEX idx_status ON user(status);
-- 联合索引 (a,b) 遵循最左前缀
坑：索引失效常见原因——对列做函数运算、隐式类型转换、LIKE '%x' 前模糊、不满足最左前缀。

6. 事务

START TRANSACTION;
UPDATE a ...; UPDATE b ...;
COMMIT;   -- 或 ROLLBACK;
  • ACID：原子、一致、隔离、持久。
  • 隔离级别：读未提交/读已提交/可重复读（MySQL 默认）/串行化。

7. 关联查询

SELECT u.name, o.amount
FROM `user` u JOIN `order` o ON o.user_id = u.id
WHERE u.id = 1;
坑：大表 JOIN 无索引会全表扫描；关注执行计划 EXPLAIN。

8. 范式与反范式

  • 范式：减少冗余、避免更新异常（1NF~3NF）。
  • 反范式：为性能加冗余字段/统计列，读多写少用。
资深：不是越范式越好，按读写比在规范与性能间权衡。

9. 与 Redis

MySQL 存“真值与关系”，Redis 存“热点缓存”。读多写少的数据放 Redis 扛量，MySQL 兜底。

10. 常见坑

坑 1 没主键/自增：无序主键导致页分裂；用自增或雪花 ID。
坑 2 慢查询：上线前用 EXPLAIN 排查，别等线上报警。
坑 3 字符集：用 utf8mb4 才能存 emoji，老 utf8 只 3 字节。

11. 资源与路线

  1. 官方 MySQL 文档。
  2. 配合 Spring Boot、MyBatis-Plus。

完整流程：MySQL 建库与查询

1. 建库建表
CREATE DATABASE shop DEFAULT CHARSET utf8mb4;
USE shop;
CREATE TABLE user(id BIGINT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(64), age INT, INDEX idx_age(age));
2. 增删改查
INSERT INTO user(name,age) VALUES('Tom',20);
SELECT * FROM user WHERE age > 18 ORDER BY id DESC LIMIT 10;
UPDATE user SET age=21 WHERE id=1;
3. 索引与事务
CREATE INDEX idx_name ON user(name);
START TRANSACTION; UPDATE account SET balance=balance-100 WHERE id=1; COMMIT;
要点：字符集用 utf8mb4；慢查询用 EXPLAIN 分析；事务保证一致性。
