Zustand：从小白到资深前端

Zustand 是极简的 React 状态管理库（也可用于 Vue 等）。它用“一个 hook 拿到 store”的极简 API，解决了 Context 的重渲染痛点与 Redux 的样板冗余。本教程讲透精准订阅、中间件、状态结构设计——这是资深前端选状态方案的依据。

1. 它解决什么问题

全局状态若用 Context：任何一个值变了，所有消费者都重渲染（难以精细控制）。若用 Redux：action/reducer/dispatch 样板多。Zustand 取中间：一个 create 建 store，组件用选择器只订阅自己关心的字段，粒度可控、几乎零样板。

一句话：Zustand = 全局可变的“迷你仓库”，但组件能按字段精准订阅，避免无谓重渲染，且可在组件外（如事件回调、定时器）直接读写。

2. 工程化起步

pnpm add zustand

无配置、无 Provider 包裹。直接用。

3. 核心 API

'use client';
import { create } from 'zustand';

interface CounterState {
  count: number;
  inc: () => void;
}
const useCounter = create<CounterState>((set, get) => ({
  count: 0,
  inc: () => set({ count: get().count + 1 }),  // set 合并，get 读当前
}));
  • set(partial | fn)：合并更新；用函数式 set(s => ({...})) 拿最新值。
  • get()：在 action 里读其他状态，避免闭包旧值。

4. 选择器与性能

关键优势：组件只订阅它选的字段，该字段不变就不重渲染。

const count = useCounter(s => s.count);     // 只订阅 count
const inc = useCounter(s => s.inc);         // 函数引用稳定，不触发渲染
坑：不要在选择器里返回新对象/新数组（如 s => ({a,b})），每次都新引用 → 无限重渲染。多字段分别订阅，或用 useShallow 浅比较。

5. 与 React 集成

  • 组件内：const x = useStore(s => s.x)。
  • 组件外读写：useCounter.getState().inc() / .setState()，可在定时器、事件监听里直接用，不需 hook 上下文。
  • 持久化：persist 中间件自动存 localStorage（见第 6 节）。

6. 中间件生态

import { persist, devtools, immer } from 'zustand/middleware';
const useStore = create(persist(
  devtools((set) => ({ ... }), { name: 'app' }),
  { name: 'app-storage' }          // 自动持久化到 localStorage
));
  • persist：状态自动存/取（适合主题、登录态 token 等）。
  • immer：用“可变写法”改嵌套状态（内部转不可变）。
  • devtools：接入 Redux DevTools 看状态时间线。

7. 与 Redux 对比

ZustandRedux Toolkit
样板极少中等（slice/action）
精准订阅原生支持需 selector + 注意
适用中小型/灵活项目大团队、强规范、时间旅行调试
选型：大多数应用 Zustand 足够且更轻；需要严格流程、可回溯、多人强约束时上 Redux Toolkit。

8. 状态设计

  • 按域分 store：useUser、useCart 分开，而非一个巨型 store。
  • 服务端数据别进 store：来自接口的数据交给 TanStack Query（同 React 思路），store 只放“客户端 UI 状态”（主题、抽屉开关、草稿）。
  • 不要囤积：能用局部 useState 解决的别提全局。

9. 常见坑

坑 1：直接改 state 对象不调 set——Zustand 靠引用变化通知，就地改不生效（用 immer 或先拷贝）。
坑 2：选择器返回新对象/数组导致无限渲染——分别订阅或用 useShallow。
坑 3：滥用全局，所有状态塞一个 store，失去分域与精准更新优势。
坑 4：持久化存了不该存的数据（如大列表），localStorage 爆了。

10. 调试

  • devtools 中间件接 Redux DevTools，看每次状态变更与时间线。
  • 控制台直接 useStore.getState() 检视当前状态。
