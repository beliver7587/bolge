Nginx：从小白到资深

Nginx 是高性能 Web 服务器 / 反向代理 / 负载均衡器，作为“网站前台”统一收口外部流量、转发后端、托管静态、做 TLS 终止。本教程讲透事件驱动架构、配置体系、反向代理路径陷阱、负载均衡、缓存压缩、长连接、性能调优与限流安全——这是把服务稳稳上线、扛住流量的核心能力。

1. 它解决什么问题

直接把后端暴露公网问题多：端口乱、无 TLS、单点、无静态能力。Nginx 作为统一入口：对外只开 80/443，对内把请求按规则转发给多个后端，同时托管静态资源、做压缩与限流。

一句话：用户只和 Nginx 打交道，Nginx 决定“给哪个后端 / 返回哪个静态文件”。

2. 架构原理

  • 事件驱动 + 多 worker：单 worker 用 epoll/kqueue 异步处理上万并发连接，远胜传统每连接一线程。
  • master/worker：master 管配置与子进程，worker 干活；reload 平滑不中断。
  • 阶段化处理：接收 → 重写 → 访问控制 → 内容处理 → 响应过滤，可挂模块。

3. 配置体系

主配置 /etc/nginx/nginx.conf 用 include 引入站点；Ubuntu 习惯放 sites-available/ 软链到 sites-enabled/。

# nginx.conf 关键
worker_processes auto;          # 通常 = CPU 核数
events { worker_connections 10240; }   # 单 worker 最大连接
http {
  include /etc/nginx/sites-enabled/*;
  gzip on;                      # 全局开压缩
}

4. 反向代理精髓

最易踩坑的是 proxy_pass 的路径拼接：

location /api/ {
  proxy_pass http://127.0.0.1:3000/;   # 末尾有 / ，把 /api/ 去掉再转发
  # 请求 /api/user → 转发到 http://127.0.0.1:3000/user
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_read_timeout 60s;       # 长任务（如 AI 流式）要调大
}
路径陷阱：proxy_pass 末尾有无 / 决定 URI 是否被替换；后端拿到的 path 不同，务必联调确认。

5. 负载均衡

upstream backend {
  least_conn;                   # 最少连接（默认 round-robin 轮询）
  server 127.0.0.1:3000 weight=3;   # 加权
  server 127.0.0.1:3001;
  server 127.0.0.1:3002 backup;     # 备胎，主全挂才用
}
location /api/ { proxy_pass http://backend; }
算法：round-robin（均匀）/least_conn（谁闲给谁）/ip_hash（同 IP 落同节点，有状态会话用）/hash（自定义键）。健康检查靠 max_fails/fail_timeout 自动摘流。

6. 静态与缓存

location /static/ {
  root /var/www;
  expires 30d;                  # 浏览器/CDN 缓存
  add_header Cache-Control "public, immutable";
  gzip_static on;               # 优先发 .gz 预压缩
}
location / { try_files $uri $uri/ /index.html; }   # SPA 兜底

7. WebSocket / SSE

# WebSocket 必须升级协议
location /ws/ {
  proxy_pass http://127.0.0.1:8080;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
}
# SSE 关闭缓冲，避免打字机延迟（Memora 已配）
location /stream { proxy_buffering off; proxy_pass http://127.0.0.1:3000; }

8. 性能调优

  • worker_connections 与系统 ulimit -n 配合，撑高并发。
  • 开启 keepalive（上游长连）减少 TCP 握手。
  • sendfile on; tcp_nopush on; 提升静态吞吐。
  • 合理设 client_max_body_size（上传限制）。

9. 限流与安全

limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;   # 每 IP 10 次/秒
location /api/ { limit_req zone=api burst=20 nodelay; }       # 令牌桶+突发
limit_conn_zone $binary_remote_addr zone=conn:10m;
limit_conn conn 50;                                           # 单 IP 并发连接
TLS：证书与加固见 HTTPS（HSTS、强套件）。

10. 可观测

  • access_log 自定义格式（含 $upstream_response_time 定位慢后端）。
  • stub_status 暴露连接/请求计数，接 Prometheus。
  • 改完必 nginx -t 再 reload。

11. 常见坑

坑 1：不 nginx -t 就 reload，配置错导致 502；先测再载。
坑 2：proxy_pass 路径错（有无斜杠）致后端 404。
坑 3：没带 Host/X-Real-IP，后端拿不到真实域名与客户端 IP。
坑 4：WebSocket/SSE 缺 Upgrade 或 buffering 未关，长连接异常。
坑 5：防火墙未放行 80/443，外部访问不了。
坑 6：超时太短，AI 流式/大文件上传被掐断。

12. 成长路线

阶段能力标志
小白能装 Nginx、配站点、反代
初级会负载均衡、静态缓存、WS/SSE
中级性能调优、限流、TLS 加固
资深可观测体系、灰度/AB、高可用架构
练习：① 反代一个 Node 服务并验证路径 ② 配 upstream 做负载均衡 ③ 给 /static 加 30 天缓存 ④ 配 WS Upgrade 与 SSE buffering off ⑤ 加 limit_req 限流 ⑥ 用 nginx -t+access_log 排查一次 502。
你已进阶：理解 Nginx 既当入口又当盾牌，能从架构层做转发、均衡、缓存、限流与可观测——这是资深后端做高可用上线的标配。
