TypeScript：从小白到类型体操

TypeScript 是 JavaScript 的静态类型超集：代码在运行前就被类型检查，把一大类 bug 挡在编译期。本教程从“为什么需要类型”讲到“泛型、条件类型、类型推断”，让你既能安心写业务，也能读懂框架里的复杂类型。

1. 它解决什么问题

JavaScript 是动态弱类型：undefined.x 运行时才炸，IDE 给不出提示，重构时“改一个字段名全站静默出错”。

一句话：TypeScript = JS + 类型系统。类型即文档、类型即测试——编辑器实时提示、重命名安全、调用传参错立刻标红。
资深视角：类型不是“限制自由”，而是把“开发者的意图”写进代码，让编译器替你盯住边界。大型项目没有类型，维护成本是指数级上升。

2. 工程化起步

1

安装与编译

npm i -D typescript
npx tsc --init        # 生成 tsconfig.json
npx tsc --noEmit      # 只检查不产出（CI 常用）
2

接构建工具

现代项目一般不手写 tsc 产出：Vite / Next.js / Webpack 在打包时调 tsc 做类型检查，运行时仍是 JS。TS 永远是“编译期的客人”。

3

最小 tsconfig

{
  "compilerOptions": {
    "strict": true,
    "target": "ES2020",
    "moduleResolution": "bundler",
    "noUncheckedIndexedAccess": true
  }
}

3. 类型注解基础

let age: number = 18;
const name: string = '王越';
let ok: boolean = true;
// 不写注解也能跑——TS 会“推断”
const nums: number[] = [1, 2, 3];   // 数组
const tuple: [string, number] = ['id', 1];  // 元组，顺序固定
坑：const x = [1, 'a'] 会被推断成 (string|number)[] 而非元组；要元组就显式标注。元组常用来当“固定结构的小对象”。

4. interface 与 type

interface User { id: number; name: string; email?: string }  // ? 可选
type Point = { x: number; y: number };
type ID = number | string;   // type 能写联合，interface 不能
  • interface：描述对象形状，可 extends 合并声明，适合“数据契约”。
  • type：能表达联合、交叉、元组、映射等，更灵活。
经验：描述对象/类用 interface；需要联合/工具类型中间结果用 type。团队统一即可，不必纠结。

5. 联合与字面量

type Role = 'admin' | 'user' | 'guest';
function greet(role: Role) { /* 只能传这三个值 */ }
type Status = 200 | 404 | 500;   // 字面量联合，常用于状态码
type Shape = { kind: 'circle'; r: number } | { kind: 'rect'; w: number };
可辨识联合：靠一个公共字面量字段（kind）收窄分支，是 TS 最安全的模式之一。

6. 泛型

泛型让函数/类型“适配多种类型”而不丢失信息。

function first<T>(arr: T[]): T | undefined { return arr[0]; }
const a = first([1, 2]);      // a: number
const b = first(['x']);       // b: string
// 约束
function len<T extends { length: number }>(x: T): number { return x.length; }
误区：泛型不是越多越好。<T, U, V> 嵌套三层的函数多半是设计信号：该拆了。

7. 函数与重载

function fmt(input: number): string;
function fmt(input: string): string;
function fmt(input: number | string): string {
  return typeof input === 'number' ? input.toFixed(2) : input.trim();
}

重载签名给“多种入参/出参形态”精确提示；实现签名必须兼容所有重载。函数类型用 (a: number) => void 书写。

8. 类与修饰器

class Animal {
  constructor(public name: string, private age: number) {}
  speak() { return `${this.name}叫`; }
}
interface Loggable { log(): void }
class Dog extends Animal implements Loggable {
  log() { console.log(this.name); }
}
  • public/private/protected 是编译期可见性，运行时无强制。
  • 修饰器（decorator）：实验特性，框架（如 NestJS、Spring 思路类似）常用它做注解。

9. 工具类型

工具类型作用
Partial<T>所有字段变可选（更新场景）
Pick<T, K>只取部分字段
Omit<T, K>排除部分字段
Record<K, V>构造键值映射类型
Readonly<T>全部只读
type UpdateUser = Partial<Omit<User, 'id'>>;  // 更新时除 id 外都能改

10. 类型守卫

function isString(x: unknown): x is string { return typeof x === 'string'; }
function handle(x: string | number) {
  if (isString(x)) return x.toUpperCase();  // 这里 x 被收窄成 string
  return x.toFixed(2);
}

typeof、in、自定义类型守卫 x is T 都能让 TS 在分支里“收窄”类型，避免无谓断言。

11. 声明文件

用没类型的 JS 库时写 .d.ts 补类型：

declare module 'legacy-lib' {
  export function doThing(opt: { a: number }): void;
}
  • @types/xxx：社区维护的类型包（如 @types/node）。
  • /// <reference />：老式三斜线指令，现代多靠 tsconfig 的 types。

12. 严格模式

"strict": true 一次开启：noImplicitAny、strictNullChecks、strictFunctionTypes 等。

最值得开的两个：strictNullChecks（null/undefined 不能再随便赋值，挡住一半线上崩溃）+ noUncheckedIndexedAccess（数组取下标可能 undefined，逼你判空）。

13. 与框架集成

  • React：组件 props、useState 泛型、事件类型都靠 TS。
  • Next.js：params/searchParams/表单都强类型。
  • Vue 3：<script setup lang="ts"> 给 ref/props 加类型。

14. 常见坑

坑 1 any 蔓延：为了“赶紧过编译”到处 any，类型系统形同虚设。用 unknown + 守卫替代。
坑 2 类型 ≠ 运行时：interface 在编译后完全消失，不能拿它做 instanceof。
坑 3 结构化类型：TS 按“形状”判兼容，不是按名字——多一个字段的对象也能赋值给少字段的类型（除非 exactOptionalPropertyTypes）。

15. 高级类型

type Awaited<T> = T extends Promise<infer U> ? U : T;  // infer 提取
type Mapped = { [K in keyof User]?: User[K] };          // 映射类型
type IsString<T> = T extends string ? true : false;     // 条件类型
价值：框架（如 Zustand、TanStack Query）的类型魔法都建立在这三件套上。读懂它们，你就能写自己的工具类型。

16. 类型体操入门

“类型体操”= 用类型系统做编译期计算。真实项目不必炫技，但理解基础能救命：

  • 递归条件类型：实现深只读 DeepReadonly。
  • 模板字面量类型：type Route = \`/user/${string}\` 约束路径。
节制：类型越复杂，编译越慢、他人越读不懂。能靠运行时验证的，别硬上类型体操。

17. 工具链

  • tsc --noEmit：CI 里做类型门禁。
  • ts-node / tsx：直接跑 TS 脚本。
  • 编辑器：VS Code 自带 TS 服务，实时报错与重构。

18. 资源与路线

  1. 官方手册 typescriptlang.org。
  2. 练：给现有 JS 项目逐步加 strict；写一个带泛型的缓存函数。
  3. 进阶：读懂 ReturnType、Parameters、Awaited 的实现。
资深标志：不是“会用类型注解”，而是能用类型给团队画出数据契约，把模糊的边界变成编译器能验证的红线。
